# 《开天辟地之大地的裂变》事件分类与触发机制

## 1. 事件分类

为了保证事件系统具有良好的扩展性与可维护性，游戏中的随机事件按照主要影响对象与作用范围划分为多个类别。

每种事件拥有不同的设计目标、触发条件与结算方式，但均遵循统一的事件触发与结算流程。

| 事件类型 | 主要作用 | 常见持续方式 |
| --- | --- | --- |
| 普通事件 | 玩家遭遇的日常随机事件，通常影响当前玩家。 | 视事件而定 |
| 命运事件 | 对玩家产生较大影响，可能改变其发展方向。 | 通常持续若干回合 |
| 遭遇事件 | 生成怪物、NPC、战斗或特殊交互。 | 通常即时 |
| 世界事件 | 对所有玩家、多个区域或整个地图产生共同影响。 | 通常持续若干回合 |
| 灾难事件 | 改变指定区域或地图环境，并产生负面影响。 | 通常持续若干回合 |
| 奇遇事件 | 提供隐藏奖励、特殊地点或稀有机会。 | 通常即时 |
| 祝福事件 | 为玩家、区域或世界提供正面持续效果。 | 通常持续 |
| 诅咒事件 | 为玩家、区域或世界施加负面持续效果。 | 通常持续 |
| 彩蛋事件 | 触发趣味内容或与原作相关的隐藏事件。 | 一般即时 |

事件类别仅用于组织事件内容，并不限制事件之间的联动。例如，一个世界事件可以为区域加入新的遭遇事件，命运事件也可以生成任务或改变地图状态。

每项事件应指定一个主要类型。当事件同时具有多种表现时，应根据其主要设计目的确定分类，其他内容作为联动效果记录，避免因重复分类造成管理混乱。

事件类型与事件池属于两个不同概念：

| 概念 | 作用 |
| --- | --- |
| 事件类型 | 描述事件主要影响什么，以及采用何种方式结算。 |
| 事件池 | 描述事件可以在什么区域、场景或触发来源下出现。 |

例如，“森林中的狼人伏击”可以属于遭遇事件，并被森林事件池与夜晚事件条件共同筛选。其类型决定事件内容，其事件池与条件决定出现环境。

## 2. 事件触发方式

事件并非只能在固定时间发生，而是在玩家行为或世界状态满足特定条件时触发。

### 2.1 地图探索触发

玩家进入带有事件标记的特殊单元格，或对未知地块执行探索时，可以触发对应事件。

例如：

* 神秘遗迹
* 废弃营地
* 古老祭坛
* 未知森林
* 地图边界
* 裂缝入口

地图探索是游戏中最主要的事件来源。地块负责提供触发入口，具体事件内容由事件系统从对应区域事件池中确定。

### 2.2 区域进入触发

玩家首次进入某个特殊区域，或在满足区域条件后再次进入时，可以触发区域专属事件。

例如：

* 城镇
* 村庄
* 山脉
* 沙漠
* 森林
* 地下洞穴
* 创界山

区域事件通常具有较强的世界观与地理特点。不同区域应维护各自的事件内容，不能使用同一组通用事件代替区域差异。

### 2.3 NPC 交互触发

玩家与部分 NPC 完成交互后，可以触发对应事件。

例如：

* 商人
* 铁匠
* 占卜师
* 神官
* 流浪旅人
* 神秘老人

部分 NPC 事件允许玩家进行选择，并根据玩家的身份、信仰、资源、关系或历史行为产生不同结果。

### 2.4 任务触发

玩家接受任务、推进任务阶段或完成任务时，可以触发新的后续事件。

例如：

* 完成悬赏任务。
* 完成隐藏任务。
* 收集指定材料。
* 击败特殊 Boss。

该类事件通常用于推进剧情、改变任务状态或开启新的探索内容。事件系统负责触发后续内容，但任务是否完成及其进度变化仍由任务系统负责判断。

### 2.5 世界状态触发

游戏中的部分世界状态可以直接触发事件，也可以改变当前可用事件池。

例如：

* 当前天气。
* 昼夜变化。
* 其他世界事件正在进行。
* 地图发生裂变。
* 特殊节日到来。
* Boss 出现或被击败。

不同世界状态下，可以启用不同事件池或调整事件权重，使事件内容与当前世界阶段保持一致。

### 2.6 道具、装备与能力触发

部分特殊道具、装备或能力可以由玩家主动使用，并触发指定事件入口。

例如：

* 使用藏宝图。
* 使用神秘卷轴。
* 开启古老宝箱。
* 使用传送水晶。

此类触发方式通常由玩家主动控制，但具体结果仍应根据物品说明与对应事件池确定。物品只负责提供触发入口，不直接绕过事件条件生成不合法事件。

## 3. 事件触发流程

所有事件均按照统一流程进行触发：

```text
玩家行为或世界状态满足触发条件
                │
                ▼
          确定触发来源
                │
                ▼
     确定事件类型与候选事件池
                │
                ▼
   合并候选事件并移除重复事件
                │
                ▼
 根据当前状态筛选满足限制的事件
                │
                ▼
       计算事件的当前抽取权重
                │
                ▼
       从合法候选事件中抽取
                │
                ▼
             事件开始
```

事件系统必须在随机抽取前完成条件检查。事件的区域、昼夜、天气、玩家状态、任务进度、冷却时间及唯一性限制不满足时，该事件不能进入本次候选集合。

多个事件池同时参与时，应先合并候选事件并按照事件标识去重，再进行条件筛选与权重计算，避免同一事件因存在于多个候选来源中而被重复增加抽取概率。

若筛选后不存在合法事件，则本次触发不产生事件。系统不应采用“先抽取、失败后反复重抽”的方式寻找结果。

若事件存在多个可选结果，则在事件公开后进入选择阶段；否则直接进入事件效果结算。

---

## 4. 事件结算流程

事件开始后，根据事件内容完成统一结算：

```text
事件开始
    │
    ▼
展示事件描述与可见信息
    │
    ▼
玩家选择（若存在）
    │
    ▼
检查选择条件并生成待结算效果
    │
    ▼
开启响应窗口（若允许）
    │
    ▼
执行最终事件效果
    │
    ▼
通知相关系统更新状态
    │
    ▼
记录持续效果（若存在）
    │
    ▼
事件结束
```

对于即时事件，效果结算完成后立即结束，不保留额外状态。

对于持续事件，事件系统应记录作用对象、开始时间、剩余时间、结算时机与结束条件，并在后续指定阶段继续处理，直至事件结束。

事件涉及战斗、地图、NPC、经济或任务变化时，由对应系统执行具体业务结果。事件系统负责组织流程与传递结果，不重复实现其他系统的内部规则。

如果事件允许策略牌或其他能力干预，应在最终效果执行前开启合法响应窗口。响应窗口关闭后，不得追溯使用策略牌修改已经完成的事件结果。

## 5. 事件持续时间

根据事件的设计目标，可以将持续方式划分为以下类型：

| 持续类型 | 说明 |
| --- | --- |
| 即时事件 | 立即完成全部结算，不保留持续状态。 |
| 回合事件 | 持续指定回合数，到期后自动结束。 |
| 条件事件 | 持续生效，直至满足明确的结束条件。 |
| 世界持续事件 | 在指定时间内影响整个世界、多个区域或所有玩家。 |
| 永久事件 | 对本局世界状态产生不可自动恢复的变化，通常极为稀有。 |

除特殊设计外，大部分事件应采用即时事件或回合事件，以避免长期累积过多持续效果。

持续事件必须明确以下内容：

* 作用对象。
* 开始生效的时间。
* 每次结算的时机。
* 持续回合数或结束条件。
* 重复触发时的处理方式。
* 结束后是否恢复原有状态。

永久事件仅用于明确改变本局世界格局的特殊内容，不能用于长期保留难以追踪的隐藏数值修饰。

## 6. 事件触发限制

为了避免事件频繁重复出现或影响游戏节奏，事件可以设置触发限制。

包括但不限于：

* 同一事件可以设置冷却时间。
* 同一玩家连续触发相同事件时，可以降低其抽取权重。
* 特殊事件可以设置整局唯一或每名玩家仅触发一次。
* 同一种世界事件通常不能重复存在。
* 部分事件仅允许首次探索时触发。
* 特定事件需要满足身份、转职、信仰、任务或地图条件。
* 彩蛋事件仅在满足隐藏条件时进入候选集合。
* 高影响事件可以限制可出现的游戏阶段与最低轮次。

事件限制只负责判断事件能否进入当前候选集合，不能在事件已经完成结算后追溯改变其结果。

隐藏条件可以对玩家保密，但系统必须能够明确判断。不能使用无法验证的描述作为触发条件。

## 7. 事件池机制

为了保证不同场景下的事件内容符合当前环境，系统采用分类事件池进行管理。

每个事件池负责维护特定区域、场景或触发来源下可以出现的事件集合。事件池本身不决定最终结果，而是为当前触发提供候选事件。

常见事件池包括：

* 地图事件池
* 城镇事件池
* 野外事件池
* 副本事件池
* NPC 事件池
* 天气事件池
* 世界事件池
* 彩蛋事件池

玩家触发事件时，系统首先根据触发来源、所在区域与当前世界状态确定候选事件池，再对其中的事件进行去重、条件筛选与权重抽取。

事件池中的每项事件可以配置基础权重。区域、天气、昼夜、游戏阶段与近期触发记录可以对当前权重进行调整，但不能使不满足触发条件的事件重新进入候选集合。

事件池机制可以概括为：

```text
触发来源 + 区域 + 世界状态
              │
              ▼
         候选事件池
              │
              ▼
       合并、去重与筛选
              │
              ▼
         动态权重调整
              │
              ▼
          抽取一个事件
```

这种设计能够保证不同区域具有不同的探索体验，同时方便后续新增地图与扩展事件内容，而无需修改整体事件框架。

## 8. 设计原则

事件分类与触发机制遵循以下设计原则：

分类明确原则

不同类型的事件应拥有清晰的主要作用范围。事件类型用于描述内容，事件池用于描述出现环境，两者不能混为一谈。

触发自然原则

玩家应通过探索、交互、任务推进与世界变化自然接触事件，而不是依赖与当前行为无关的固定流程。

流程统一原则

所有事件采用统一的触发、筛选与结算流程，以降低理解和维护成本。

先筛选后抽取原则

系统必须先移除不满足条件的事件，再从合法候选集合中进行随机抽取，避免无效事件进入结算流程。

场景匹配原则

事件应优先从符合当前区域、天气、昼夜与游戏阶段的事件池中生成，保证世界观与场景逻辑一致。

节奏控制原则

同一行动能够触发的事件数量、重复事件频率与高影响事件出现时机都应受到限制，避免随机事件频繁打断主要玩法。

方便扩展原则

后续新增事件、地图或玩法时，只需增加事件配置或调整对应事件池，无需修改已有触发与结算框架。
