# 《开天辟地之大地的裂变》装备设计规范

## 1. 设计目标

装备设计规范用于统一整个游戏装备系统的设计思想，为后续所有装备、图纸、制造及扩展内容提供统一标准。

本规范不规定具体装备的数据，而是规定装备应如何设计、如何分类、如何形成成长，以及如何与其他系统进行联动，从而保证整个装备体系具有良好的平衡性、扩展性与可维护性。

装备设计应始终遵循以下核心理念：

**装备服务于玩法，而不是单纯服务于数值。**

玩家更换装备，应当是为了适应不同的战斗、探索和地图环境，而不是始终选择攻击力最高或防御力最高的一件装备。

装备系统需要保留原剧中职业、装备、卡牌、状态和冒险规则彼此叠加的复杂感，但每件装备本身仍应拥有清晰定位。系统层面可以丰富，单件装备不能因此变成包含所有功能的规则集合。

---

## 2. 装备设计原则

### 2.1 明确装备定位

每件装备都应拥有明确的设计定位。

一件装备可以突出某一方面能力，也可以附带少量其他效果，但不应同时承担多个装备类别的核心职责。

各类别的主要定位如下：

* 武器主要影响攻击能力
* 护甲主要影响生存能力
* 鞋子主要影响移动能力
* 饰品主要影响角色构筑
* 特殊装备主要影响探索与世界交互能力

设计装备前，应当能够使用一句话说明该装备的用途。

例如：

```text
一把适合对付高物理防御敌人的长枪。

一双能够降低沼泽移动消耗的靴子。

一件在黑夜中提高感知能力的饰品。
```

如果一件装备无法用简短语言说明核心用途，或者同时解决输出、生存、移动、探索和资源问题，则应重新拆分其效果。

尽量避免出现“一件装备解决所有问题”的设计。

### 2.2 机制优于数值

装备成长应优先丰富玩法，而不是无限增加数值。

普通装备可以主要体现基础数值差异；高品质装备则应更多体现：

* 新的战斗机制
* 特殊触发效果
* 地图探索能力
* 资源管理能力
* 环境适应能力
* 与其他系统的联动能力

装备品质越高，其特色应越明确，而不是单纯拥有更高的攻击力、生命值或防御力。

高品质装备的复杂度也不能无限增加。品质提高代表机制更加独特，不代表文本必须更长、触发链必须更多。

### 2.3 不存在绝对最优装备

游戏中原则上不存在所谓“毕业装备”。

不同装备应适用于不同场景，例如：

* 不同地图与区域
* 不同天气与昼夜
* 不同敌人与伤害类型
* 不同任务与使命
* 不同身份与转职
* 不同信仰
* 不同队伍配置

装备之间应形成横向选择，而不是单纯纵向淘汰。

高品质装备可以拥有更独特的机制和更高的构筑价值，但不应在所有场景下无条件替代低品质装备。

### 2.4 保持简单易理解

装备效果应尽量做到：

* 容易阅读
* 容易理解
* 容易结算
* 容易维护
* 容易追踪来源

单件装备通常只设置一项核心机制。

少量高品质装备可以拥有两项相互关联的机制，但应避免：

* 过多连续触发
* 递归触发
* 装备之间形成无限循环
* 同一事件被重复响应
* 需要长期记忆但无法从状态中读取的隐藏效果

如果一项装备效果需要大量例外规则才能成立，应优先使用已有系统重新表达，而不是继续增加专属判断。

## 3. 装备组成规范

原则上，每件装备可以由基础信息、基础数值效果、特殊机制、使用条件和主动能力组成。

并非所有装备都必须拥有全部组成部分，但装备类型、品质和核心定位必须明确。

### 3.1 基础信息

每件装备至少应定义以下基础信息：

| 信息 | 说明 |
| --- | --- |
| 装备名称 | 用于展示和识别的正式名称。 |
| 装备标识 | 配置和程序使用的唯一标识。 |
| 装备类型 | 武器、护甲、鞋子、饰品或特殊装备。 |
| 装备品质 | 普通、优秀、稀有、史诗或传说。 |
| 核心定位 | 使用一句话说明装备的主要用途。 |
| 穿戴数量限制 | 是否允许同名装备同时穿戴。 |
| 获取方式 | 掉落、任务、交易、图纸制造或其他来源。 |

神话品质仅保留名称与层级定义，属于未来扩展项。当前阶段不定义其颜色、数值区间、获取方式与特殊规则，也不允许在常规装备配置中使用。

### 3.2 基础数值效果

基础数值效果用于体现装备最直接的能力提升。

这里的“基础数值效果”是装备效果的组成部分，不等同于《06-数值系统》中的五项基础属性（Primary Attributes）。

装备可以修正：

* 力量、体质、灵力、敏捷和悟性等基础属性
* 物理攻击、法术攻击和物理防御
* 法术抗性、命中、闪避和穿透
* 移动力、移动速度、视野和感知
* 幸运值、最大生命值和最大灵力值
* 其他已经纳入数值系统的派生属性

装备数值必须统一接入属性修饰器：

| 装备效果 | 数值系统处理方式 |
| --- | --- |
| 修正五项基础属性 | 写入 `primaryDynamicOffset` |
| 直接修正派生属性 | 写入 `derivedDynamicOffset` |

装备穿戴时添加修饰器，卸下、失效或不再满足生效条件时移除修饰器，不永久修改角色当前基础属性。

并非所有装备都必须拥有基础数值效果。纯机制装备可以不提供任何直接属性加成。

### 3.3 特殊机制

特殊机制用于体现装备特色，也是高品质装备的核心价值。

例如：

* 改变攻击方式
* 提供或免疫特定状态
* 影响移动方式
* 改变资源获取方式
* 增强探索能力
* 与天气、昼夜、地图或裂变状态联动
* 满足条件后触发一次明确效果

通常建议每件装备拥有一项主要机制，少量高品质装备可以拥有两项相互关联的机制。

每项机制必须明确：

* 触发时机
* 生效条件
* 作用目标
* 持续时间
* 是否可以叠加
* 是否具有次数或冷却限制
* 与其他规则冲突时的处理方式

装备机制应调用战斗、地图、状态、经济等已有系统完成结算，不应自行复制另一套同类规则。

### 3.4 使用条件

部分装备可以拥有使用条件，用于体现装备特色或限制适用范围。

常见条件包括：

* 特定身份
* 特定转职
* 特定信仰
* 特定等级
* 特定地图或区域
* 特定天气或昼夜
* 特定角色状态
* 特定任务进度

使用条件分为两类：

| 条件类型 | 说明 |
| --- | --- |
| 穿戴条件 | 不满足时不能将装备放入对应装备栏。 |
| 生效条件 | 可以正常穿戴，但只有满足条件时才提供指定效果。 |

设计时必须明确条件属于哪一种，不能在结算时临时解释。

使用条件应作为玩法设计的一部分，为装备建立适用场景，而不是单纯为了排除玩家或人为延长成长时间。

### 3.5 主动能力（可选）

少量装备可以拥有主动能力。

主动能力应遵循以下要求：

* 操作简单
* 使用时机明确
* 消耗与冷却明确
* 目标和效果清晰
* 响应与冲突规则明确
* 数量保持较少

原则上不建议大量装备同时拥有主动能力，以避免玩家操作负担过重，并防止装备栏变成额外技能栏。

主动能力的行动类型、目标选择和冷却结算由回合系统与对应玩法系统负责，装备系统只负责声明能力来源和配置内容。

## 4. 各装备类别职责

为了保持装备系统长期可维护，各类别装备应拥有明确职责。

### 4.1 武器

武器主要负责角色的输出能力，并定义角色最主要的攻击方式。

设计重点包括：

* 攻击方式
* 攻击距离
* 伤害类型
* 命中与暴击
* 穿透能力
* 战斗节奏

武器可以附带少量战斗辅助机制，但原则上不承担大量探索、生存或资源生产功能。

### 4.2 护甲

护甲主要负责角色的生存能力。

设计重点包括：

* 物理防御
* 法术抗性
* 状态抵抗
* 最大生命值
* 承受伤害的特殊机制
* 环境抗性

护甲可以具有反击或受击触发效果，但不应成为角色主要且稳定的输出来源。

### 4.3 鞋子

鞋子主要负责角色的移动与地形适应能力。

设计重点包括：

* 地形适应
* 移动力
* 移动速度
* 地势影响
* 行动顺序
* 位移能力

鞋子可以提供少量闪避或环境抗性，但原则上不提供大量攻击属性。

### 4.4 饰品

饰品主要负责角色构筑与机制补充。

设计重点包括：

* 属性强化
* 幸运系统
* 资源循环
* 技能辅助
* 身份或转职特色
* 条件触发效果

玩家可以同时装备两件饰品。

同名饰品原则上不能同时装备，以避免相同机制重复叠加。只有具体饰品明确声明允许重复穿戴时，才可以覆盖该限制。

两件饰品之间可以形成组合，但不应设计必须长期绑定的唯一组合，避免压缩饰品栏的选择空间。

### 4.5 特殊装备

特殊装备主要负责地图探索与世界交互。

设计重点包括：

* 地图探索
* 环境互动
* 特殊事件
* 地图机关
* 裂变系统
* 隐藏区域
* 特殊功能

特殊装备应尽量避免承担主要战斗能力，也不应成为另一件武器、护甲或饰品。

## 5. 数值设计原则

装备数值应与整体数值系统保持统一。

### 5.1 整数优先

装备属性、次数、消耗和持续回合原则上使用整数，并遵循《06-数值系统》中的取整与边界规则。

### 5.2 使用已有属性

装备应优先修正现有基础属性和派生属性，不为单件装备创建只有自身使用的新属性。

对于涉及概率的效果，应优先使用幸运值、命中、暴击率等已有属性进行统一计算，避免每件装备设计独立的随机规则。

### 5.3 控制比例效果

装备应避免大量百分比效果相互叠加。

如果必须使用比例，应明确比例单位、结算顺序、取整方式和上下限，并调用数值系统的统一规则。

能够使用固定整数表达的效果，不应优先设计为百分比。

### 5.4 禁止无限成长与循环

装备原则上不允许无限成长。

可以累积或升级的装备必须设置明确的：

* 最大层数
* 最大等级
* 单次增长值
* 触发次数
* 重置或结束条件

装备效果之间不得形成无限资源、无限触发、无限伤害或无法结束的结算循环。

### 5.5 保持合理差距

装备之间应更多依赖机制形成差异，而不是依赖巨大数值差距。

品质提升可以增加装备的机制价值和适用范围，但不应使低品质装备在获得高品质装备后全部失去使用意义。

## 6. 与其他系统的联动

装备系统不是独立存在，而是整个游戏循环的重要组成部分。

后续新增装备时，应优先考虑与已有系统形成联动。

| 关联系统 | 装备联动方向 |
| --- | --- |
| 地图系统 | 不同区域的材料、探索装备、地形适应和特殊地点。 |
| 战斗系统 | 攻击方式、伤害、防御、状态和战斗触发。 |
| 图纸与制造系统 | 图纸、材料、制造条件和装备产出。 |
| 背包与物品系统 | 装备实例的持有、存放、拾取、丢弃及装备栏之间的转移。 |
| NPC 系统 | 商店、制造、鉴定、赠送和特殊服务。 |
| 经济系统 | 材料、图纸、装备价格和玩家交易。 |
| 任务系统 | 装备奖励、任务需求和特殊获取条件。 |
| 天气系统 | 环境适应、天气触发和天气抗性。 |
| 昼夜系统 | 昼夜限定效果和探索能力。 |
| 裂变系统 | 异常装备、特殊变化和隐藏机制。 |
| 数值系统 | 属性修饰、整数规则、边界和最终属性计算。 |

装备之间的联动应尽量通过已有系统实现，而不是新增独立规则。

例如：

* “在森林中视野 +1”应读取地图系统的区域或地形信息
* “黑夜中感知 +2”应读取昼夜系统的当前状态
* “受到攻击后获得护盾”应由战斗与状态系统完成触发和持续时间管理
* “出售材料时收益 +1”应由经济系统处理价格结算

装备系统只声明装备提供了何种效果，不重复实现地图、战斗、状态或经济系统的底层逻辑。

## 7. 扩展规范

装备系统应具备良好的扩展能力。

未来新增任何装备时，应遵循以下流程：

```text
明确装备定位
↓
确定所属类别
↓
设计基础数值效果
↓
设计核心机制
↓
确定使用条件
↓
确定图纸与制造方式
↓
确定其他获取途径
↓
检查与已有系统的联动
↓
检查触发、叠加与冲突规则
↓
完成数值平衡
```

### 7.1 新装备检查清单

新增装备在进入正式配置前，应至少确认以下内容：

* 是否能够用一句话说明核心定位
* 是否符合所属装备类别的主要职责
* 是否与现有装备形成场景选择，而不是完全替代
* 是否只使用已有属性和通用修饰器
* 是否明确触发时机、生效条件、目标和持续时间
* 是否明确同名装备与同类效果的叠加规则
* 是否可能形成递归触发或无限收益
* 是否明确图纸、材料、制造与其他获取方式
* 是否调用已有系统完成具体结算
* 是否符合当前品质的复杂度与稀有程度
* 是否能够通过配置新增，而不修改装备系统底层逻辑

### 7.2 资源扩展原则

新的装备、图纸、材料和制造方式，都应遵循本规范进行设计。

当后续增加新的地图、身份、转职、信仰、副本及裂变内容时，应优先通过增加装备配置和资源内容进行适配，而不轻易修改装备系统底层规则。

通过保持系统稳定、资源持续扩展的设计方式，使装备系统能够随着游戏内容不断丰富，并始终保持统一、清晰且易于维护的整体架构。
