# 《开天辟地之大地的裂变》扩展任务类型

> 本文档属于 V2 版本预留设计，不属于当前版本（V1）的开发范围。文中任务类型不得提前加入 V1 的任务类型枚举、任务池或实现计划。

当前版本仅实现委托任务、悬赏任务、探索任务与隐藏任务四种基础类型。世界任务、阵营任务、职业专属任务与种族专属任务仅作为未来扩展方向，其参与方式、进度归属、奖励范围与冲突规则将在后续版本中进一步完善。

所有 V2 扩展任务仍应复用 V1 已经建立的任务静态定义、运行时实例、生命周期、品质体系与奖励池规范。新增类型只用于扩展任务的适用范围和玩法定位，不代表为每种类型重新建立一套 Quest 系统。

---

## 1. 世界任务（World Quest）

世界任务是面向整个游戏世界开放的特殊任务。

与普通任务不同，世界任务通常由重大事件、特殊场景、世界阶段或全局状态触发，而不是由单个 NPC 向单个玩家发布。

世界任务可以允许多名玩家共同参与，也可以围绕同一目标形成竞争。无论采用何种参与方式，都必须在任务定义中明确参与范围、进度归属、完成判定及奖励对象。

### 1.1 设计特点

世界任务具有以下特点：

* 影响范围通常覆盖多个玩家、区域或整个世界。
* 触发条件通常来自世界事件、地图变化或世界阶段。
* 持续时间通常长于普通任务。
* 目标规模与整体难度相对较高。
* 奖励价值通常较高，并可以包含公共世界结果。
* 任务完成可以推动世界状态或剧情阶段发生变化。

### 1.2 参与方式

世界任务未来可以支持以下参与模式：

| 模式 | 说明 |
| --- | --- |
| 共同任务 | 多名玩家共同推进同一目标，达到全局条件后统一完成。 |
| 独立贡献 | 玩家分别积累个人贡献，世界目标完成后按照贡献发放奖励。 |
| 竞争任务 | 多名玩家争夺同一目标，由最先满足条件的玩家或队伍完成。 |

参与模式必须由任务配置明确指定，不能在任务进行过程中临时切换。

世界任务的公共进度不应占用普通玩家任务实例中的个人进度字段。后续实现时应在复用任务定义的基础上，增加统一的世界任务参与与贡献状态，而不是将同一份公共进度复制到每名玩家身上。

### 1.3 系统边界

世界事件负责改变世界并提供世界任务触发条件，世界任务负责维护目标、参与者、贡献与奖励。两者可以联动，但不能合并为同一概念。

世界任务完成后可以请求世界系统改变地图、天气、NPC 或剧情状态，具体变化仍由对应系统执行。

## 2. 阵营任务（Faction Quest）

阵营任务是未来组织型阵营系统开放后，由特定阵营向其成员提供的专属任务。

玩家加入某个阵营后，可以领取符合自身阵营关系与声望条件的任务。不同阵营可以拥有独立的任务主题、目标倾向、资源需求与奖励内容。

当前角色系统中的“阵营”本质上表示光明、混沌与中立三种信仰立场，并非国家、组织或势力。V2 的 Faction Quest 指向未来可能新增的组织型阵营，不应直接将现有隐藏信仰公开为普通任务领取条件。

### 2.1 设计特点

阵营任务具有以下特点：

* 仅限符合阵营成员条件的玩家领取。
* 通过任务目标与叙事强化不同阵营的特色。
* 可以鼓励同阵营玩家协作。
* 可以围绕资源、区域或世界目标形成阵营竞争。
* 奖励可以包含阵营声望、阵营资源或专属权限。

### 2.2 设计边界

阵营任务不能只通过更换阵营名称重复使用完全相同的内容。不同阵营应在目标、解决方式或奖励方向上体现真实差异。

阵营任务也不能强迫玩家公开隐藏信仰、使命或契约信息。组织阵营资格与隐藏信仰必须保持独立，除非未来规则明确建立两者之间的公开关系。

玩家退出、转换或失去阵营资格时，已领取阵营任务如何处理，需要由未来阵营系统统一规定，不能由单项任务自行决定。

---

## 3. 职业专属任务（Class Quest）

职业专属任务仅允许符合指定角色定位或成长路线的玩家领取。

不同职业可以拥有符合自身玩法特点的成长内容，通过完成专属任务获得相关资源、知识、装备或剧情体验。

例如：

* 法师学习新的魔法知识。
* 游侠调查森林遗迹。
* 杀手完成秘密委托。
* 盗贼破解隐藏机关。
* 魔王挑战强大的统治者。
* 神仙长老寻找失落的古老典籍。

本项目当前统一使用“身份（Identity）”描述法师、游侠、杀手等开局定位，并通过转职系统扩展后续成长路线。V2 设计中的 Class Quest 在正式实现前，应明确映射到基础身份或转职身份，不能额外创建一套与身份系统重复的职业数据。

### 3.1 设计特点

职业专属任务具有以下特点：

* 仅允许符合指定身份或转职条件的玩家领取。
* 任务目标应体现对应身份的核心玩法。
* 用于增强不同身份的发展差异与叙事体验。
* 奖励方向应与身份定位相匹配。
* 可以用于引导玩家理解身份能力与成长路线。

### 3.2 奖励边界

职业专属奖励可以包含相关装备、图纸、资源与剧情内容，但不能使对应身份获得无法平衡的基础数值优势。

专属任务不应成为身份正常成长的唯一途径。玩家未能触发或完成某项职业任务时，仍应能够通过其他系统继续参与游戏，不得因此永久失去基本能力。

## 4. 种族专属任务（Race Quest）

种族专属任务仅允许符合指定种族条件的玩家领取，用于展现不同种族的历史、文化、生活方式与世界关系。

不同种族可以拥有各自的叙事主题与任务内容，使种族选择不仅表现为角色标签或数值调整，也能够在探索与剧情中形成差异化体验。

例如：

* 人族协助城镇建设。
* 神族守护古老神殿。
* 魔族完成恶魔试炼。
* 妖族探索远古秘境。

具体种族名称、背景与可用任务必须以角色种族系统的正式定义为准。示例只用于说明设计方向，不代表 V2 已经确定全部种族内容。

### 4.1 设计特点

种族专属任务具有以下特点：

* 仅允许符合指定种族条件的玩家领取。
* 用于丰富种族背景与世界观内容。
* 增强玩家选择不同种族时的代入感。
* 任务目标可以体现种族文化、历史与环境关系。
* 奖励方向可以与种族特色相关，但仍需保持整体平衡。

### 4.2 设计边界

种族专属任务应提供内容与体验差异，不应通过高额基础属性奖励形成种族之间的长期强度差距。

不同种族的专属任务数量、预期难度与总体奖励价值应保持相对平衡。某个种族可以在任务主题上更偏向战斗、探索或交互，但不能因此稳定获得明显更多的永久成长资源。

## 5. 与 V1 任务类型的关系

V2 扩展任务类型用于描述任务的适用范围与参与方式，V1 基础类型用于描述任务的主要玩法内容。

两者可以形成组合关系。例如：

| 扩展类型 | V1 主要玩法类型 | 示例 |
| --- | --- | --- |
| 世界任务 | 悬赏任务 | 所有玩家共同击败世界首领。 |
| 世界任务 | 探索任务 | 多名玩家共同调查裂变区域。 |
| 阵营任务 | 委托任务 | 为所属阵营收集指定资源。 |
| 职业专属任务 | 探索任务 | 游侠调查森林中的隐藏遗迹。 |
| 种族专属任务 | 隐藏任务 | 满足种族条件后开启远古试炼。 |

未来实现时，不建议将“世界”“阵营”“职业”“种族”与“委托”“悬赏”“探索”“隐藏”全部混入同一个互斥枚举。

更合理的方式是继续保留 V1 的主要任务类型，并为 V2 增加适用范围、参与模式或资格标签。这样既能够组合不同玩法，也可以避免随着扩展内容增加而产生大量重复类型。

具体字段结构需要在 V2 开发前重新评审，本文件只确定扩展方向，不提前修改 V1 数据结构。

## 6. V2 设计原则

V2 扩展任务类型遵循以下原则：

兼容 V1 原则

扩展类型不能破坏 V1 任务系统的静态定义、运行时实例、生命周期、任务栏与奖励结算规则。

统一生命周期原则

扩展任务继续复用未触发、可领取、进行中、完成、奖励、放弃、失效与结束等基础生命周期，不为每种扩展类型建立独立状态机。

组合扩展原则

世界、阵营、职业与种族优先作为适用范围或参与方式，与委托、悬赏、探索和隐藏等主要玩法类型组合使用。

职责清晰原则

世界、阵营、身份、种族与任务系统分别维护自身状态。任务系统只引用其他系统已经确认的资格与结果，不复制其核心业务逻辑。

平衡一致原则

扩展任务继续使用统一品质与奖励体系。专属资格可以改变任务内容，但不能自动获得更高品质或更高价值奖励。

配置优先原则

新增任务仍应以资源配置为主。需要支持多人贡献、竞争归属或资格变化时，应先建立可以复用的公共机制，不为单项任务增加特殊判断。

版本隔离原则

V2 内容在正式启用前，不进入 V1 任务池、任务枚举、随机抽取、测试基线与平衡范围。仅保留文档不代表当前版本已经支持对应功能。

---

## 7. 小结

世界任务、阵营任务、职业专属任务与种族专属任务为任务系统提供了未来的扩展方向。

这些类型可以扩大任务的影响范围，强化组织、身份与种族特色，并支持多人协作或竞争玩法，但不应因此重新建立彼此独立的任务框架。

通过复用 V1 的统一生命周期、品质体系、奖励池与配置规范，并将扩展类型设计为可组合的适用范围和参与方式，任务系统可以在保持底层稳定的前提下逐步丰富长期玩法。
