# 《开天辟地之大地的裂变》任务类型与生命周期

## 1. 任务类型

当前版本共支持四种任务（Quest）类型。不同类型拥有不同的常见来源、目标方向与奖励倾向，但均使用统一的任务数据结构和生命周期。

任务类型用于描述任务的主要玩法定位。一项任务只能指定一个主要类型，不能因为同时包含探索、收集与战斗目标而重复归入多个类型。

| 任务类型 | 英文名称 | 主要玩法 | 常见来源 |
| --- | --- | --- | --- |
| 委托任务 | Commission Quest | 收集、交付、调查与轻量探索。 | NPC、组织、城镇设施。 |
| 悬赏任务 | Bounty Quest | 击败怪物、精英单位或特殊目标。 | NPC、悬赏板、城镇与事件。 |
| 探索任务 | Explore Quest | 抵达地点、发现区域与调查场景。 | 地图地点、NPC、事件与情报。 |
| 隐藏任务 | Hidden Quest | 满足隐蔽条件后开启特殊内容。 | 隐藏地点、特殊事件与秘密交互。 |

### 1.1 委托任务（Commission Quest）

委托任务是游戏中最常见的任务类型，通常由 NPC、组织或城镇设施发布。

任务目标以收集、交付、调查、寻找和轻量探索等内容为主，整体完成难度较低，奖励相对稳定，用于为玩家提供持续且容易理解的阶段性目标。

委托任务具有以下特点：

* 获取方式简单。
* 整体数量较多。
* 目标描述清晰，完成路径相对稳定。
* 鼓励玩家探索地图、收集资源并与 NPC 互动。
* 奖励偏向元宝、经验、普通材料与基础消耗品。

委托任务不代表独立于 Quest 之外的另一套系统。任何 NPC 委托均属于任务系统，并遵循统一的任务栏、进度、放弃与奖励规则。

### 1.2 悬赏任务（Bounty Quest）

悬赏任务主要围绕战斗玩法展开。

玩家通常需要击败指定怪物、精英单位、首领或其他特殊战斗目标才能完成任务。相比普通委托任务，悬赏任务具有更高的战斗风险与资源消耗，其奖励价值通常也相对更高。

悬赏任务具有以下特点：

* 主要目标与战斗结果相关。
* 完成难度通常高于普通委托任务。
* 可以要求指定敌人、数量、区域或战斗条件。
* 奖励通常优于同阶段的普通委托任务。
* 可以引导玩家挑战精英单位与区域首领。

悬赏任务的击败进度只能来源于战斗系统已经确认的战斗结果。发现目标、进入战斗或仅对目标造成伤害，不能提前视为完成击败要求。

### 1.3 探索任务（Explore Quest）

探索任务用于鼓励玩家前往未知区域、特殊地点或具有世界观意义的场景进行探索。

常见目标包括抵达指定地点、发现特殊区域、调查遗迹、揭示地图信息或完成场景交互。探索任务应通过地点与路线引导玩家认识世界，而不是仅要求玩家机械移动固定格数。

探索任务具有以下特点：

* 鼓励玩家探索地图未知区域。
* 提高不同区域与特殊地点的利用率。
* 引导玩家接触世界背景与区域内容。
* 可以与地图情报、特殊道路及场景事件联动。
* 奖励偏向地图信息、材料、图纸与探索类道具。

探索任务是否完成，由地图系统确认玩家已经满足抵达、发现或交互条件后，再向任务系统提交结果。仅在客户端看到目标区域不能视为已经完成探索。

### 1.4 隐藏任务（Hidden Quest）

隐藏任务在触发前不会主动向玩家展示，也不会出现在普通任务列表或可领取任务列表中。

只有玩家满足特定隐藏条件后，任务才会被触发。例如：

* 到达特殊地点。
* 完成指定事件或前置任务。
* 满足特定角色、物品或世界状态条件。
* 与场景或 NPC 进行特殊交互。
* 在特定昼夜、天气或地图阶段执行指定行为。

隐藏任务具有以下特点：

* 触发条件具有一定隐蔽性。
* 整体数量较少。
* 通常包含特殊剧情、地点或交互内容。
* 奖励价值一般高于同阶段的普通任务。
* 用于增强探索过程中的未知感与发现乐趣。

隐藏任务只在“未触发”阶段隐藏。触发条件满足后，该任务进入正常的可领取状态，并按照任务规则向有权领取的玩家展示必要信息。

隐藏任务触发不代表玩家已经领取任务。若玩家任务栏已满，仍不能绕过上限直接进入进行中状态；任务是否继续保持可领取，由具体任务来源与有效规则决定。

## 2. 任务生命周期

所有任务均遵循统一的生命周期：

```text
未触发
   │
   ▼
可领取
   │
   ▼
进行中
   │
   ├──────────────┬──────────────┐
   │              │              │
   ▼              ▼              ▼
已完成         主动放弃         已失效
   │              │              │
   ▼              ▼              ▼
待领取奖励        已结束          已结束
   │
   ▼
奖励发放
   │
   ▼
已结束
```

任务状态按照单向流程变化。任务进入主动放弃、已失效或奖励发放完成后的结束状态后，不能重新回到进行中状态。

### 2.1 未触发

任务尚未满足触发条件，玩家无法查看、领取或主动操作该任务。

普通任务可以在任务来源尚未开放时处于未触发状态；隐藏任务在满足隐藏条件前始终处于该状态，并且不会公开任务名称、目标、奖励或触发条件。

未触发任务不属于任何玩家持有的任务实例，不占用任务栏位置，也不计算有效回合。

### 2.2 可领取

任务已经满足触发条件，并由对应 NPC、场景、事件或其他来源提供给玩家。

玩家可以查看规则允许公开的任务内容、主要目标与奖励信息，并自行决定是否领取。

领取任务前，任务系统必须检查：

* 当前任务仍然可以领取。
* 玩家满足任务领取条件。
* 玩家当前持有任务数量少于 `4`。
* 唯一任务尚未被其他规则锁定或完成。
* 前置任务与世界状态仍然有效。

任意条件不满足时，本次领取失败，不创建任务实例，也不占用任务栏位置。

### 2.3 进行中

玩家成功领取任务后，任务进入进行中状态并占用一个任务栏位置。

进行中状态下，玩家可以查看：

* 任务名称与任务类型。
* 已公开的任务描述。
* 当前目标与完成条件。
* 当前任务进度。
* 剩余有效回合。
* 已公开的任务奖励。

任务进度只能根据其他系统已经确认的业务结果进行更新。收集、击败、抵达、交互与提交等不同目标，分别由对应系统提供权威结果，任务系统只负责匹配目标并记录进度。

### 2.4 已完成

当任务的全部必要完成条件满足后，任务进入已完成状态。

任务完成时，系统应固定本次完成结果，不再继续修改任务进度。已经完成的任务不会因为玩家之后失去物品、离开区域或状态变化而恢复为进行中。

已完成任务不再占用进行中任务栏位置，并进入待领取奖励阶段。任务完成与奖励发放属于两个独立步骤，系统不能在尚未确认完成时提前生成奖励。

### 2.5 待领取奖励

任务完成后，玩家可以领取对应奖励。

领取奖励时，任务系统负责确认任务尚未领取奖励，并生成任务配置声明的奖励内容；元宝、经验、手牌、物品及其他奖励分别交由对应系统完成实际结算。

奖励全部成功发放后，任务进入已结束状态，并从玩家当前任务界面中移除。奖励结算失败时，任务保持待领取奖励状态，不能重复生成已经成功发放的部分奖励。

### 2.6 主动放弃

玩家可以在自己的回合内主动放弃任意一个进行中的任务。

主动放弃遵循以下规则：

* 只能在玩家自己的回合内进行。
* 每回合主动放弃次数不限。
* 放弃不会产生元宝、属性、状态或其他额外惩罚。
* 放弃后立即释放对应任务栏位置。
* 任务实例与当前进度立即失效。
* 已经积累的任务进度不会保留。
* 已完成、待领取奖励或已经结束的任务不能主动放弃。

任务进入主动放弃状态后立即结束。玩家之后重新领取同一任务时，应创建新的任务实例，并从初始进度重新开始。

### 2.7 已失效

进行中的任务超过有效回合，或因任务规则明确规定的终止条件而无法继续时，进入已失效状态。

任务失效后：

* 立即停止记录新的任务进度。
* 不生成任务完成奖励。
* 释放对应任务栏位置。
* 从当前任务列表中移除。
* 已经积累的任务进度不再保留。

任务暂时难以完成、目标距离较远或玩家当前资源不足，不属于自动失效条件。只有有效时间结束或任务配置声明的终止条件成立时，系统才能使任务失效。

### 2.8 已结束

已结束是任务生命周期的最终状态。

任务可以通过以下方式进入已结束状态：

* 完成任务并成功领取全部奖励。
* 玩家主动放弃进行中的任务。
* 任务超过有效时间或满足终止条件。

已结束任务不占用任务栏位置，也不再接收任何进度更新。系统可以保留必要的任务结果记录，用于日志、存档、使命进度与赛后复盘，但不会继续将其作为当前任务向玩家展示。

## 3. 任务有效时间

每个任务均拥有有效回合数，用于限制任务进入进行中状态后可以持续的时间。

默认有效回合数为：

```text
999999 回合
```

该值表示任务长期有效，在正常的一局游戏中可以视为不会自然过期。长期任务仍使用普通整数回合数，不额外建立“永久任务”布尔标记或特殊生命周期分支。

对于部分具有明确时限的特殊任务，可以配置有限的有效回合，例如：

* `10` 回合。
* `20` 回合。
* `50` 回合。

任务有效时间遵循以下规则：

* 有效回合从玩家成功领取任务并进入进行中状态后开始计算。
* 每次该玩家自身回合结束时，剩余有效回合数减少 `1`。
* 任务在剩余回合数归零前完成，则正常进入已完成状态。
* 任务在回合结束结算时归零且尚未完成，则进入已失效状态。
* 未触发与可领取状态不消耗任务有效回合。
* 已完成与待领取奖励状态不再消耗任务有效回合。

同一回合内，系统应先结算该玩家已经确认的任务进度与完成结果，再扣减任务剩余有效回合。已经在本回合完成的任务不会因随后进行的有效时间扣减而失效。

默认值 `999999` 应由任务系统公共配置统一维护，任务定义可以引用该配置，不应在每项长期任务中重复写入不同的近似大数。

## 4. 唯一任务

部分任务属于唯一任务（Unique Quest）。

唯一任务在当前对局中最多只能成功完成一次，通常用于控制特殊 NPC、稀有物品、特殊遗迹与剧情内容的稀缺性。

例如：

* 某位特殊 NPC 的一次性委托。
* 某件传说装备的获取任务。
* 某个特殊遗迹的探索任务。
* 某条隐藏剧情的关键任务。

唯一任务遵循以下规则：

* 系统统一记录唯一任务的全局状态。
* 同一时间只能存在一个有效的唯一任务实例。
* 唯一任务完成后，立即记录为本局已完成。
* 已完成的唯一任务不能再次生成、领取或完成。
* 唯一任务主动放弃或失效后，不会记录为已完成。
* 未完成的唯一任务是否能够再次出现，由任务来源与当前世界状态决定。

普通任务不受全局唯一限制。只要满足触发条件、重复规则与任务栏限制，普通任务可以在同一局游戏中再次出现，并为每次领取创建独立任务实例。

任务的“唯一”只限制当前对局中的任务实例与完成记录，不代表任务定义只能存在于一份资源文件，也不影响其他游戏对局正常生成同一任务。

## 5. 生命周期结算顺序

当同一结算节点同时发生进度增加、任务完成、有效时间减少与其他状态变化时，统一按照以下顺序处理：

```text
接收其他系统确认的业务结果
            │
            ▼
更新任务目标与进度
            │
            ▼
检查任务是否完成
            │
       ┌────┴────┐
       │         │
       ▼         ▼
    已完成      未完成
       │         │
       │         ▼
       │   扣减剩余有效回合
       │         │
       │         ▼
       │   检查任务是否失效
       │         │
       └────┬────┘
            ▼
      提交最终任务状态
```

主动放弃由玩家在自己的回合主动发起，不与普通进度更新同时执行。任务状态一旦在当前结算中进入已完成、主动放弃或已失效，后续尚未处理的进度通知不再作用于该任务实例。

统一结算顺序用于保证服务端、存档、日志与未来联机客户端得到一致结果，不能由不同任务自行调整生命周期状态的优先级。

## 6. 生命周期设计原则

任务生命周期遵循以下设计原则：

流程统一原则

所有任务均按照未触发、可领取、进行中和终止状态组成的统一流程运行，不为单个任务建立独立生命周期。

玩家选择原则

玩家可以自行决定是否领取任务，并可以在自己的回合主动放弃进行中的任务。系统不能自动覆盖玩家已有任务。

状态单向原则

任务状态只允许按照规定方向变化。已经完成、放弃、失效或结束的任务实例不能恢复为进行中状态。

长期配置原则

长期任务统一引用默认有效回合 `999999`，避免增加永久状态分支，也避免不同任务使用不一致的大数值。

唯一控制原则

唯一任务用于控制特殊内容的稀缺性，普通任务则通过可重复生成保证游戏过程中的持续体验。

职责分离原则

任务系统负责生命周期、目标与进度管理；战斗、地图、物品、经济和其他系统负责提供已经确认的业务结果。

可复现原则

任务状态变化、有效时间扣减与奖励领取必须采用稳定顺序，并保留必要记录，以支持存档恢复、日志追踪与未来联机同步。

易于扩展原则

后续新增任务类型时，应继续复用现有生命周期。新增类型主要扩展任务内容与目标方向，不应随意增加新的基础状态。

---

## 7. 小结

委托、悬赏、探索与隐藏任务构成当前版本的任务类型体系，并通过统一生命周期管理领取、进度、完成、奖励、放弃与失效过程。

统一的状态流转能够降低系统理解与实现成本，任务有效时间与唯一任务规则则用于控制目标节奏和特殊内容的稀缺性。

后续新增任务内容时，只需按照任务类型配置目标与奖励，并接入统一生命周期即可，无需为每项任务重新设计领取、结束或奖励流程。
