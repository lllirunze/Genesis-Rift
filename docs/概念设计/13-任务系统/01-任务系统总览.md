# 《开天辟地之大地的裂变》任务系统总览

## 1. 系统定位

任务（Quest）系统是《开天辟地之大地的裂变》中的支线目标系统，用于在一局游戏进行过程中为玩家提供阶段性的行动方向与成长机会。

玩家可以在探索地图、与 NPC 交互、进入特殊建筑、触发事件或完成特定行为时领取任务，并通过满足任务目标获得对应奖励，从而推动角色成长、丰富探索体验并增强游戏过程中的目标感。

本项目统一使用“任务”作为 Quest 的中文名称。“委托”用于描述由 NPC、组织或场景发布的一类任务表现形式，不单独建立另一套系统。

任务属于游戏过程中的成长内容，不属于玩家的个人胜利条件。任务可以为使命提供进度或创造完成条件，但完成任务本身不会直接使玩家获得游戏胜利。

任务系统的核心定位可以概括为：

**在长期使命之外，为玩家持续提供可以选择、完成或放弃的阶段性目标。**

---

## 2. 任务与使命的区别

任务（Quest）与使命（Mission）属于两个相互独立的目标系统。

| 对比项目 | 任务（Quest） | 使命（Mission） |
| --- | --- | --- |
| 主要定位 | 游戏过程中的支线目标与成长内容。 | 玩家在整局游戏中的隐藏胜利目标。 |
| 获取时间 | 在游戏过程中动态领取或触发。 | 完成角色创建后生成。 |
| 信息范围 | 根据任务内容决定公开或仅自己可见。 | 默认属于玩家个人隐藏信息。 |
| 是否可以放弃 | 可以在符合规则时主动放弃。 | 不能主动放弃，只能通过使命重塑进行调整。 |
| 主要收益 | 元宝、经验、物品、情报及其他成长奖励。 | 使命完成记录与个人胜利进度。 |
| 是否决定胜负 | 不直接决定游戏胜负。 | 完成规定数量后满足个人胜利条件。 |
| 持有方式 | 可以在游戏中反复获得，但受任务栏上限限制。 | 每局固定拥有规定数量。 |

任务更关注玩家**当前正在做什么**，使命更关注玩家**最终为什么而战**。

任务与使命不存在替代关系，而是共同组成游戏的目标体系。任务可以引导玩家接触地图、NPC、战斗与经济内容，使命则从更长时间尺度上决定玩家的发展方向与胜利路线。

任务推进使命时，两个系统仍应分别记录自身状态。完成某个任务只能向使命系统提交已经确认的任务结果，不能由任务系统直接将使命标记为完成。

使命组成、隐藏规则与胜利判定统一遵循《14-获胜条件/01-使命与胜利条件》。

## 3. 任务与事件的区别

事件（Event）负责为游戏提供随机反馈、临时变化与未知体验，任务（Quest）负责为玩家提供可以持续追踪的阶段性目标。

| 系统 | 主要职责 |
| --- | --- |
| 事件系统 | 判断事件何时触发、抽取何种事件，并组织揭露、选择与结算流程。 |
| 任务系统 | 管理任务的领取、目标进度、完成、奖励与放弃状态。 |

事件可以触发任务，例如玩家在遗迹事件中发现求救信，从而获得一个新的调查任务；任务也可以要求玩家触发、揭露或完成指定事件。

两者联动时仍保持职责分离：

```text
事件触发并完成揭露
        │
        ▼
事件效果声明“提供任务”
        │
        ▼
任务系统检查任务栏与领取条件
        │
        ▼
创建玩家任务实例
```

事件完成结算不代表关联任务自动完成，任务完成也不会由任务系统反向修改已经结束的事件结果。

---

## 4. 任务来源

任务可以通过多种方式获得，包括但不限于：

* NPC 发布任务。
* 特殊建筑、地点或场景提供任务。
* 已揭露事件触发任务。
* 击败特定敌人或首领后解锁后续任务。
* 完成前置任务后开启新的任务。
* 特殊剧情或世界状态提供任务。

不同来源的任务可以拥有不同目标、奖励与表现形式，但均遵循统一的任务领取、进度、完成和放弃规则。

任务来源只负责提供任务，不直接绕过任务系统写入玩家状态。例如，NPC 可以声明向玩家发布某项委托，但任务系统仍需检查玩家是否满足领取条件以及任务栏是否存在空位。

任务的具体分类、状态变化与生命周期将在《02-任务类型与生命周期》中说明。

---

## 5. 玩家任务限制

为了避免玩家同时维护过多目标而增加理解与操作负担，每位玩家同时最多持有 `4` 个未结束任务。

任务栏上限只计算当前仍由玩家持有的任务。已经完成、已经放弃或因其他合法原因结束的任务不再占用任务栏位置。

当玩家已经持有 `4` 个任务时，不能继续领取新的任务。玩家需要先完成或主动放弃至少一个已有任务，释放任务栏位置后才能领取新任务。

```text
尝试领取任务
      │
      ▼
检查当前持有任务数量
      │
  ┌───┴───┐
  │       │
少于 4   已达 4
  │       │
  ▼       ▼
正常领取  领取失败
```

任务栏已满时，系统不能自动放弃旧任务、覆盖已有任务或将新任务暂存在背包与临时拾取区。

当前任务栏上限属于任务系统统一规则。普通任务、NPC 委托与事件任务均共享该上限，不能通过更换任务来源规避限制。

---

## 6. 主动放弃任务

玩家可以在自己的回合内主动放弃任意一个尚未结束的任务。

主动放弃遵循以下规则：

* 只能在玩家自己的回合内进行。
* 每回合主动放弃任务的次数不限。
* 放弃任务不消耗行动次数。
* 放弃任务不会使玩家受到元宝、属性或状态惩罚。
* 放弃后，任务立即从当前任务列表中移除。
* 已经积累的任务进度不会保留。
* 已完成或已经结束的任务不能再次放弃。

```text
选择尚未结束的任务
        │
        ▼
确认主动放弃
        │
        ▼
清除任务进度与任务实例
        │
        ▼
释放一个任务栏位置
```

主动放弃机制用于帮助玩家及时清理不再需要、暂时无法完成或不符合当前发展方向的任务，保持任务栏的灵活性。

放弃任务本身不产生惩罚，但任务是否能够再次领取、任务来源是否仍然存在以及相关世界内容是否已经变化，由具体任务配置与当前游戏状态决定。系统不会因为玩家曾经放弃而自动恢复原有进度。

---

## 7. 奖励体系

玩家完成任务后，可以获得对应任务配置的奖励。

任务奖励包括但不限于：

* 元宝。
* 经验值。
* 手牌。
* 装备。
* 图纸。
* 材料。
* 药剂与消耗品。
* 基础属性点。
* 特殊道具。
* 地图情报。
* 特殊权限。
* 特殊剧情奖励。

不同品质、流程长度、完成难度与潜在风险的任务，应提供具有合理梯度的奖励。任务品质用于描述任务的稀有程度、复杂程度与整体价值，不代表所有高品质任务都必须提供相同种类的奖励。

任务奖励由任务系统确认完成后统一生成，再交由对应系统执行：

| 奖励内容 | 负责接收或结算的系统 |
| --- | --- |
| 元宝 | 经济系统与背包系统。 |
| 经验值、基础属性点 | 等级系统与角色数值系统。 |
| 手牌 | 手牌系统。 |
| 装备、材料、图纸、消耗品 | 背包与物品系统、装备系统。 |
| 地图情报 | 地图与探索系统。 |
| 特殊权限与剧情结果 | 对应场景、NPC 或剧情系统。 |

涉及物品的任务奖励仍需遵循背包空间与临时拾取规则。任务系统不能为了保证奖励发放而绕过背包容量，也不能直接修改其他系统的运行时状态。

基础属性点与其他永久成长奖励应保持稀有，并遵循数值系统的整数、边界与成长规则，避免任务奖励成为无限提升角色数值的稳定来源。

## 8. 与其他系统的关系

任务系统与多个游戏模块存在联动，但只负责任务自身的状态与目标管理。

| 相关系统 | 联动内容 |
| --- | --- |
| 地图系统 | 提供任务地点、探索目标、区域条件与地图情报。 |
| NPC 系统 | 发布、推进、提交任务，并提供任务对话与委托背景。 |
| 事件系统 | 触发新任务、推进任务条件或提供任务分支结果。 |
| 战斗系统 | 提供击败敌人、保护目标及战斗胜利等已确认结果。 |
| 角色与等级系统 | 提供等级、身份、种族、信仰等领取条件，并接收成长奖励。 |
| 背包与物品系统 | 提供收集、持有、提交物品的事实，并接收物品奖励。 |
| 装备系统 | 提供制造、获得或穿戴指定装备等任务进度。 |
| 经济系统 | 处理元宝奖励、任务费用及经济类目标。 |
| 手牌系统 | 接收任务奖励产生的手牌。 |
| 使命系统 | 接收已经确认的任务完成结果，用于推进符合条件的使命。 |

其他系统只向任务系统提交已经确认的业务结果，任务系统根据目标规则更新进度。任务系统不应自行模拟战斗、扣除物品、修改地图或发放其他模块资源。

## 9. 设计原则

任务系统遵循以下设计原则：

阶段目标原则

任务用于为玩家提供当前阶段可以追踪和完成的目标，不承担整局游戏的最终胜利判断。

自由选择原则

玩家可以根据自身路线选择是否领取、继续或放弃任务。任务不应强制所有玩家体验相同内容。

职责独立原则

任务、使命与事件可以相互联动，但必须分别维护自身状态与规则，不能通过名称相近而合并为同一系统。

数量受控原则

每位玩家同时最多持有 `4` 个任务，以控制信息量并保留任务选择与取舍。

奖励匹配原则

任务奖励应与任务品质、完成难度、流程长度和风险相匹配，不能通过低风险任务稳定获得过高收益。

结果驱动原则

任务进度只能来源于其他系统已经确认的业务结果，不能根据客户端表现、操作意图或尚未完成的过程提前增加。

配置优先原则

任务名称、目标、条件、奖励与来源应通过统一资源配置维护。新增任务原则上不需要修改任务系统底层流程。

易于扩展原则

新增地图、NPC、事件或玩法时，可以通过补充任务定义和目标类型进行适配，同时保持领取、进度、完成、奖励与放弃流程稳定。

---

## 10. 小结

任务系统是连接探索、NPC、事件与角色成长的重要支线目标系统。

玩家能够在完成长期使命的过程中不断领取新的任务，根据当前路线选择完成或放弃，并通过阶段性目标获得成长资源、地图信息与剧情体验。

通过明确区分 Quest、Mission 与 Event，限制同时持有任务数量，并统一任务来源、放弃规则与奖励职责，任务系统能够在不干扰胜利条件的前提下，为每局游戏持续提供值得探索和完成的内容。
