# 《开天辟地之大地的裂变》整数与边界规则

## 1. 文档目的

为了降低数值系统的理解成本与实现复杂度，本项目中的角色属性、伤害、消耗、移动距离和其他主要数值原则上均使用整数。

数值计算应尽量避免：

* 浮点数长期参与运算
* 平方根、对数等复杂计算
* 多次取整造成结果不一致
* 不同模块使用不同的取整方式
* 因浮点误差导致相同输入得到不同结果

本章节用于统一规定数值的整数表示、取整时机、上下限和异常值处理规则。

《05-属性计算与结算顺序》负责得到取整前的完整计算结果，本章节负责将该结果转换为合法、稳定且可用于玩法结算的最终整数值。

原剧中的装备、卡牌、天气、建筑与突发事件可以产生大量叠加效果，但无论规则多么繁复，同一组输入都必须得到唯一结果。整数与边界规则正是保证这种“复杂但可结算”设计成立的最后一道约束。

---

## 2. 整数化原则

游戏中对玩家可见并直接参与玩法的主要数值，原则上均以整数形式保存和展示。

包括但不限于：

* 五项基础属性
* 派生属性
* 当前生命值与最大生命值
* 当前灵力值与最大灵力值
* 攻击、防御、抗性与穿透
* 移动力、移动速度与视野
* 幸运值
* 伤害与治疗量
* 元宝与经验值
* 装备数值
* 持续回合数
* 卡牌和事件产生的数值效果

需要表示概率、倍率或比例时，也应优先使用带有固定分母的整数，而不是直接保存浮点数。

例如，采用百分制时：

```text
暴击率：15
表示：15%
```

采用万分制时：

```text
暴击率：1500
表示：15.00%
```

项目应为同一类数值统一比例单位。百分制与万分制不能在未进行显式转换的情况下混合计算。

---

## 3. 简单运算原则

数值公式应优先使用：

* 加法
* 减法
* 整数乘法
* 整数除法
* 比较
* 最小值与最大值限制

原则上避免使用：

* 平方根与开方
* 对数
* 三角函数
* 无理数
* 多层幂运算
* 需要长小数才能表达的系数

例如，不建议使用：

```text
移动速度 = √敏捷 × 3
```

建议使用：

```text
移动速度
= 敏捷 × 敏捷系数
+ 固定偏移量
```

移动速度只受到敏捷影响，与《03-派生属性》中确定的依赖关系保持一致。

如果希望属性成长逐渐变慢，可以通过以下方式实现：

* 分段公式
* 整数除法
* 等级区间
* 上限限制
* 较小整数系数

如果必须使用小数比例，应将其改写为“整数分子 ÷ 固定整数分母”的形式，并在完整计算结束后统一取整。

---

## 4. 统一取整规则

### 4.1 取整时机

数值应当在一轮完整公式计算完成后统一取整，不应在中间步骤反复取整。

例如，派生属性计算应先完成：

```text
五项基础属性贡献值求和
+ 派生属性静态偏移
+ 派生属性动态偏移
```

然后再对完整结果执行取整和边界限制。

不推荐以下流程：

```text
每项基础属性贡献值分别取整
↓
中间结果再次取整
↓
加入偏移量后再次取整
```

多次取整会持续损失小数部分，也容易使不同模块对同一公式得出不同结果。

统一顺序为：

```text
完成完整计算
↓
执行一次取整
↓
执行最小值限制
↓
执行最大值限制
↓
得到最终结果
```

### 4.2 默认向下取整

游戏中的一般数值计算默认采用向下取整。

表示为：

```text
最终整数值 = floor（计算结果）
```

例如：

| 计算结果 | 最终结果 |
| --- | --- |
| `12.8` | `12` |
| `7.2` | `7` |

默认向下取整适用于：

* 派生属性
* 普通伤害与普通治疗
* 属性比例加成
* 经验奖励
* 掉落数量与资源收益
* 概率修正
* 持续恢复量

采用向下取整可以避免较小的零散加成过早形成完整单位，也便于控制整体数值膨胀。

### 4.3 特殊向上取整

只有在玩法规则明确要求“任何不足一个完整单位的部分也必须占用一个单位”时，才使用向上取整。

表示为：

```text
最终整数值 = ceil（计算结果）
```

例如：

```text
计算结果：3.1
最终结果：4
```

适合向上取整的场景包括：

| 场景 | 说明 |
| --- | --- |
| 移动消耗 | 只要跨越需要额外消耗的地形，就必须支付完整移动力 |
| 制造材料消耗 | 任何不足一份的材料需求都按一份计算 |
| 商店支付价格 | 存在比例加价或折扣时，应付金额不能通过舍弃小数减少 |
| 距离分段 | 距离只要超过当前区间，就进入下一个完整区间 |
| 人数或目标数量 | 不能出现不足一个角色或目标的结果 |
| 容量占用 | 物品只要产生容量消耗，就至少占用一个单位 |

向上取整必须由配置或玩法规则明确声明，不能由程序根据数值大小自行判断。

### 4.4 负数与除法

对于可能产生负数的计算，不应依赖编程语言的默认整数转换行为。

例如：

```text
floor（-2.7）= -3
```

直接截断小数部分则可能得到 `-2`，两者含义不同。因此，项目必须显式调用统一取整方法。

如果某项属性不允许为负数，应先取整，再执行最小值限制：

```text
计算结果：-2.7
向下取整：-3
最小值限制：0
最终结果：0
```

当公式中存在除法时，取整方向由结果的用途决定：

| 数值用途 | 默认取整方向 |
| --- | --- |
| 普通收益或能力 | 向下取整 |
| 必须支付或完整占用的成本 | 向上取整 |

例如：

```text
奖励 = 15 ÷ 2 = 7.5
最终奖励 = 7

材料消耗 = 15 ÷ 2 = 7.5
最终消耗 = 8
```

## 5. 比例与概率处理

### 5.1 比例计算

为避免浮点误差，比例计算应使用整数倍率。

例如，伤害提高 `15%` 时，不建议直接使用：

```text
伤害 × 1.15
```

采用百分制时可以写为：

```text
伤害 × 115 ÷ 100
```

采用万分制时可以写为：

```text
伤害 × 11500 ÷ 10000
```

乘法应先于除法执行，以减少整数运算造成的精度损失。

例如：

```text
基础伤害 = 37
伤害倍率 = 115%

37 × 115 ÷ 100 = 42.55
向下取整后：42
```

比例分母必须由对应数值类型统一定义，不能让不同模块自行选择。

### 5.2 概率表示与边界

概率相关数值必须限制在合法区间内。

| 表示方式 | 最小值 | 最大值 |
| --- | --- | --- |
| 百分制 | `0` | `100` |
| 万分制 | `0` | `10000` |

即使幸运值、Buff 或其他修饰器使概率超出范围，也必须在随机系统使用前执行边界限制。

例如：

```text
计算暴击率：115%
暴击率配置上限：80%
随机系统实际读取：80%
```

属性面板可以根据设计显示限制后的数值，也可以额外展示溢出部分，但实际结算只能使用合法区间内的结果。

## 6. 属性上下限

### 6.1 最小值规则

不同属性可以配置不同的最小值。

常见建议如下：

| 数值类型 | 建议最小值 |
| --- | --- |
| 最大生命值 | `1` |
| 最大灵力值 | `0` |
| 当前生命值 | `0` |
| 当前灵力值 | `0` |
| 基础属性 | `0` 或 `1`，由后续设计决定 |
| 物理攻击与法术攻击 | `0` |
| 物理防御与法术抗性 | `0` |
| 穿透 | `0` |
| 移动力与移动速度 | `0` |
| 视野 | `0` 或 `1`，由地图系统决定 |
| 幸运值 | `0` |
| 元宝与经验值 | `0` |

如果某项属性允许负数，例如临时行动优先级修正，应在该属性配置中明确说明。

不允许为负数的属性在最终计算后统一限制为：

```text
最终值 = max（取整后的结果，最小值）
```

### 6.2 最大值规则

部分属性需要设置最大值，避免数值无限增长或破坏玩法。

可能需要上限的属性包括：

* 暴击率
* 闪避率
* 减伤比例
* 控制抗性
* 移动力
* 视野
* 幸运值
* 穿透
* 单次属性增减
* 装备词条层数

例如，暴击率最大值为 `80%` 时，即使计算结果为 `95%`，最终结果仍限制为 `80%`。

统一表示为：

```text
最终值 = min（取整后的结果，最大值）
```

同时存在最小值和最大值时：

```text
最终值
= min（
    max（取整后的结果，最小值），
    最大值
）
```

具体上下限不在本章节统一确定，由各属性配置分别定义。

---

## 7. 当前值与最大值边界

当前生命值、当前灵力值等资源必须受对应最大值限制。

例如，最大生命值从 `100` 降低到 `80` 时，如果当前生命值为 `95`，则应同步修正为：

```text
当前生命值 = 80
```

统一规则为：

```text
当前值
= min（
    max（当前值，0），
    最大值
）
```

最大值发生变化时，原则上不按照比例自动恢复或扣除当前值，只在当前值超出新上限时进行截断。

例如：

| 变化 | 当前值处理 |
| --- | --- |
| 最大生命值从 `100` 提高到 `120` | 当前生命值保持不变，不自动恢复 `20` 点 |
| 最大生命值从 `100` 降低到 `80`，当前生命值为 `95` | 当前生命值截断为 `80` |
| 最大生命值从 `100` 降低到 `80`，当前生命值为 `60` | 当前生命值保持 `60` |

特殊技能或状态需要按比例调整当前值时，应由对应玩法系统单独处理，不纳入通用边界规则。

---

## 8. 最小有效值

部分行为在完整计算后可能得到大于 `0` 但小于 `1` 的结果。

例如：

```text
治疗量计算结果：0.6
默认向下取整：0
```

默认情况下，这表示该行为没有产生有效治疗。

如果某项玩法要求行为成功后至少产生一点效果，可以为该行为配置最小有效值：

```text
成功后最小治疗量：1
```

适用场景包括：

* 未被闪避的合法攻击至少造成 `1` 点伤害
* 成功释放的治疗至少恢复 `1` 点生命
* 成功采集至少获得 `1` 份资源
* 成功制造至少产生 `1` 件物品
* 成功触发的恢复效果至少恢复 `1` 点

最小有效值只在行为已经被对应玩法系统判定为成功时生效。

是否保留至少一点效果，应由战斗、制造、采集等玩法系统分别声明，不应对所有数值全局强制使用。

## 9. 玩法数值规则

### 9.1 伤害与治疗

伤害和治疗原则上均在完整结算结束后取整。

普通伤害建议流程为：

```text
完成伤害公式
↓
按照规则取整
↓
应用最小伤害规则
↓
扣除当前生命值
```

普通治疗建议流程为：

```text
完成治疗公式
↓
按照规则取整
↓
应用最小治疗规则
↓
限制当前生命值不超过最大生命值
```

持续伤害或持续治疗应对每次实际结算分别取整，而不是先计算总量后平均分配。

例如，三回合总伤害为 `10` 时，不建议在运行时使用每回合 `3.333...` 点伤害。可以直接配置为 `3、3、4`，或者明确配置为每回合 `3` 点、总计 `9` 点。

### 9.2 持续回合数

持续时间必须使用整数回合，不允许出现“持续 `2.5` 回合”。

如果比例公式产生小数回合数，应由效果配置明确取整方向：

* 增益持续时间通常向下取整
* 冷却或必须完整承担的持续时间可以向上取整
* 固定设计内容应优先直接配置整数

效果在持续回合计数归零后立即移除，不保留隐藏的小数剩余时间。

### 9.3 移动相关数值

移动力、移动速度和地形消耗均使用整数。

单个格子的移动消耗至少为 `1`，除非特殊效果明确允许免费移动。

如果地形消耗经过比例修正后产生小数，原则上向上取整。

例如：

```text
基础地形消耗：3
减耗效果：25%

3 × 75 ÷ 100 = 2.25
向上取整后：3
```

如果希望该减耗效果在较小的基础消耗上实际生效，可以使用更大的比例、固定减耗或调整地形基础消耗。

### 9.4 经济数值

元宝、商店价格、制造费用和交易金额均使用整数。

价格计算的一般原则为：

* 玩家获得的出售收益向下取整
* 玩家需要支付的购买价格向上取整

例如，某商品基础价格为 `15`，折扣为 `10%`：

```text
15 × 90 ÷ 100 = 13.5

购买价格：向上取整为 14
出售收益：向下取整为 13
```

该规则可以避免经济系统因不同方向的取整产生可重复利用的循环套利。

## 10. 配置与异常处理

### 10.1 配置校验

数值配置加载时应至少检查：

* 配置字段是否缺失
* 数值内容是否为合法数字
* 比例分母是否为 `0`
* 最小值是否大于最大值
* 取整模式是否为受支持的类型
* 当前值是否超过对应最大值
* 配置数值是否超出合理游戏范围

配置非法时应：

1. 按照《15-日志系统》记录包含配置位置和字段名称的 `ERROR` 日志
2. 使用明确的安全默认值
3. 阻止非法结果写入角色数据
4. 避免单项配置错误导致整个游戏流程中断

### 10.2 计算安全

程序应使用足够大的整数类型完成中间计算，并在加法、乘法和除法发生时检查溢出与非法操作。

推荐至少使用 64 位整数保存中间结果，再根据属性配置限制到合法范围。

溢出检查不能只放在完整公式结束后。若中间乘法已经溢出，后续边界限制无法恢复正确结果。

对于除数为 `0`、超出整数类型范围或其他无法得到合法结果的情况，应立即停止当前数值结算，记录错误并返回对应规则定义的安全值。

---

## 11. 推荐处理顺序

所有需要整数化和边界处理的数值，建议采用以下顺序：

```text
校验配置与输入
↓
使用安全整数类型完成全部加减乘除
↓
在计算过程中检查除零、溢出与非法值
↓
按照配置执行一次取整
↓
行为成功时应用最小有效值
↓
应用属性最小值
↓
应用属性最大值
↓
检查当前值与最大值关系
↓
得到最终整数值
```

一般派生属性默认使用：

```text
完成统一公式
↓
向下取整
↓
最小值限制
↓
最大值限制
```

只有配置或玩法规则明确指定时，才使用向上取整或最小有效值。

## 12. 推荐配置结构

不同属性和玩法数值可以使用统一结构声明取整与边界规则：

```json
{
  "maxHealth": {
    "roundingMode": "FLOOR",
    "minimum": 1,
    "maximum": null,
    "minimumEffectiveValue": null
  },
  "movementCost": {
    "roundingMode": "CEIL",
    "minimum": 1,
    "maximum": null,
    "minimumEffectiveValue": null
  },
  "physicalDamage": {
    "roundingMode": "FLOOR",
    "minimum": 0,
    "maximum": null,
    "minimumEffectiveValue": 1
  },
  "criticalChance": {
    "roundingMode": "FLOOR",
    "minimum": 0,
    "maximum": 100,
    "minimumEffectiveValue": null
  }
}
```

其中：

| 字段 | 说明 |
| --- | --- |
| `roundingMode` | 取整方式，当前主要支持 `FLOOR` 与 `CEIL` |
| `minimum` | 数值允许的最小值 |
| `maximum` | 数值允许的最大值，没有上限时为 `null` |
| `minimumEffectiveValue` | 行为成功时允许产生的最小有效结果，不适用时为 `null` |

对于纯属性数值，`minimumEffectiveValue` 通常为 `null`；该字段主要供伤害、治疗和资源产出等玩法结果使用。

不应让取整方式和边界值分散在各业务代码中临时决定。

---

## 13. 职责边界

数值系统负责提供统一取整能力、边界约束和安全检查，但不同玩法数值采用何种规则，应由对应系统明确声明。

| 内容 | 负责系统 |
| --- | --- |
| 派生属性的默认取整与上下限 | 数值系统 |
| 伤害与治疗的最小有效值 | 战斗系统 |
| 地形移动消耗的取整方式 | 地图与移动系统 |
| 购买价格与出售收益的取整方向 | 经济系统 |
| 持续回合数与移除时机 | 状态系统 |
| 概率单位与随机判定 | 随机系统 |
| 通用 `floor`、`ceil` 与边界方法 | 底层数值模块 |

各系统可以声明不同规则，但必须调用同一套底层方法，不能自行实现含义不同的取整逻辑。

## 14. 设计原则

整数与边界规则遵循以下原则：

### 14.1 整数优先原则

玩家可见并参与玩法的主要数值均使用整数。

### 14.2 简单运算原则

优先使用加减乘除，避免平方根、对数和其他复杂数学计算。

### 14.3 单次取整原则

一轮完整公式只在最终阶段统一取整，避免中间步骤反复损失数值。

### 14.4 默认向下原则

普通属性、收益、伤害和治疗默认向下取整。

### 14.5 成本向上原则

必须支付或完整占用的成本、材料、价格和容量可以向上取整。

### 14.6 显式配置原则

所有特殊取整方式必须由配置或玩法规则明确指定，不能隐式推测。

### 14.7 边界限制原则

取整后统一执行最小值、最大值和资源上限限制。

### 14.8 概率整数化原则

概率使用百分比或万分比整数表示，避免直接保存浮点数。

### 14.9 职责分离原则

数值系统提供统一处理能力，战斗、经济、移动等系统负责声明自身采用的具体规则。

### 14.10 结果一致原则

所有运行端、测试工具和数据校验工具必须使用相同的取整定义，保证相同输入始终产生相同结果。
