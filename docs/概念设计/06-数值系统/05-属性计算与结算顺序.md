# 《开天辟地之大地的裂变》属性计算与结算顺序

## 1. 文档目的

属性计算与结算顺序用于规定角色基础属性、属性系数、静态偏移量和动态偏移量之间的统一计算关系。

本系统不为最大生命值、物理攻击、移动力、幸运值等不同派生属性分别编写计算逻辑，而是采用同一套通用公式进行计算。

每项派生属性均完整读取五项基础属性：

* 力量
* 体质
* 灵力
* 敏捷
* 悟性

当某项基础属性不影响当前派生属性时，只需将对应系数设置为 `0`，无需删除字段，也无需增加特殊判断。

例如，护甲穿透不受任何基础属性影响时，其五项系数全部为 `0`；系统依然使用相同公式完成计算。

本设计的主要目标是：

* 统一所有派生属性的计算入口
* 减少特殊分支
* 降低代码维护成本
* 保证配置结构一致
* 方便后续增加新的派生属性
* 保证相同输入得到相同结果

---

## 2. 参与计算的数据

派生属性计算由角色数据、派生属性配置和运行时数据共同完成。

### 2.1 角色数据

角色实例提供：

```text
currentPrimaryAttributes
```

即角色当前永久基础属性。

该数据已经包含：

* 五项基础属性的初始值
* 种族初始调整
* 职业初始调整
* 升级加点
* 转职永久成长
* 任务永久奖励
* 其他永久属性变化

### 2.2 派生属性配置

每项派生属性配置提供：

* `coefficients`
* `primaryStaticOffset`
* `derivedStaticOffset`

其中：

| 配置项 | 作用 |
| --- | --- |
| `coefficients` | 定义五项基础属性对当前派生属性的换算系数 |
| `primaryStaticOffset` | 仅在计算当前派生属性时，对基础属性输入进行固定修正 |
| `derivedStaticOffset` | 在基础属性换算完成后，直接增加或减少派生属性结果 |

### 2.3 运行时数据

游戏运行过程中提供：

* `primaryDynamicOffset`
* `derivedDynamicOffset`

其中：

| 数据项 | 作用 |
| --- | --- |
| `primaryDynamicOffset` | 装备、Buff、Debuff 等对基础属性产生的运行时修正 |
| `derivedDynamicOffset` | 装备、状态、地形等直接对派生属性产生的运行时修正 |

---

## 3. 五项基础属性统一结构

所有派生属性都必须拥有完整的五项基础属性系数。

统一结构如下：

```json
{
  "strength": 0,
  "constitution": 0,
  "spirit": 0,
  "agility": 0,
  "insight": 0
}
```

即使某项派生属性只受到一项或两项基础属性影响，其余字段也不能省略，而应明确配置为 `0`。

例如，最大生命值只受到体质影响：

```json
{
  "strength": 0,
  "constitution": 8,
  "spirit": 0,
  "agility": 0,
  "insight": 0
}
```

法术攻击受到灵力和悟性影响：

```json
{
  "strength": 0,
  "constitution": 0,
  "spirit": 7,
  "agility": 0,
  "insight": 3
}
```

护甲穿透不受任何基础属性影响：

```json
{
  "strength": 0,
  "constitution": 0,
  "spirit": 0,
  "agility": 0,
  "insight": 0
}
```

系统无需判断当前派生属性受到几项基础属性影响，只需要依次完成五项乘法并求和。

## 4. 最终基础属性输入

在计算派生属性之前，需要先确定参与当前计算的最终基础属性。

对于任意一项基础属性，其计算方式为：

```text
最终基础属性
= 当前基础属性
+ 基础属性静态偏移量
+ 基础属性动态偏移量
```

分别展开为：

```text
最终力量 = 当前力量 + 力量静态偏移量 + 力量动态偏移量
最终体质 = 当前体质 + 体质静态偏移量 + 体质动态偏移量
最终灵力 = 当前灵力 + 灵力静态偏移量 + 灵力动态偏移量
最终敏捷 = 当前敏捷 + 敏捷静态偏移量 + 敏捷动态偏移量
最终悟性 = 当前悟性 + 悟性静态偏移量 + 悟性动态偏移量
```

这里的 `primaryStaticOffset` 来自当前派生属性的配置，因此不同派生属性在计算时可以使用不同的基础属性静态修正。

而 `primaryDynamicOffset` 来自角色当前有效的装备、状态、天气、地图和其他运行时效果。

这里得到的“最终基础属性”只是当前派生属性本次计算所使用的临时输入，不会覆盖角色保存的 `currentPrimaryAttributes`，也不代表角色面板必须显示该数值。

---

## 5. 派生属性统一计算公式

任意派生属性均采用以下统一公式：

```text
最终派生属性
= Σ[
    （当前基础属性
    + 基础属性静态偏移量
    + 基础属性动态偏移量）
    × 对应系数
]
+ 派生属性静态偏移量
+ 派生属性动态偏移量
```

展开到五项基础属性后：

```text
最终派生属性
=（当前力量 + 力量静态偏移 + 力量动态偏移）× 力量系数
+（当前体质 + 体质静态偏移 + 体质动态偏移）× 体质系数
+（当前灵力 + 灵力静态偏移 + 灵力动态偏移）× 灵力系数
+（当前敏捷 + 敏捷静态偏移 + 敏捷动态偏移）× 敏捷系数
+（当前悟性 + 悟性静态偏移 + 悟性动态偏移）× 悟性系数
+ 派生属性静态偏移
+ 派生属性动态偏移
```

公式中不参与当前派生属性计算的基础属性，其对应系数配置为 `0`。

因此：

```text
任意数值 × 0 = 0
```

该项自然不会影响最终结果，无需编写条件判断。

---

## 6. 统一公式的设计意义

采用完整五项基础属性参与的统一公式，可以避免代码中出现大量不同分支。

不推荐以下实现方式：

```text
如果属性是最大生命值：
    读取体质
如果属性是法术攻击：
    读取灵力和悟性
如果属性是护甲穿透：
    不读取基础属性
如果属性是移动速度：
    读取敏捷
```

这种方式会导致：

* 每增加一种派生属性都需要修改代码
* 属性关系分散在不同逻辑中
* 难以统一排查计算错误
* 配置文件无法成为唯一规则来源
* 后续平衡调整容易遗漏

推荐方式为：

```text
读取完整五项基础属性
↓
读取完整五项静态偏移
↓
读取完整五项动态偏移
↓
读取完整五项系数
↓
逐项相加、相乘并求和
↓
增加派生属性静态偏移
↓
增加派生属性动态偏移
```

这样，无论新增何种派生属性，底层代码都不需要改变。

原剧中的职业、装备、卡牌、建筑、天气和突发事件可以继续制造大量看似夸张的数值变化，但所有变化最终都会进入同一条计算链。这样既保留《开天辟地之大地的裂变》“规则庞大而效果繁多”的气质，也确保每一次结算都有明确来源和唯一结果。

## 7. 属性计算结算顺序

完整的属性计算顺序如下。

### 7.1 第一步：读取角色当前基础属性

系统读取：

```text
currentPrimaryAttributes
```

该值已经是角色永久成长后的结果，不再重新计算种族、职业和升级历史。

### 7.2 第二步：读取派生属性配置

系统根据派生属性标识读取：

* `coefficients`
* `primaryStaticOffset`
* `derivedStaticOffset`

例如，计算最大生命值时，读取 `maxHealth` 对应配置。

### 7.3 第三步：汇总基础属性动态偏移量

系统从当前所有有效修饰器中，汇总：

```text
primaryDynamicOffset
```

可能的来源包括：

* 装备
* Buff
* Debuff
* 天气
* 地图
* 建筑
* 光环
* 卡牌
* 临时事件

此阶段只汇总当前仍然有效的修饰器。

### 7.4 第四步：计算最终基础属性输入

针对五项基础属性，分别执行：

```text
最终基础属性
= 当前基础属性
+ primaryStaticOffset
+ primaryDynamicOffset
```

计算得到的结果仅作为当前派生属性的输入，不一定直接显示在角色面板中。

### 7.5 第五步：基础属性乘以对应系数

五项最终基础属性分别乘以当前派生属性对应的系数：

```text
力量贡献值 = 最终力量 × 力量系数
体质贡献值 = 最终体质 × 体质系数
灵力贡献值 = 最终灵力 × 灵力系数
敏捷贡献值 = 最终敏捷 × 敏捷系数
悟性贡献值 = 最终悟性 × 悟性系数
```

系数为 `0` 时，该基础属性贡献值自然为 `0`。

### 7.6 第六步：基础属性贡献值求和

将五项贡献值相加：

```text
基础换算结果
= 力量贡献值
+ 体质贡献值
+ 灵力贡献值
+ 敏捷贡献值
+ 悟性贡献值
```

### 7.7 第七步：增加派生属性静态偏移量

在基础换算结果上增加：

```text
derivedStaticOffset
```

得到派生属性的固定计算结果。

### 7.8 第八步：汇总派生属性动态偏移量

系统从所有有效运行时修饰器中，汇总当前派生属性对应的：

```text
derivedDynamicOffset
```

例如：

* 武器提供物理攻击
* 装备提供护甲穿透
* 高地提供视野
* Buff 提供移动速度
* 黑夜降低视野
* 道具提高幸运值

### 7.9 第九步：得到最终派生属性

最终执行：

```text
最终派生属性
= 基础换算结果
+ derivedStaticOffset
+ derivedDynamicOffset
```

### 7.10 第十步：执行取整与边界处理

在全部计算完成后，统一进行：

* 取整
* 最小值限制
* 最大值限制
* 空值处理
* 异常值处理

这些规则将在《06-整数与边界规则》中详细说明。

---

## 8. 完整流程

```text
读取角色当前基础属性
↓
读取当前派生属性配置
↓
汇总基础属性动态偏移量
↓
当前基础属性
+ primaryStaticOffset
+ primaryDynamicOffset
↓
得到五项最终基础属性输入
↓
分别乘以五项 coefficients
↓
五项贡献值求和
↓
+ derivedStaticOffset
↓
汇总并加入 derivedDynamicOffset
↓
执行取整
↓
执行上下限约束
↓
得到最终派生属性
```

## 9. 最大生命值计算示例

假设某角色当前基础属性为：

```json
{
  "strength": 7,
  "constitution": 8,
  "spirit": 4,
  "agility": 5,
  "insight": 6
}
```

最大生命值配置为：

```json
{
  "coefficients": {
    "strength": 0,
    "constitution": 8,
    "spirit": 0,
    "agility": 0,
    "insight": 0
  },
  "primaryStaticOffset": {
    "strength": 0,
    "constitution": 1,
    "spirit": 0,
    "agility": 0,
    "insight": 0
  },
  "derivedStaticOffset": 50
}
```

角色当前受到以下动态效果：

```text
装备：力量 +1
虚弱状态：体质 -2
护符：最大生命值 +10
```

汇总得到：

```json
{
  "primaryDynamicOffset": {
    "strength": 1,
    "constitution": -2,
    "spirit": 0,
    "agility": 0,
    "insight": 0
  },
  "derivedDynamicOffset": {
    "maxHealth": 10
  }
}
```

首先计算五项最终基础属性输入：

```text
最终力量 = 7 + 0 + 1 = 8
最终体质 = 8 + 1 - 2 = 7
最终灵力 = 4 + 0 + 0 = 4
最终敏捷 = 5 + 0 + 0 = 5
最终悟性 = 6 + 0 + 0 = 6
```

然后计算五项贡献值：

```text
力量贡献值 = 8 × 0 = 0
体质贡献值 = 7 × 8 = 56
灵力贡献值 = 4 × 0 = 0
敏捷贡献值 = 5 × 0 = 0
悟性贡献值 = 6 × 0 = 0
```

基础换算结果：

```text
0 + 56 + 0 + 0 + 0 = 56
```

加入派生属性静态偏移：

```text
56 + 50 = 106
```

加入派生属性动态偏移：

```text
106 + 10 = 116
```

因此：

```text
最终最大生命值 = 116
```

装备提供的力量 `+1` 已经进入最终力量，但由于最大生命值的力量系数为 `0`，因此不会影响本次计算结果。

## 10. 护甲穿透计算示例

护甲穿透不受任何基础属性影响，其配置可以为：

```json
{
  "coefficients": {
    "strength": 0,
    "constitution": 0,
    "spirit": 0,
    "agility": 0,
    "insight": 0
  },
  "primaryStaticOffset": {
    "strength": 0,
    "constitution": 0,
    "spirit": 0,
    "agility": 0,
    "insight": 0
  },
  "derivedStaticOffset": 0
}
```

假设角色拥有：

```text
破甲长枪：护甲穿透 +3
装备词条：护甲穿透 +2
临时 Buff：护甲穿透 +1
```

其 `derivedDynamicOffset` 汇总结果为：

```text
3 + 2 + 1 = 6
```

系统仍然按照完整公式计算：

```text
最终护甲穿透
= 力量 × 0
+ 体质 × 0
+ 灵力 × 0
+ 敏捷 × 0
+ 悟性 × 0
+ 0
+ 6
```

因此：

```text
最终护甲穿透 = 6
```

该属性不需要任何独立的特殊代码。

## 11. 幸运值计算示例

幸运值同样可以不受基础属性影响，但可以拥有作者配置的初始值。

例如：

```json
{
  "coefficients": {
    "strength": 0,
    "constitution": 0,
    "spirit": 0,
    "agility": 0,
    "insight": 0
  },
  "primaryStaticOffset": {
    "strength": 0,
    "constitution": 0,
    "spirit": 0,
    "agility": 0,
    "insight": 0
  },
  "derivedStaticOffset": 5
}
```

假设角色因装备和事件获得：

```text
幸运护符：幸运值 +2
事件状态：幸运值 -1
```

则：

```text
derivedDynamicOffset = 2 - 1 = 1
```

最终结果为：

```text
最终幸运值
= 五项基础属性贡献值 0
+ 静态偏移 5
+ 动态偏移 1
= 6
```

幸运值虽然不受基础属性影响，但仍然与其他派生属性共用相同计算流程。

## 12. 移动速度与移动顺序

移动速度只受到敏捷影响，并按照统一公式完成计算。

计算完成后，由移动系统或回合系统读取其最终值，用于决定同一回合内角色的移动先后顺序。

属性系统只负责给出：

```text
最终移动速度
```

至于多个角色之间如何排序，由回合系统负责。

推荐基本排序方式为：

**移动速度较高者优先移动。**

当移动速度相同时，可以继续比较：

* 先手值
* 当前回合优先权
* 固定座次
* 随机值

这些属于回合系统的结算规则，不属于属性计算公式。

因此，属性系统与回合系统的职责应保持分离：

| 系统 | 职责 |
| --- | --- |
| 属性系统 | 计算移动速度数值 |
| 回合系统 | 根据移动速度安排顺序 |

## 13. 重新计算触发时机

派生属性不需要在每一帧持续计算，而应在相关数据发生变化时重新计算。

典型触发条件包括：

* 当前基础属性发生变化
* 角色升级加点
* 角色转职
* 装备穿戴或卸下
* Buff 或 Debuff 添加、刷新、到期
* 进入或离开特殊地形
* 天气发生变化
* 建筑或光环范围发生变化
* 派生属性配置重新加载
* 特殊事件修改属性
* 角色形态发生改变

如果某次变化只影响单项派生属性，可以只重新计算相关属性。

例如：

```text
高地提供视野 +1
```

只需要重新计算视野，不需要重新计算最大生命值、攻击力和移动力。

如果变化影响基础属性，则需要重新计算所有依赖该基础属性的派生属性。

例如：

```text
力量 +1
```

需要重新计算所有力量系数不为 `0` 的派生属性。

---

## 14. 依赖关系索引

为了减少不必要的重复计算，可以根据系数配置建立基础属性与派生属性之间的依赖关系。

例如：

```text
力量
├── 物理攻击
├── 物理防御
├── 暴击伤害
├── 负重
└── 采集效率

敏捷
├── 物理攻击
├── 闪避
├── 暴击率
├── 移动力
└── 移动速度
```

当力量发生变化时，只重新计算力量系数不为 `0` 的派生属性。

系数为 `0` 的属性不需要加入对应依赖列表。例如，最大生命值只依赖体质，因此不应出现在力量依赖列表中。

依赖关系索引应根据派生属性配置自动生成，避免手工维护的索引与实际系数产生偏差。

该索引属于性能优化措施，不改变统一公式本身。

---

## 15. 配置缺失处理

为了保证系统稳定，所有派生属性配置都应包含完整字段。

如果某字段缺失，系统可以按照以下默认规则补全：

| 缺失内容 | 默认值 |
| --- | --- |
| 基础属性系数 | `0` |
| 基础属性静态偏移 | `0` |
| 派生属性静态偏移 | `0` |
| 动态偏移 | `0` |

例如，配置只写了：

```json
{
  "coefficients": {
    "constitution": 8
  }
}
```

系统加载后应标准化为：

```json
{
  "coefficients": {
    "strength": 0,
    "constitution": 8,
    "spirit": 0,
    "agility": 0,
    "insight": 0
  },
  "primaryStaticOffset": {
    "strength": 0,
    "constitution": 0,
    "spirit": 0,
    "agility": 0,
    "insight": 0
  },
  "derivedStaticOffset": 0
}
```

不过，为了提升配置可读性和便于排查问题，正式配置文件仍建议显式填写完整的五项字段。

默认值只用于提供安全兜底，不应代替配置校验。加载配置时仍应记录缺失字段，以便作者及时发现不完整配置。

## 16. 计算职责边界

属性系统只负责计算最终属性数值，不负责具体玩法结算。

例如：

| 内容 | 负责系统 |
| --- | --- |
| 计算最终物理攻击 | 属性系统 |
| 根据攻击与防御计算伤害 | 战斗系统 |
| 计算最终移动力 | 属性系统 |
| 根据地形扣除移动力 | 地图与移动系统 |
| 计算最终移动速度 | 属性系统 |
| 决定本回合移动顺序 | 回合系统 |
| 计算最终幸运值 | 属性系统 |
| 使用幸运值修正随机结果 | 随机系统 |
| 计算最终视野 | 属性系统 |
| 判断哪些格子可见 | 视野系统 |
| 计算制造能力 | 属性系统 |
| 判断制造是否成功 | 制造系统 |

这样可以避免属性系统承担过多业务逻辑。

## 17. 推荐伪代码

```text
function calculateDerivedAttribute(
    currentPrimaryAttributes,
    attributeConfig,
    primaryDynamicOffset,
    derivedDynamicOffset
):
    result = 0

    for each primaryAttribute in allPrimaryAttributes:
        currentValue =
            currentPrimaryAttributes[primaryAttribute]
            default 0

        staticOffset =
            attributeConfig.primaryStaticOffset[primaryAttribute]
            default 0

        dynamicOffset =
            primaryDynamicOffset[primaryAttribute]
            default 0

        coefficient =
            attributeConfig.coefficients[primaryAttribute]
            default 0

        finalPrimaryValue =
            currentValue
            + staticOffset
            + dynamicOffset

        result += finalPrimaryValue * coefficient

    result += attributeConfig.derivedStaticOffset default 0
    result += derivedDynamicOffset default 0
    result = applyIntegerRule(result)
    result = applyBoundaryRule(result)

    return result
```

该方法适用于所有派生属性，不需要根据属性名称编写不同计算分支。

## 18. 设计原则

属性计算与结算顺序遵循以下原则：

### 18.1 统一公式原则

所有派生属性均使用同一套完整五维计算公式。

### 18.2 零系数原则

某项基础属性不参与当前派生属性计算时，将其系数设置为 `0`，不增加特殊判断。

### 18.3 完整结构原则

所有系数与基础属性偏移量均使用完整五项结构，避免不同配置拥有不同字段。

### 18.4 先基础后派生原则

先完成基础属性静态和动态偏移，再乘系数，最后增加派生属性偏移。

### 18.5 静态先于动态原则

派生属性换算完成后，先加入固定静态偏移，再加入当前运行时动态偏移。

### 18.6 最终处理原则

取整、上下限和异常值处理统一放在全部计算结束后执行。

### 18.7 配置驱动原则

基础属性与派生属性之间的关系由配置决定，代码只负责执行公式。

### 18.8 职责分离原则

属性系统只计算数值，不负责伤害、移动、随机、视野和制造等具体业务判定。

### 18.9 按需重算原则

属性仅在依赖数据发生变化时重新计算，不需要无意义地持续刷新。

### 18.10 可维护原则

新增派生属性时，只需新增配置，不修改底层计算逻辑。
