# 《开天辟地之大地的裂变》技能系统

## 1. 系统定位

技能系统用于定义角色在战斗、移动、探索、交互及其他游戏场景中可以主动使用、持续生效或条件触发的特殊能力。

技能是角色职业、装备、事件、信仰及特殊成长路线的重要表现方式。不同来源可以授予角色不同技能，但所有技能均使用统一的数据结构、条件检查和效果执行流程。

与普通攻击相比，技能通常可以提供：

* 特殊攻击方式。
* 固定攻击修正。
* 状态添加或移除。
* 位移与地图交互。
* 资源变化。
* 对标准规则的受控修改。

技能系统主要负责：

```text
定义技能
    │
    ▼
检查使用条件与目标
    │
    ▼
支付技能消耗
    │
    ▼
生成标准技能效果
    │
    ▼
交由对应系统完成结算
```

技能系统不重新计算角色最终派生属性，也不自行实现另一套伤害公式。

造成攻击的技能向战斗系统提供攻击属性、武器参与方式、固定修正、伤害类型及附加效果，最终伤害统一由《03-攻击与伤害计算》完成。

---

## 2. 设计目标

技能系统遵循以下设计目标：

### 2.1 统一结构

职业、装备、信仰与事件授予的技能采用相同定义结构，不为不同来源建立互不兼容的技能模型。

### 2.2 效果复用

技能优先组合伤害、状态、位移、资源变化等标准效果，不为每个技能单独编写完整业务流程。

### 2.3 配置优先

技能名称、类型、目标、距离、消耗、条件及效果参数通过配置维护。程序负责校验和执行，不在主流程中按照技能编号增加特殊判断。

### 2.4 职责分离

技能只声明希望产生的结果，伤害、状态、移动、物品、手牌及事件等具体变化由对应系统负责结算。

### 2.5 易于扩展

新增技能原则上只需新增技能配置并复用已有条件与效果处理器。只有出现真正无法由现有基础效果表达的新机制时，才新增通用效果类型。

---

## 3. 技能组成

每个技能建议包含以下基础信息：

| 项目 | 说明 |
| --- | --- |
| 技能 ID | 全局唯一且稳定的技能标识。 |
| 技能名称 | 玩家界面显示的技能名称或本地化资源键。 |
| 技能描述 | 向玩家说明使用条件、目标、消耗及结果。 |
| 技能类型 | 主动、被动或触发。 |
| 技能来源 | 职业、装备、信仰、事件或其他授予来源。 |
| 使用时机 | 主要行动、响应、回合阶段或指定触发时机。 |
| 使用条件 | 使用技能前必须满足的条件集合。 |
| 目标规则 | 技能允许选择的目标及目标数量。 |
| 作用距离 | 目标与技能使用者之间允许的距离。 |
| 作用范围 | 单体、指定区域或其他合法作用范围。 |
| 行动消耗 | 是否消耗主要行动、响应机会或其他行动权限。 |
| 资源消耗 | 灵力、生命、物品、元宝或其他资源消耗。 |
| 使用限制 | 每回合、每完整轮次、每次遭遇或每局的次数限制。 |
| 效果列表 | 按照顺序执行的标准效果集合。 |

概念配置示例如下：

```json
{
  "id": "skill_000001",
  "name": "powerStrike",
  "type": "ACTIVE",
  "sourceType": "CLASS",
  "timing": "MAIN_ACTION",
  "targetType": "SINGLE_ENEMY",
  "range": 1,
  "actionCost": "MAIN_ACTION",
  "resourceCosts": [],
  "conditionIds": [],
  "effectIds": ["skill-effect.power-strike.attack"]
}
```

技能定义只引用条件与效果标识。具体条件参数、效果参数及数值配置应与技能基础定义分离，避免将定义类型、内容配置和执行逻辑耦合在同一文件中。

## 4. 技能类型

V1 阶段支持以下三种技能类型。

### 4.1 主动技能（Active Skill）

主动技能需要玩家在合法时机主动声明使用。

其特点包括：

* 需要玩家进行选择。
* 通常需要选择合法目标。
* 可以消耗行动、资源或使用次数。
* 拥有明确的使用时机。

主动技能包括但不限于：

* 主动攻击技能。
* 主动防御技能。
* 位移技能。
* 辅助技能。
* 探索与交互技能。

“主动”只表示需要玩家声明，不表示技能只能在自己的主要行动阶段使用。例如，主动防御技能仍属于主动技能，但其合法时机是受到攻击后的防守响应阶段。

### 4.2 被动技能（Passive Skill）

被动技能不需要玩家主动声明，在技能有效并满足条件时持续提供规则或属性效果。

例如：

```text
生命值低于最大生命值的 30%
→ 最终物理防御提高
```

```text
装备指定类型武器
→ 降低目标本次闪避能力
```

被动技能通常通过属性修饰器、规则查询接口或其他持续效果实现。

被动技能只在自身有效期间生效。由装备授予的被动技能在装备卸下后立即失效；由临时事件授予的技能在事件结束后失效；永久学习的技能则按照角色成长规则保留。

### 4.3 触发技能（Triggered Skill）

触发技能在指定事件已经发生并满足条件后，自动创建一次离散效果。

常见触发时机包括：

* 受到攻击时。
* 成功造成伤害后。
* 击败目标后。
* 回合开始或结束时。
* 进入指定区域时。
* 获得或失去某项状态时。

触发技能必须明确触发条件、结算时机、单次触发上限及循环限制。

被动技能与触发技能的区别在于：

| 类型 | 生效方式 |
| --- | --- |
| 被动技能 | 条件满足期间持续提供能力或规则。 |
| 触发技能 | 条件满足时生成一次需要结算的具体效果。 |

---

## 5. 使用时机与行动消耗

技能类型与使用时机属于两个不同概念。

建议 V1 支持以下基础使用时机：

| 使用时机 | 说明 |
| --- | --- |
| 主要行动 | 在自己的主要行动阶段主动使用。 |
| 防守响应 | 在自身成为攻击目标后的防守响应阶段使用。 |
| 通用响应 | 在规则允许的效果结算前响应使用。 |
| 回合开始 | 在自身回合开始阶段使用或触发。 |
| 回合结束 | 在自身回合结束阶段使用或触发。 |
| 条件触发 | 指定事件发生后由系统自动触发。 |
| 场景交互 | 在地图、NPC、物品或其他场景允许时使用。 |

技能需要独立声明行动消耗，例如：

* 消耗主要行动。
* 消耗一次响应机会。
* 不消耗行动，但受到次数限制。
* 由触发条件自动执行。

主动攻击技能默认消耗一次主要行动，并在正式发起攻击后清空当前剩余移动力。

辅助、位移及探索技能是否消耗主要行动或移动力，由技能自身配置决定，不能仅根据技能名称推断。

---

## 6. 技能使用流程

主动技能按照以下统一流程执行：

```text
玩家选择技能
        │
        ▼
检查技能是否有效且已经获得
        │
        ▼
检查使用时机与行动权限
        │
        ▼
选择并校验目标
        │
        ▼
检查距离、视野、状态与使用条件
        │
        ▼
检查行动、资源与使用次数
        │
   ┌────┴────┐
   │         │
  非法      合法
   │         │
   ▼         ▼
不产生消耗  原子支付全部成本
             │
             ▼
        按顺序执行技能效果
             │
             ▼
        更新使用次数与状态
             │
             ▼
            结束
```

系统必须先完成全部合法性检查，再支付技能成本。

行动、资源与物品消耗需要作为一个整体完成。任意必要成本不足时，技能使用失败，不得只扣除其中一部分。

技能正式生效后，即使后续攻击被防御或闪避，已经支付的行动、资源与物品通常不会返还；技能规则明确允许返还时除外。

攻击技能进入标准战斗流程时，需要携带已经支付的技能成本记录。战斗系统可以复核攻击条件并按照规则清空剩余移动力，但不得再次扣除已经由技能系统支付的主要行动、角色资源、物品或使用次数。

被动技能不执行主动使用流程，而是在条件变化时重新评估是否生效。触发技能则在触发条件确认后，检查触发限制并执行对应效果。

## 7. 目标、距离与范围

### 7.1 目标类型

技能需要明确允许选择的目标类型。

V1 可以支持以下基础目标：

* 自身。
* 单个友方角色。
* 单个敌对角色。
* 单个合法角色。
* 指定地块。
* 指定区域。
* 无需选择目标。

目标类型采用可扩展配置。后续新增 NPC、物品、建筑或其他目标时，应扩展统一目标规则，不在单个技能中自行判断对象类型。

### 7.2 目标校验

目标需要同时满足：

* 目标类型合法。
* 目标当前仍然存在。
* 目标与使用者关系符合规则。
* 目标处于技能有效距离内。
* 视野或锁定条件符合技能要求。
* 目标没有处于技能明确禁止的状态。

技能正式生效前目标失效时，应按照技能配置决定终止技能、重新选择目标或继续作用于原位置。V1 默认终止该技能，不自动更换目标。

### 7.3 作用范围

范围技能应明确中心点、作用半径、合法目标筛选方式及目标结算顺序。

范围效果不等于一次普通单目标攻击。若范围内每个目标都需要进行防守、闪避与伤害判定，则系统应为每个目标建立独立的目标结算结果，并共享同一次技能成本与技能使用记录。

V1 阶段的范围技能应保持范围较小、目标筛选简单，并避免在同一技能中重复生成多轮范围攻击。

## 8. 技能与攻击计算

技能本身不直接决定最终伤害，而是向战斗系统提供当前攻击所需的信息。

一次攻击技能通常提供：

* 使用物理攻击或法术攻击。
* 是否读取武器本体攻击力。
* 固定技能修正值。
* 物理、法术或真实伤害类型。
* 是否允许暴击。
* 攻击距离与目标规则。
* 攻击未被闪避后需要执行的附加效果。

普通物理攻击可以表示为：

```text
攻击值
=
角色最终物理攻击
+
武器物理攻击力
```

“重击”技能可以表示为：

```text
攻击值
=
角色最终物理攻击
+
武器物理攻击力
+
技能固定修正
```

“火球”技能可以表示为：

```text
攻击值
=
角色最终法术攻击
+
技能固定修正
```

V1 阶段优先使用固定整数修正，不为普通技能大量配置独立攻击倍率。确实需要倍率的特殊技能应使用整数百分数，并继续遵循《03-攻击与伤害计算》的先乘后除及取整规则。

技能只决定读取哪些数据、增加哪些修正以及附加哪些效果。防御、穿透、最低伤害、暴击、护盾与生命值扣除仍由战斗系统统一处理。

---

## 9. 技能效果

技能效果采用统一、可组合的效果结构。

一个技能可以包含一个或多个效果，并按照配置顺序执行：

```text
造成一次法术攻击
        │
        ▼
攻击未被闪避
        │
        ▼
为目标添加燃烧状态
```

后续效果可以声明执行条件，例如“攻击未被闪避后”“造成生命伤害后”或“目标进入击倒状态后”。条件未满足时，只跳过对应效果，不回滚此前已经合法完成的效果。

### 9.1 攻击与伤害效果

攻击效果用于创建一次标准攻击流程，可以声明：

* 攻击属性来源。
* 武器参与方式。
* 固定攻击修正。
* 伤害类型。
* 是否允许暴击。
* 修正目标的闪避数值或闪避条件。

技能不能在自身处理器中绕过战斗系统直接扣除生命值。明确属于直接生命变化而非攻击伤害的特殊效果，必须使用独立效果类型并清楚说明其边界。

### 9.2 状态效果

状态效果用于添加、刷新、叠加或移除 Buff／Debuff，例如：

* 增加力量。
* 降低物理防御。
* 添加中毒。
* 移除冰冻。

技能只提交状态标识、目标及必要参数，状态是否可叠加、持续多久以及何时移除，由《05-状态效果（Buff／Debuff）》统一管理。

### 9.3 位移效果

位移效果用于改变角色位置，例如：

* 推开目标。
* 拉近目标。
* 使用者移动。
* 传送至合法地块。

位移必须调用地图系统提供的普通移动、特殊连接或强制位移接口，并遵循坐标、边界、地块占用与落点校验规则。

技能系统不能直接修改角色坐标以绕过地图合法性检查。

### 9.4 资源效果

资源效果用于改变当前生命、灵力、护盾、元宝或其他合法运行时资源。

资源变化必须调用对应资源系统，并遵循最小值、最大值及背包空间等规则。元宝属于背包物品，技能需要支付或给予元宝时，以元宝物品数量为单位处理。

### 9.5 手牌与物品效果

技能可以在规则允许时获得手牌、使用物品或产生物品奖励。

抽取手牌必须调用共享牌库服务；获得物品必须遵循背包与临时拾取区流程。技能不得直接向角色状态写入未经校验的手牌或物品。

### 9.6 特殊效果

少量技能可以修改行动规则、触发事件或产生其他特殊机制。

特殊效果应优先调用已有系统能力。若现有系统无法表达，应先设计可复用的通用效果处理器，不能在技能主流程中按照单个技能 ID 编写分支。

## 10. 技能消耗

技能可以配置一种或多种消耗。

### 10.1 行动消耗

行动消耗包括：

* 主要行动。
* 响应机会。
* 移动力。
* 其他系统定义的行动权限。

主动攻击技能默认消耗主要行动，并在攻击正式发起后将剩余移动力清零。

### 10.2 角色资源消耗

角色资源消耗可以包括：

* 当前灵力值。
* 当前生命值。
* 职业专属资源。
* 其他可扩展运行时资源。

以生命值作为消耗时，默认不能将使用者生命值降低至 `0`；允许以生命为代价进入击倒状态的特殊技能必须明确说明。

### 10.3 物品与经济消耗

技能也可以消耗：

* 指定消耗品。
* 指定材料。
* 元宝。
* 其他合法背包物品。

技能使用前必须确认背包中拥有足够数量，并在技能正式生效时原子扣除。元宝消耗以元宝物品数量为单位，不使用独立余额字段。

---

## 11. 使用条件与限制

### 11.1 条件限制

技能可以配置以下条件：

* 当前生命值低于或高于指定边界。
* 目标位于指定距离内。
* 使用者装备指定武器或装备类型。
* 使用者或目标拥有指定状态。
* 当前处于指定地形、天气或昼夜。
* 使用者属于指定职业、种族或信仰。
* 当前拥有足够资源或物品。

多个条件默认需要全部满足。需要“满足任意条件”的技能，应通过明确的条件组合配置表示。

### 11.2 次数限制

技能可以按照以下时间范围限制使用次数：

| 限制范围 | 示例 |
| --- | --- |
| 每次攻击响应 | 每次成为攻击目标时最多使用一次。 |
| 每个自身回合 | 每个自身回合最多使用一次。 |
| 每个完整轮次 | 每轮所有玩家行动期间最多使用一次。 |
| 每次遭遇 | 当前遭遇对象存续期间最多使用一次。 |
| 每局游戏 | 整局游戏最多使用一次。 |

本游戏不存在独立的持续战斗场景，因此不使用含义模糊的“每场战斗一次”。需要限制某段交互时，应明确使用攻击、回合、完整轮次、遭遇或整局游戏作为计数范围。

### 11.3 冷却与恢复

V1 可以使用整数回合冷却，但必须明确按“自身回合”还是“完整轮次”递减。

冷却值为 `0` 表示技能当前可用。技能成功使用后设置冷却，只有对应时间单位完成时才递减；技能使用失败不会进入冷却。

被动技能通常不使用冷却。触发技能需要限制频率时，可以采用触发次数上限或明确的回合冷却。

## 12. 技能与移动规则

主动攻击技能通常遵循普通攻击的移动规则：

```text
完成技能合法性检查
        │
        ▼
支付技能与主要行动成本
        │
        ▼
当前剩余移动力清零
        │
        ▼
进入标准攻击流程
```

即使技能攻击被主动防御或自然闪避，已经清空的移动力也不会返还。

非攻击技能是否消耗移动力，由技能配置决定：

* 自身强化技能可以只消耗主要行动。
* 位移技能可以消耗指定移动力或直接产生强制位移。
* 响应技能通常不消耗普通移动力。
* 探索技能可以使用主要行动、移动力或场景交互机会。

技能允许“攻击后继续移动”时，必须明确恢复或授予多少移动力。不得简单恢复攻击前的全部剩余移动力，以免结算期间的其他移动修正被错误覆盖。

---

## 13. 技能与反击机制

默认情况下，技能不会因为造成攻击而自动触发目标反击。

只有规则明确声明以下内容时，才会产生额外战斗效果：

* 反击。
* 追击。
* 追加攻击。
* 受到攻击时触发。
* 受到伤害时触发。

例如：

```text
荆棘护甲

受到近战攻击并承受生命伤害后，
攻击者受到 2 点真实伤害。
```

该效果属于触发技能或装备触发效果，不属于基础战斗规则。

反击与追加攻击必须建立新的攻击上下文，但仍属于当前外层效果的嵌套结算。每项能力必须设置明确的触发次数，并默认禁止由自身产生的反击再次触发同一反击，避免无限循环。

---

## 14. 技能来源与失效

技能可以来自：

* 初始职业。
* 转职。
* 装备。
* 信仰。
* 事件。
* 任务奖励。
* 永久成长。
* 特殊契约或世界规则。

角色运行时应记录技能授予来源，而不是只保存无法追溯的技能 ID 集合。

当某个授予来源失效时，只移除该来源提供的技能权限。若同一技能仍由其他有效来源提供，角色继续拥有该技能。

装备授予的技能在装备卸下后失效；临时事件授予的技能在事件结束后失效；职业与永久成长授予的技能按照各自规则保留。

技能失效时，尚未开始的技能不可继续使用。已经支付成本并进入结算的技能通常完成当前结算，效果明确要求立即终止时除外。

---

## 15. V1 设计范围

V1 阶段支持：

* 主动技能。
* 被动技能。
* 触发技能。
* 主要行动与响应时机。
* 单目标效果。
* 简单范围效果。
* 物理、法术与真实伤害入口。
* 状态添加与移除。
* 普通移动与强制位移效果。
* 简单资源及物品消耗。
* 条件与使用次数限制。
* 整数回合冷却。

以下内容保留至战斗系统 `V2` 目录：

* 连招系统。
* 技能升级树。
* 技能融合。
* 复杂多阶段技能。
* 实时施法与施法条。
* 大量技能联动组合。
* 复杂 AI 技能决策。

## 16. 设计原则

技能系统遵循以下设计原则：

玩法优先原则

技能应优先提供攻击方式、目标选择、状态、位移及规则变化，而不是只提供更高伤害。

统一结算原则

技能产生的攻击、伤害、状态、位移与资源变化必须进入对应系统的统一流程，不能自行修改底层状态。

固定修正优先原则

V1 技能优先使用简单整数修正，减少独立倍率和多层百分比计算。

类型与时机分离原则

主动、被动与触发描述技能如何生效；主要行动、响应及回合阶段描述技能何时生效，两者不能混为同一字段。

先校验后消耗原则

技能必须先通过权限、目标、条件与资源校验，再原子支付全部成本。

配置与执行分离原则

技能定义、技能内容配置、条件处理器与效果处理器彼此分离，避免按照单个技能 ID 编写业务分支。

循环受控原则

触发、反击与追加攻击必须拥有触发次数和结束条件，不能形成递归触发或无限结算。

---

## 17. 小结

技能系统通过统一定义、使用条件、目标规则、资源消耗与效果列表，描述角色可以主动使用、持续拥有或条件触发的特殊能力。

技能只负责声明能力意图，并将攻击、状态、位移、资源与物品变化交由对应系统结算。通过区分技能类型与使用时机、复用标准效果并限制复杂倍率与触发循环，V1 技能系统能够保持规则清晰、易于配置且便于后续扩展。
