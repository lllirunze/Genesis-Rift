# 《开天辟地之大地的裂变》状态效果（Buff／Debuff）

## 1. 系统定位

状态效果用于描述角色在游戏过程中受到的临时、长期或近似永久影响。

状态按照作用倾向分为：

* Buff：为目标提供正向增益。
* Debuff：削弱目标能力或限制目标行为。

状态可以来自：

* 技能。
* 装备。
* 事件。
* 天气。
* 地形。
* 神鬼契约。
* 任务与特殊奖励。
* 其他明确授予状态的机制。

状态系统负责维护状态定义、运行时实例、层数、剩余回合、来源及移除规则。

状态本身不重新计算角色属性。涉及属性变化时，状态系统根据当前有效层数生成属性修饰器，再由数值系统统一计算角色最终属性。

整体关系如下：

```text
状态被施加
    │
    ▼
创建或更新状态实例
    │
    ▼
生成属性修饰器或规则效果
    │
    ▼
数值系统重新聚合角色属性
    │
    ▼
战斗及其他系统读取最终结果
```

状态系统不直接修改角色基础属性存档，也不保存状态生效前的旧属性值。

---

## 2. 设计目标

状态系统遵循以下设计目标：

### 2.1 统一生命周期

所有 Buff 与 Debuff 均通过统一的施加、刷新、叠层、持续时间推进和移除流程管理。

### 2.2 属性解耦

状态引起的基础属性或派生属性变化统一转换为属性修饰器，不直接覆盖角色当前属性。

### 2.3 来源可追踪

每个运行时状态实例记录来源、目标和创建顺序，便于日志、复盘、移除及异常定位。

### 2.4 叠层受控

普通状态默认只有 `1` 层。只有明确配置为可叠层的状态才能继续增加层数，并且必须具有最大层数。

### 2.5 配置优先

状态名称、类型、标签、持续时间、最大层数、移除规则及效果通过配置维护，程序负责统一校验和执行。

---

## 3. 状态数据组成

状态数据分为静态定义与运行时实例，两者不得混合维护。

### 3.1 状态静态定义

状态静态定义描述所有相同状态共享的固定规则。

| 字段 | 说明 |
| --- | --- |
| 状态定义 ID | 全局唯一且稳定的状态标识。 |
| 名称 | 状态名称或对应本地化资源键。 |
| 描述 | 向玩家说明状态效果、持续时间与叠层方式。 |
| 类型 | Buff 或 Debuff。 |
| 标签 | 用于检索、免疫、驱散及规则判断。 |
| 默认持续时间 | 状态每次施加或刷新后拥有的完整持续回合数。 |
| 最大层数 | 状态允许达到的最高层数。 |
| 是否可驱散 | 普通驱散效果能否移除该状态。 |
| 死亡时是否移除 | 角色正式死亡时是否清除该状态。 |
| 效果列表 | 每层状态产生的属性修正或其他规则效果。 |

概念配置示例如下：

```json
{
  "definitionId": "debuff_000001",
  "name": "poisoned",
  "description": "Reduces health regeneration for a limited duration.",
  "kind": "debuff",
  "tags": ["poison", "survival", "recovery"],
  "duration": {
    "turns": 3
  },
  "maxStacks": 1,
  "removal": {
    "dispellable": true,
    "removeOnDeath": true
  },
  "effects": []
}
```

### 3.2 状态运行时实例

状态运行时实例只保存当前角色实际拥有的状态数据。

| 字段 | 说明 |
| --- | --- |
| 状态实例 ID | 当前状态实例的唯一编号。 |
| 状态定义 ID | 关联的静态状态定义。 |
| 来源 ID | 首次创建当前实例的技能、装备、事件或其他来源。 |
| 目标 ID | 当前受到状态影响的角色。 |
| 当前层数 | 当前实际生效的状态层数。 |
| 剩余回合 | 状态距离自然结束还剩多少个目标自身回合。 |
| 创建顺序 | 用于稳定排序、日志及同时结算。 |

运行时实例不复制状态名称、描述、效果参数及最大层数等固定配置。

### 3.3 定义与实例关系

同一个状态定义可以在不同角色身上分别创建运行时实例。

同一角色在 V1 阶段对同一状态定义只保留一个运行时实例。重复施加同一定义时，系统更新已有实例的层数和剩余回合，不创建重复实例。

如果未来确实需要同名效果按照不同来源独立计时，应创建能够明确区分规则的状态定义，或在 V2 中扩展多来源实例模型，不能绕过状态系统直接保存临时字段。

## 4. 状态类型

### 4.1 增益状态（Buff）

Buff 用于提升角色能力、提供保护或授予额外权限。

例如：

* 提高力量。
* 提高物理防御。
* 提高移动力。
* 提高暴击率。
* 提高生命恢复。
* 提供特定控制免疫。

属性型 Buff 通常通过属性修饰器实现。

例如：

```json
{
  "effectType": "attribute_modifier",
  "effectId": "physical-attack",
  "targetType": "derived",
  "targetAttribute": "physicalAttack",
  "valuePerStack": 5
}
```

当前状态为 `1` 层时，表示为角色提供：

```text
最终物理攻击 +5
```

### 4.2 负面状态（Debuff）

Debuff 用于降低角色能力、造成持续影响或限制角色行为。

例如：

* 中毒。
* 虚弱。
* 燃烧。
* 减速。
* 沉默。
* 束缚。

属性型 Debuff 可以提供负数属性修饰：

```text
最终物理攻击 -3
```

行为型 Debuff 则通过规则限制生效：

```text
沉默
→ 无法使用规则标记为“会被沉默阻止”的技能
```

Debuff 不一定允许普通驱散。是否可驱散必须由状态定义明确配置。

### 4.3 特殊表现状态

部分状态主要改变角色规则，而不是直接修改属性，例如：

* 隐匿。
* 无敌。
* 沉默。
* 变形。
* 技能施加的倒地控制。

“特殊状态”不是 Buff 与 Debuff 之外的第三种底层类型。每个特殊状态仍需根据作用倾向归入 Buff 或 Debuff，并通过标签与效果类型表达具体规则。

例如，隐匿通常属于 Buff，沉默通常属于 Debuff。

角色生命值降至 `0` 后进入的“击倒”属于角色生命生命周期，不作为普通 Buff／Debuff 管理。技能施加的倒地控制与击倒也不是同一概念。

---

## 5. 状态与属性修饰器

状态产生的属性变化统一通过属性修饰器系统管理。

例如，角色受到“虚弱”状态：

```text
状态定义：debuff_000002
状态实例：status-instance.weakness.001
当前层数：1
```

状态系统根据定义和实例生成派生属性动态偏移量：

```json
{
  "sourceId": "status-instance.weakness.001",
  "targetType": "derived",
  "targetAttribute": "physicalAttack",
  "value": -4
}
```

状态属性修正按照以下公式计算：

```text
当前状态修正值
=
每层修正值 × 当前层数
```

状态结束或被移除后，系统根据状态实例 ID 删除其产生的全部属性修饰器，并重新聚合角色属性。

这种设计能够保证：

* 状态添加时不需要记录修改前属性。
* 状态叠层后可以统一重建修正值。
* 状态移除时不会误删其他来源的修饰器。
* 多个不同状态可以同时影响同一属性。
* 战斗系统始终读取数值系统生成的最终属性。

状态不得直接修改角色当前基础属性或永久成长结果。

---

## 6. 状态施加流程

状态按照以下流程施加：

```text
效果请求施加状态
        │
        ▼
读取状态定义
        │
        ▼
检查目标、免疫与施加条件
        │
   ┌────┴────┐
   │         │
  失败      成功
   │         │
   ▼         ▼
不修改状态  查找同定义状态实例
             │
        ┌────┴────┐
        │         │
      不存在     已存在
        │         │
        ▼         ▼
 创建零层实例  读取当前层数
        │         │
        └────┬────┘
             ▼
      尝试增加一层状态
             │
             ▼
      刷新为完整持续时间
             │
             ▼
      重建对应属性修饰器
             │
             ▼
       记录结果并结束
```

首次施加状态时，运行时实例先以 `0` 层创建，再按照同一施加规则增加至 `1` 层。

普通不可叠层状态的最大层数为 `1`。重复施加时层数保持 `1`，但剩余回合刷新为该状态的完整持续时间。

可叠层状态每次成功施加默认增加 `1` 层，达到最大层数后不再增加，但仍然刷新完整持续时间。

状态免疫只阻止对应状态成功施加，不应先创建实例或短暂产生属性修饰器。

## 7. 状态持续时间

### 7.1 时间单位

状态持续时间统一使用目标角色的“自身回合”作为 V1 默认时间单位。

例如：

```text
燃烧
持续时间：2 个目标自身回合
```

状态定义保存默认完整持续时间，状态实例保存当前剩余回合。

### 7.2 回合递减

所有处于生效状态且剩余回合大于 `0` 的状态，在目标自身回合结束阶段按照统一顺序处理。

```text
结算回合结束时状态效果
        │
        ▼
状态剩余回合 -1
        │
        ▼
剩余回合是否为 0？
   ┌────┴────┐
   │         │
   否        是
   │         │
   ▼         ▼
继续保留    移除状态实例
             │
             ▼
       删除对应修饰器
             │
             ▼
       重新聚合角色属性
```

状态在目标自身回合结束前施加时，会参与该回合结束阶段的持续时间递减。内容设计者应据此配置持续回合数，不能假设新状态必然跳过当前回合。

剩余回合不会在其他玩家回合结束时递减，也不会因为单次攻击、事件响应或其他嵌套流程而额外递减。

### 7.3 永久状态

永久状态不增加额外布尔标记，而是统一使用预留持续时间：

```text
永久状态持续时间 = 999999 回合
```

程序与配置统一引用 `PERMANENT_STATUS_DURATION_TURNS`，不在不同状态中重复书写含义不同的永久数值。

永久状态仍使用普通持续时间结构，并按照统一流程维护。该数值在一局正常游戏中可视为不会自然结束，但状态仍可能按照自身移除规则被特定效果移除。

---

## 8. 状态结算时机

状态效果必须明确触发时机，避免使用含义不清的“行动时”或“战斗中”。

V1 建议支持以下基础时机：

### 8.1 自身回合开始

在状态目标自身回合开始阶段结算。

例如：

* 中毒造成持续伤害。
* 自然恢复效果生效。
* 回合开始时获得护盾。

### 8.2 移动前与移动后

在目标尝试移动前检查限制，或在合法移动完成后触发效果。

例如：

* 束缚阻止普通移动。
* 每移动一格累计一次特殊效果。
* 进入指定地形后移除伪装。

单纯降低移动力的状态不需要在每次移动时触发，而是通过属性修饰器直接影响最终移动力。

### 8.3 攻击声明时

攻击正式发起并建立攻击上下文时触发。

例如：

* 本次攻击附加燃烧。
* 消耗一层强化状态提高攻击值。
* 沉默阻止特定技能攻击。

### 8.4 攻击未被闪避后

攻击未被主动防御或自然闪避规避后触发，但此时不一定已经造成生命伤害。

例如：

* 攻击未被闪避后施加标记。
* 攻击未被闪避后降低目标物理防御。

### 8.5 受到攻击或伤害后

“受到攻击后”与“受到伤害后”属于不同触发条件：

* 受到攻击后：攻击已经指向目标，即使护盾完全吸收也可能触发。
* 受到伤害后：目标实际承受了大于 `0` 的合法伤害后触发。
* 受到生命伤害后：当前生命值实际减少后触发，护盾完全吸收时不触发。

荆棘、反击及受击恢复等效果必须选择其中一个明确时机。

### 8.6 自身回合结束

在目标自身回合结束阶段结算持续效果。

例如：

* 燃烧造成持续伤害。
* 回合结束时移除护盾。
* 延迟恢复生效。

回合结束效果先完成结算，再统一递减剩余回合。剩余 `1` 回合的状态因此仍会完成最后一次回合结束效果，然后到期移除。

## 9. 状态叠加规则

### 9.1 普通不可叠层状态

普通 Buff 与 Debuff 默认配置：

```text
最大层数 = 1
```

该状态生效时当前层数始终为 `1`。重复施加不会创建第二个实例，也不会将层数提高至 `2`，只刷新完整持续时间。

例如：

```text
冻结
当前层数：1
剩余回合：1

再次施加冻结
        ↓
当前层数：1
剩余回合：恢复为完整持续时间
```

### 9.2 可叠层状态

只有明确配置 `maxStacks` 大于 `1` 的状态可以叠层。

可叠层状态的实例以 `0` 层创建，每次成功施加增加 `1` 层，直到达到最大层数。

例如：

```text
奥术积累
每层悟性 +1
最大层数：10

当前层数：3
实际修正：悟性 +3
```

达到最大层数后再次施加时：

* 当前层数保持最大值。
* 剩余回合刷新为完整持续时间。
* 不产生超出最大层数的额外收益。

状态层数只能在规则明确允许的时机增加或减少，不能因为回合推进自动减少层数。回合结束默认只减少剩余回合。

### 9.3 不同状态独立存在

不同状态定义可以同时存在，并分别维护层数与剩余回合。

例如，“战斗狂热”和“风神祝福”即使都提高角色能力，也不会合并为同一个状态实例。

多个不同状态修改同一属性时，各自生成独立属性修饰器，再由属性系统按照统一规则聚合。

同一状态定义无论由何种来源重复施加，V1 均合并至目标现有的同定义实例。实例保留首次创建时的来源 ID，后续施加来源记录在本次操作日志中，但不创建第二个实例。

### 9.4 层数减少

技能、驱散或其他规则可以明确减少状态层数。

```text
减少后的层数
=
max（0，当前层数 - 移除层数）
```

层数降低后，状态产生的属性修正立即按照新层数重新计算。

当层数降低至 `0` 时，状态实例立即移除，不继续保留零层占位实例，也不等待剩余回合结束。

## 10. 状态移除

状态可以通过以下方式移除：

* 剩余回合降低至 `0`。
* 状态层数降低至 `0`。
* 合法驱散效果成功。
* 状态来源或场景规则明确要求结束。
* 角色正式死亡且状态配置为死亡时移除。
* 特殊系统规则直接移除指定状态。

状态移除流程如下：

```text
确认状态可以移除
        │
        ▼
移除状态运行时实例
        │
        ▼
移除该实例产生的属性修饰器
        │
        ▼
关闭该实例提供的规则效果
        │
        ▼
重新聚合角色属性与资源边界
        │
        ▼
记录移除原因
```

普通驱散只能移除 `dispellable` 为 `true` 的状态。不可驱散不代表绝对无法移除，状态仍可以因到期、死亡规则或明确指定的特殊效果结束。

角色正式死亡时，只移除 `removeOnDeath` 为 `true` 的状态。神鬼契约、永久成长等需要跨越死亡保留的状态应将该配置设为 `false`。

状态移除导致最大生命、最大灵力或其他资源上限降低时，当前资源按照数值系统的边界规则截断，不按比例自动恢复或扣除额外资源。

---

## 11. 行为限制与控制状态

行为型状态不通过属性偏移量表达，而是向对应系统提供规则限制。

例如：

| 状态 | 规则影响 |
| --- | --- |
| 沉默 | 阻止使用被沉默限制的技能。 |
| 束缚 | 阻止普通移动，但不一定阻止传送或强制位移。 |
| 冰冻 | 按照状态定义限制移动、主要行动或响应。 |
| 隐匿 | 影响其他角色的视野与目标锁定。 |
| 无敌 | 按照定义使指定伤害或效果失效。 |

每个控制状态必须明确：

* 被限制的具体行为。
* 不受影响的行为。
* 生效与结束时机。
* 是否允许驱散。
* 是否在死亡后保留。

当多个行为状态同时存在时，默认采用“禁止优先”原则：只要任意有效状态禁止当前行为，该行为即不可执行。明确声明可以忽略某类限制的特殊能力除外。

控制状态不能通过直接把无关属性设置为极端数值来模拟。例如，沉默应限制对应技能权限，而不是将法术攻击修改为 `0`。

---

## 12. 状态效果执行顺序

同一时机存在多个状态效果时，按照以下顺序处理：

1. 检查状态实例是否仍然有效。
2. 处理阻止非法行为的控制与免疫规则。
3. 按照状态定义的效果顺序执行同一状态内的效果。
4. 按照状态实例创建顺序执行不同状态。
5. 处理效果产生的直接后续结果。
6. 检查生命、资源及属性边界。
7. 记录状态结算结果。

状态实例创建顺序必须由权威游戏状态提供，不能依赖客户端请求到达顺序或本地数组偶然顺序。

若状态效果在结算过程中移除了另一个尚未执行的状态，被移除状态不再继续执行本次效果。

任何触发型状态都必须具有明确触发次数和结束条件，避免状态之间互相触发形成无限循环。

## 13. 与其他系统的关系

状态系统与其他模块的职责如下：

| 相关系统 | 主要职责 |
| --- | --- |
| 数值系统 | 聚合状态产生的属性修饰器并计算最终属性。 |
| 战斗系统 | 在规定节点提交攻击、闪避、伤害及生命变化结果。 |
| 技能系统 | 根据技能效果请求施加、减少或移除状态。 |
| 地图系统 | 为天气、地形、区域与移动状态提供环境信息。 |
| 装备系统 | 授予状态、状态免疫或与状态相关的装备效果。 |
| 事件系统 | 根据事件结果施加祝福、诅咒或其他状态。 |
| 角色资源系统 | 管理状态造成的生命、灵力及护盾变化。 |
| 日志系统 | 记录状态施加、叠层、刷新、结算与移除。 |

状态系统不能直接修改地图坐标、背包内容、任务进度或使命结果。需要产生这些变化时，应调用对应系统的标准接口。

## 14. V1 设计范围

V1 阶段支持：

* Buff 与 Debuff 二分类。
* 状态静态定义与运行时实例分离。
* 普通单层状态。
* 具有最大层数的可叠层状态。
* 重复施加时叠层或刷新持续时间。
* 目标自身回合结束时递减持续时间。
* 统一永久状态持续时间常量。
* 基础属性与派生属性修饰。
* 简单行为限制。
* 按标签查询状态。
* 可驱散与死亡移除规则。

以下内容保留至战斗系统 `V2` 目录：

* 同一定义按照多个来源独立计时。
* 复杂状态优先级与覆盖组。
* 状态之间的自动转化与融合。
* 多阶段持续伤害公式。
* 跨角色传播与连锁感染。
* 复杂控制抗性与持续时间缩减。

## 15. 设计原则

状态系统遵循以下设计原则：

二分类原则

底层状态只分为 Buff 与 Debuff，特殊表现通过标签和效果类型表达，不新增含义模糊的第三类状态。

单实例原则

同一状态定义在同一角色上默认只有一个实例，重复施加只负责叠层和刷新。

普通单层原则

普通状态最大层数为 `1`；只有明确配置为可叠层的状态才能超过 `1` 层。

回合递减原则

状态剩余回合在目标自身回合结束时统一减 `1`，状态层数只在明确效果发生时变化。

修饰器复用原则

属性型状态只生成属性修饰器，不直接覆盖角色属性，也不保存状态生效前的旧值。

来源可追踪原则

状态实例、属性修饰器和日志需要保留稳定标识，确保添加、移除和复盘结果一致。

永久值统一原则

永久状态统一使用 `PERMANENT_STATUS_DURATION_TURNS`，不增加额外永久标记或分散定义魔法数字。

循环受控原则

触发型状态必须设置次数、时机和终止条件，不能形成递归触发或无限结算。

## 16. 小结

状态系统通过统一的 Buff／Debuff 定义、运行时实例、层数、持续时间、来源和移除策略，管理角色在游戏过程中受到的各种持续影响。

普通状态始终保持 `1` 层，可叠层状态从 `0` 层开始并在合法时机逐层增加；所有生效状态在目标自身回合结束时推进持续时间。属性变化统一转换为属性修饰器，行为限制则通过对应系统的规则接口生效。

通过保持定义与实例分离、状态与属性计算解耦，并统一处理刷新、叠层、驱散和死亡移除，状态系统能够为技能、装备、事件、天气及其他玩法提供稳定且可扩展的持续效果基础。
