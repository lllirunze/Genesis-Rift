# 《开天辟地之大地的裂变》项目定位

## 1. 文档目的

本文档用于明确《开天辟地之大地的裂变》的项目定位、核心体验、设计边界与当前规则基准。

本章节只描述项目级原则，不重复定义地图、角色、数值、装备、战斗、手牌、经济、事件、获胜条件及公共模块的详细规则。各系统的具体行为，均以后续对应设计文档为准。

当早期设想、原作片段与现行系统规则存在差异时，应按照以下优先级进行判断：

现行系统文档 → 本项目定位 → 指导思想 → 原作中未完整说明的推测内容。

---

## 2. 项目概述

《开天辟地之大地的裂变》是一款以多人联机为主要形态的数字桌游。

项目灵感来源于《爱情公寓》第三季中陆展博设计的同名桌游。原作通过“上帝”、创界山、身份、种族、元宝、点卡、昼夜变化以及二十面骰等内容，展示了一个将多种桌游规则融合在一起的庞大游戏世界。

由于原作主要服务于剧情与喜剧表达，许多规则只展示了局部片段，并未形成可以直接运行的完整体系。

本项目的目标不是逐句复刻剧中台词，也不是借用名称重新制作一款无关游戏，而是在尊重原作核心设定与娱乐气质的基础上，对缺失规则进行系统化补全，使其成为一款规则统一、能够实际运行并便于持续扩展的多人数字桌游。

---

## 3. 核心定位

### 3.1 原作致敬作品

项目首先是对《爱情公寓》中同名桌游的致敬。

以下内容构成项目的重要原作基底：

* 《开天辟地之大地的裂变》的名称与整体气质；
* 由“上帝”维护规则的桌游表现形式；
* 创界山与大地裂变；
* 身份、种族、信仰与隐藏信息；
* 元宝、点卡及朋友间的娱乐互动；
* 昼夜变化、秘密行动与世界事件；
* 角色死亡后通过二十面骰重新加入游戏；
* 多种玩法彼此连接所形成的荒诞感与趣味性。

对于原作已经明确展示的内容，原则上保留其名称、用途与表现特征；对于原作没有说明或无法直接运行的部分，则在不破坏原作气质的前提下进行补全。

### 3.2 多人联机数字桌游

本项目的主要运行形态为多人联机游戏。

玩家将在同一张共享地图中进行探索、成长、战斗、交易、制造、合作与博弈，并围绕各自隐藏的使命争取胜利。

数字化的主要价值是由系统承担复杂规则的执行工作，包括：

* 回合与世界轮次推进；
* 隐藏信息管理；
* 行动合法性检查；
* 属性与效果结算；
* 随机结果生成；
* 地图、事件与环境状态更新；
* 使命进度与获胜条件判断；
* 可读日志、权威操作记录、存档快照与断线恢复。

玩家的注意力应集中在路线规划、资源分配、临场选择与彼此互动上，而不是手工记忆和计算大量规则。

### 3.3 探索驱动的角色成长游戏

游戏的长期动力来自世界探索，而不是单纯依靠战斗或等级提升。

玩家通过探索未知地块接触区域、NPC、事件、敌人、图纸与材料，再通过角色成长、装备制造、元宝交易及策略牌使用，提高处理后续局势的能力。

游戏不设置唯一固定的成长路线。不同身份、种族、信仰、属性分配、装备搭配与使命组合，应当形成不同的发展方式。

---

## 4. 核心体验

项目希望为玩家提供以下五项核心体验。

### 4.1 逐步揭示的世界

玩家从地图外围进入世界，并在环形移动规则下逐步探索未知区域。

已探索区域便于通行，首次进入未知地块则需要付出更高的移动成本。随着游戏推进，地图会从陌生逐渐变得清晰，同时仍会受到天气、事件、裂变及其他世界状态的持续影响。

### 4.2 多路线角色构筑

角色由信仰、身份、种族、性别标签、等级、基础属性、派生属性、装备、手牌与使命等内容共同组成。

其中，身份承担角色主要玩法定位；种族与信仰提供不同倾向；等级和属性形成基础成长；装备与策略牌用于适应具体局势。

任何单一系统都不应完全决定角色强度或最终胜负。

### 4.3 隐藏目标与玩家博弈

每名玩家拥有五个隐藏使命，并通过完成其中任意三个使命获得个人胜利。

使命使不同玩家在同一世界中拥有不同目标。玩家可以合作处理公共威胁，也可以围绕资源、路线、事件与任务形成竞争，同时通过他人的行为推测其发展方向。

### 4.4 持续变化的公共世界

昼夜、气候、事件、NPC状态、地图变化与大地裂变共同构成动态世界。

这些变化应当为玩家带来新的条件和选择，而不是无预警地摧毁长期成长。若世界变化使某项使命客观上无法完成，系统应提供自动转换等保障机制。

### 4.5 轻松而有规则感的聚会体验

游戏可以拥有荒诞、意外与原作彩蛋，但所有结果仍需遵循公开规则。

“上帝”、点卡、神鬼契约及彩蛋事件用于增强聚会氛围，不得成为任意修改结果、破坏公平或向特定玩家提供隐藏优势的借口。

---

## 5. 默认游戏框架

当前默认游戏由以下系统共同组成：

| 系统 | 主要职责 |
| --- | --- |
| 地图系统 | 管理六边形地图、环层、区域、地形、探索、视野、移动与出生位置。 |
| 角色系统 | 管理信仰、身份、种族、性别标签、等级、转职与角色使命。 |
| 数值系统 | 统一管理基础属性、派生属性、属性修饰及数值结算规则。 |
| 装备系统 | 管理装备栏、图纸、制造及装备生效机制。 |
| 背包与物品系统 | 管理物品的持有与存放；元宝进入背包后按照普通可叠加物品处理。 |
| 战斗系统 | 管理战斗流程、攻击、伤害、生命、技能与状态效果。 |
| 手牌系统 | 管理稀缺的一次性策略牌及其响应时机。 |
| 经济系统 | 定义元宝的获取、消耗、计价、支付与交易规则。 |
| 事件系统 | 通过分类事件池为探索与世界变化提供随机内容。 |
| 使命系统 | 生成隐藏使命、记录进度并判定个人获胜条件。 |
| 公共模块 | 提供随机、复活与中途加入、昼夜与气候、神鬼契约等通用能力。 |

各系统应通过稳定接口联动，不应在自身文档中重复定义其他系统的核心规则。

---

## 6. 核心循环

游戏的核心循环可概括为：

探索世界 → 接触事件与目标 → 获得资源与信息 → 完成成长与构筑 → 应对更高风险 → 推进隐藏使命 → 达成获胜条件。

战斗、交易、制造和策略牌都服务于这一循环，而不是相互独立的玩法入口。

创界山、世界事件与大地裂变会提供高价值目标和局势变化，但默认情况下不会替代使命获胜规则。

---

## 7. 获胜定位

本项目默认采用个人隐藏使命作为主要获胜方式。

每名玩家在角色创建完成后获得五个隐藏使命：

* 身份使命；
* 信仰使命；
* 成长使命；
* 世界使命；
* 自由使命。

完成任意三个使命后，玩家满足个人胜利条件。系统将在当前行动、战斗或事件完整结算后统一宣布结果。

如果同一次完整结算使多名玩家同时满足条件，则这些玩家可以共同获胜。

创界山是地图中心的重要区域，也是世界使命、特殊事件与高难度内容的主要承载位置。若未来需要采用“率先登上创界山直接获胜”等规则，应作为独立的可选模式，不改变默认规则。

---

## 8. 原作适配边界

为了兼顾还原度与可运行性，项目内容分为以下三类。

| 类型 | 定义 | 处理原则 |
| --- | --- | --- |
| 原作基底 | 原剧中明确出现或明确表达的名称、规则与情节。 | 优先保留核心含义与表现形式。 |
| 系统化补全 | 原作未完整说明，但游戏正常运行所必需的规则。 | 采用统一、清晰且可验证的方式补充。 |
| 可选扩展 | 用于增强彩蛋、聚会感或后续内容规模的规则。 | 默认不启用，不影响核心流程完整性。 |

点卡属于典型的可选扩展。它只作为朋友间的场外彩蛋使用，不进入角色背包，不与元宝兑换，也不参与正式经济与商业化设计。

神鬼契约属于隐藏的游戏内特殊机制，但必须遵循公开的数据边界和统一结算规则。“上帝”不能通过私下修改概率或结果的方式制造契约效果。

---

## 9. 系统设计原则

### 9.1 统一规则

同类内容采用统一的数据结构、触发方式和结算流程，不为单个角色、装备、事件或策略牌随意增加例外逻辑。

### 9.2 配置优先

固定数值、资源内容、随机权重、事件条件和效果参数应由配置维护，程序负责读取、校验与执行。

### 9.3 模块解耦

业务模块只维护自身职责，通过明确接口访问地图、角色、数值、事件及其他系统，不跨模块直接修改内部状态。

### 9.4 整数优先

主要属性、伤害、消耗、移动距离和资源数量原则上使用整数，统一取整与边界规则，降低理解和结算成本。

### 9.5 选择优于堆叠

成长应优先增加新的路线、机制与场景选择，避免依靠无限等级、巨大数值或绝对最优装备形成单一路线。

### 9.6 长期成长保护

死亡、灾难、世界变化和随机事件可以造成代价，但不应轻易清除等级、身份、使命、已学图纸与永久能力等长期成果。

### 9.7 扩展不修改底层

新增地图、身份、种族、装备、事件、使命及策略牌时，应尽量通过新增资源和配置完成，而不是反复修改公共框架。

---

## 10. 数字化与权威规则

联机游戏由权威服务器或房主实例维护最终状态。

系统中的“上帝”是世界观与交互层面的最高规则执行者，其实际权限由程序中已经公开的规则接口提供，不代表可以绕过系统任意修改结果。

所有随机行为统一通过随机系统完成。每局游戏只生成一次主随机种子，各业务模块使用独立随机流，以支持：

* 联机同步；
* 结果复现；
* 游戏回放；
* 问题调试；
* 随机日志审计。

客户端只提交行动意图，不自行决定命中、掉落、事件、天气、使命完成或其他权威结果。

普通文本日志用于开发调试和人工复盘，不能代替游戏存档或权威领域事件。日志格式与保存边界由《14-日志系统》统一规定；随机结果的确定性与复现规则由《15-模块系统/01-随机系统》统一规定。

---

## 11. 当前设计范围

当前阶段以完成统一、可执行的概念设计为主要目标。

设计工作应优先保证：

* 一局游戏能够从创建、出生、探索持续运行至胜利；
* 玩家始终拥有清晰的当前状态与可执行行动；
* 隐藏信息、随机结果和结算顺序具有明确边界；
* 世界变化不会无故破坏玩家的获胜可能；
* 后续系统能够在不推翻基础框架的情况下逐步加入。

尚未完成详细设计的系统，不应由入口文档提前规定大量具体数值或特殊规则。相关内容应在对应系统文档中单独讨论并确认。

---

## 12. 最高设计原则

本项目的最高设计原则是：

**尊重原作的核心设定，以统一规则将其补全为真正可运行的游戏，并让复杂系统最终服务于玩家的选择、互动与乐趣。**

当还原度、系统完整性与游戏体验发生冲突时，应先确认原作真正需要保留的核心表达，再采用最少例外、最易理解且能够长期维护的方式完成适配。
