# 《开天辟地之大地的裂变》使命生成系统

## 1. 系统概述

使命生成系统负责在游戏开始时，为每位玩家生成本局游戏所需要完成的隐藏使命。

使命并非完全随机，而是结合角色自身信息、已启用的游戏模块与当前世界环境共同生成，使不同身份、不同信仰的角色拥有符合自身定位的发展方向。同时，系统保留一定随机性，保证相同角色在不同对局中也能获得不同的游戏体验。

玩家完成角色创建，且本局地图与世界状态初始化完成后，系统自动生成 `5` 个隐藏使命，分别对应不同的发展方向，共同组成玩家本局游戏的个人胜利目标。

使命生成系统主要负责：

* 建立符合当前角色与世界状态的候选使命池。
* 分别生成身份、信仰、成长、世界与自由使命。
* 检查使命之间的重复、冲突、难度与玩法覆盖情况。
* 在转职或世界变化时，为失效使命提供合法的同类型替代使命。
* 保证新增使命可以通过配置加入系统，而无需修改生成框架。

使命生成系统只负责确定使命内容，不负责直接判定玩家获胜。使命完成记录与获胜条件统一遵循《01-使命与胜利条件》。

---

## 2. 生成原则

使命生成遵循以下原则：

* **角色匹配：**身份使命与角色的开局身份相匹配，信仰使命与角色的隐藏信仰相匹配。
* **系统覆盖：**五个使命应尽量引导玩家接触不同玩法，而不是集中于同一种行为。
* **冲突排除：**使命之间不得存在无法同时满足的直接冲突。
* **难度均衡：**不同玩家获得的使命组合应具有相近的总体获胜难度。
* **保证可达：**使命只能依赖本局已经启用或必然能够开启的内容。
* **保留随机：**满足约束后，根据权重随机生成使命，避免固定答案。
* **隐藏信息：**最终使命只向对应玩家展示，不向其他玩家公开。
* **配置优先：**使命内容、条件、权重与转换关系均由资源配置维护。

使命生成的核心目标可以概括为：

**随机决定玩家这一局可以选择的道路，但不随机剥夺玩家获胜的机会。**

## 3. 使命组成

每位玩家固定获得五个不同类型的使命：

| 使命类型 | 主要来源 | 设计目的 |
| --- | --- | --- |
| 身份使命 | 开局基础身份 | 引导玩家体验身份特色与主要玩法定位。 |
| 信仰使命 | 隐藏信仰 | 体现不同信仰的价值取向与发展方向。 |
| 成长使命 | 等级、装备、属性与经济 | 鼓励玩家完成角色成长与资源规划。 |
| 世界使命 | 地图、创界山、裂变与世界事件 | 推动玩家参与探索和世界变化。 |
| 自由使命 | 通用随机使命池 | 补充其他玩法方向，增加每局游戏的变化性。 |

系统分别从五类使命池中生成一个使命，不使用五次完全无分类的随机抽取。因此，玩家不会获得多个相同类型的使命，也不会因为随机结果而完全失去某一类发展路线。

### 3.1 身份使命

身份使命根据角色的开局基础身份生成。

使命内容应体现该身份的核心玩法，例如：

* 法师围绕灵力、法术或知识展开。
* 游侠围绕探索、远程作战或环境适应展开。
* 盗贼围绕潜行、资源获取或特殊交互展开。

身份使命用于提供玩法倾向，不应强制角色只能采用唯一构筑。不同身份可以拥有部分相似目标，但完成方式与侧重点应有所区别。

### 3.2 信仰使命

信仰使命根据角色的隐藏信仰生成，并与信仰本身共同保持隐藏。

信仰使命应体现对应信仰的行为倾向、价值选择或世界立场，但不应通过过于明显且唯一的行为直接暴露玩家信仰。

同一信仰应提供多个可选使命，避免玩家通过观察一次行动便准确判断其隐藏信息。

### 3.3 成长使命

成长使命从通用成长使命池中生成，主要涉及：

* 提升角色等级。
* 分配基础属性。
* 获取或制造装备。
* 积累或消费元宝。
* 完成其他合法的角色养成行为。

成长使命不应只比较玩家最终数值高低，也不应要求无限积累资源。其目标应当明确、有限，并能够通过多种成长路线推进。

### 3.4 世界使命

世界使命根据当前地图、世界阶段与已启用模块生成，主要涉及：

* 探索指定数量或类型的区域。
* 参与世界事件。
* 进入创界山或其他重要地点。
* 处理地图裂变产生的变化。
* 完成与特殊副本、NPC 或世界状态相关的目标。

只有当创界山已经开放，或本局流程保证其必然开放时，相关使命才可以进入候选池。其他区域、事件与副本同样遵循这一原则。

### 3.5 自由使命

自由使命从通用随机使命池中生成，用于增加每局游戏的变化性。

自由使命可以涉及战斗、探索、交易、制造、事件或玩家交互，但不应与前四个使命形成重复。系统应优先选择能够补充当前使命组合玩法方向的自由使命，而不是简单抽取权重最高的内容。

例如，当其他四个使命已经集中于战斗与成长时，自由使命应优先从探索、事件或交互方向中选择。

### 3.6 使命配置

每项使命至少应包含以下配置：

| 配置项 | 说明 |
| --- | --- |
| `missionId` | 全局唯一标识，用于配置、存档与日志管理。 |
| 使命类型 | 身份、信仰、成长、世界或自由。 |
| 适用条件 | 身份、信仰、世界阶段及模块等候选条件。 |
| 完成条件 | 使命达到完成状态所需要满足的条件。 |
| 进度口径 | 用于累计进度的行为或数值；一次性使命可不配置。 |
| 难度等级 | 用于使命组合难度评估。 |
| 玩法标签 | 战斗、探索、成长、交易、事件、交互等标准标签。 |
| 冲突标签 | 用于识别互斥目标与不可共存条件。 |
| 基础权重 | 使命在合法候选池中的默认抽取权重。 |
| 转职映射 | 身份使命转职后对应的新使命，可选。 |
| 替换分组 | 世界变化导致使命失效时使用的同类型候选分组。 |

使命名称与描述用于玩家展示，不能代替结构化的完成条件、进度口径与冲突规则。

## 4. 使命生成流程

玩家完成角色创建后，系统按照统一流程生成使命：

```text
角色创建与世界初始化完成
            │
            ▼
读取身份、信仰与角色信息
            │
            ▼
读取地图、模块与世界状态
            │
            ▼
建立五类合法候选使命池
            │
            ▼
每类按权重生成一个候选使命
            │
            ▼
检查重复、冲突、难度与玩法覆盖
            │
            ▼
替换不合格候选并重新检查
            │
            ▼
锁定并私下发放五个隐藏使命
```

系统应先排除不合法使命，再进行随机抽取。不能先从完整资源库随机获得使命，再依靠无限重复抽取碰撞出合法结果。

### 4.1 候选池筛选

每类使命池首先根据当前对局状态进行筛选。

只有同时满足以下条件的使命才能进入合法候选池：

* 符合玩家的身份、信仰及其他角色条件。
* 对应地图、区域、NPC、敌人或玩法模块在本局存在。
* 当前世界阶段允许使命开始或推进。
* 不依赖已经永久错过的唯一内容。
* 不与本局规则、模式或禁用内容冲突。

无额外限制的通用使命可以直接进入对应候选池。

### 4.2 权重抽取

完成筛选后，系统根据候选使命的有效权重进行随机抽取。

```text
有效权重 = 基础权重 × 角色匹配修正 × 世界状态修正 × 玩法覆盖修正
```

各项修正只影响合法候选使命之间的相对出现机会，不能使不满足触发条件的使命进入候选池。

同一使命可以在不同对局中拥有不同权重。例如，某项探索使命在对应区域已经开放时可以提高权重，在区域尚未开放但确定会于后续阶段开启时可以保留基础权重。

### 4.3 组合检查

五个候选使命生成后，系统统一检查整个组合。

检查内容包括：

* 是否存在相同的 `missionId`。
* 是否拥有完全相同的完成条件。
* 是否依赖同一个不可共享的唯一目标。
* 是否存在互斥的冲突标签。
* 是否全部集中于同一种玩法。
* 是否存在当前对局客观无法完成的使命。
* 玩家完成任意三个使命的预计难度是否处于允许范围。

同一次行为能够推进多个使命，不等同于使命重复。只有目标、进度口径与主要玩法均高度一致时，才应判定为重复使命。

### 4.4 失败与兜底

组合检查失败时，系统优先替换导致冲突的候选使命，而不是重新生成全部五个使命。

统一兜底顺序如下：

1. 从同类型合法候选池中选择尚未尝试的使命。
2. 重新计算玩法覆盖修正，并替换冲突程度最高的使命。
3. 使用该类型预先配置的通用保底使命。
4. 若仍然无法组成五个合法使命，则阻止本局开始并记录配置错误。

生成系统必须设置明确的最大检查次数，不能使用没有终止条件的重复抽取。

保底使命仍须属于原使命类型，并满足可完成性与难度要求。不能使用空白使命、自动完成使命或其他类型使命临时填充。

### 4.5 随机结果记录

生成结果应与本局随机种子、玩家标识及使命配置版本共同记录。

同一局游戏在相同初始条件下重新加载时，应恢复已经生成的使命，而不是再次随机。客户端只接收本玩家有权查看的完整使命内容，其他玩家只能获得必要的公开状态。

## 5. 世界状态影响

除了身份与信仰外，当前世界状态也会影响使命生成。

常见影响因素包括：

* 当前世界是否已经发生裂变。
* 创界山是否开放或确定会在本局开放。
* 特殊副本是否存在。
* 当前世界阶段。
* 重要 NPC 与敌人是否仍然存在。
* 特殊区域是否可达。
* 天气与昼夜模块是否启用。

世界状态主要用于排除无效使命和调整合法使命的权重，不应无条件将玩家引向同一目标。

已经存在且可以到达的内容可以直接用于使命生成。尚未出现但由固定流程保证会出现的内容，可以作为长期使命目标。仅有较低概率出现的随机事件、唯一随机掉落或其他玩家自愿配合，不能成为使命唯一的完成条件。

例如：

* 本局未启用裂变机制时，裂变相关使命不能进入候选池。
* 创界山已永久关闭且没有重新开启方式时，进入创界山的使命不能生成。
* 某特殊 Boss 只存在一名时，应检查该目标是否允许多人独立获得完成记录。
* 某 NPC 已在开局世界状态中永久死亡时，与其交互的使命不能生成。

世界状态在使命生成后仍可能变化。使命因此客观失效时，按照本章第七节的自动转换规则处理。

## 6. 难度平衡

虽然使命内容各不相同，但不同玩家达到胜利条件的预计难度应保持基本一致。

使命难度建议统一划分为：

| 难度等级 | 设计定位 |
| --- | --- |
| 基础 | 能够在正常游戏流程中自然推进，不需要明显改变发展路线。 |
| 标准 | 需要主动规划若干行动或投入一定资源。 |
| 挑战 | 需要承担较高风险、完成长期积累或参与高难度内容。 |

难度等级用于生成约束与平衡评估，不直接向玩家公开具体计算分值。

由于玩家只需要完成五个使命中的任意三个，系统评估组合难度时，应重点比较每名玩家最容易完成的三个使命，而不是简单相加全部五个使命的难度。

生成系统应避免以下情况：

* 五个使命全部属于基础难度或挑战难度。
* 五个使命全部依赖同一种玩法。
* 三个最容易完成的使命明显低于或高于其他玩家。
* 某个使命天然无法在当前地图或世界状态中完成。
* 多个玩家被要求争夺同一个只能由一人完成的唯一目标。

每组使命原则上应至少覆盖三种不同的玩法标签，使玩家拥有多条可选发展路线。

同一使命可以生成给多名玩家，但必须保证每名玩家均可独立完成。若使命依赖全局唯一目标，则应限制分配人数、提供共享完成记录，或为后续玩家生成等价替代目标。

难度平衡只保证合理的完成机会，不保证所有使命在任何局势下花费完全相同。玩家对路线的选择、其他玩家的行动与世界事件仍然可以改变实际完成难度。

## 7. 特殊情况

### 7.1 转职

玩家完成转职后，身份使命按照完成状态分别处理。

已经完成的身份使命保持完成状态，不进行替换，也不会因转职失效。

尚未完成的身份使命根据配置的转职映射，升级为对应转职身份的新使命。该过程遵循以下规则：

* 不消耗元宝或其他资源。
* 不计入主动使命重塑次数。
* 新使命必须与转职路线和身份玩法相匹配。
* 新使命应与原使命保持相近的发展方向。
* 新使命的预计剩余难度不得明显高于原使命。
* 转换后重新检查其与其他四个使命的重复与冲突。

新旧使命使用相同进度口径时，原有进度可以直接继承。例如，二者均以“击败精英敌人数量”作为进度时，可以保留已经确认的击败次数。

进度口径不同，但能够从本局历史记录中准确重新计算时，应根据历史记录计算新进度。无法等价转换且无法重新计算时，原进度不直接复制，但系统应通过降低新使命剩余要求等方式维持合理难度。

使命转换不能凭空产生完成记录。只有当合法继承或重新计算的进度已经满足新使命条件时，新使命才可以在转职结算完成后被判定为完成。

### 7.2 世界变化

若地图、世界事件或其他不可逆变化导致某个未完成使命客观无法继续完成，系统自动生成一个同类型的新使命进行替换。

自动转换遵循以下规则：

* 不消耗任何资源。
* 不影响已经完成的使命数量。
* 只替换尚未完成且已经确认失效的使命。
* 新使命与原使命属于相同类型。
* 新使命的预计剩余难度不得明显提高。
* 新使命必须重新通过可完成性、重复与冲突检查。

短期封路、临时天气、当前资源不足或玩家暂时不愿完成，不属于客观无法完成，不触发自动转换。

### 7.3 特殊剧情

部分大型剧情、副本或世界事件可能影响尚未完成的世界使命。

例如：

* 创界山开启。
* 世界裂变爆发。
* 特殊 Boss 降临。
* 世界进入最终阶段。

系统可以根据剧情阶段升级或替换尚未完成的世界使命，使其符合当前世界状态，但不得取消已经完成的使命记录，也不得在没有补偿选择的情况下强制提高使命完成难度。

如果升级后的使命难度更高且提供额外奖励，应由玩家选择是否接受；拒绝升级时，系统仍须保留可完成的原使命或提供同难度替代使命。

### 7.4 模块变化

正常对局开始后，不应关闭当前使命必须依赖的玩法模块。

若调试、房间规则变更或其他特殊情况导致模块永久不可用，系统应重新检查所有未完成使命，并按照世界变化规则替换受影响内容。已经完成的使命记录不受影响。

## 8. 数据组织建议

使命资源建议按照使命类型与系统职责分别管理：

```text
missions/
├── identity/
├── faith/
├── growth/
├── world/
├── free/
├── evolution/
├── fallback/
└── conflict_rules/
```

各目录职责如下：

| 目录 | 主要内容 |
| --- | --- |
| `identity/` | 开局身份对应的身份使命。 |
| `faith/` | 各隐藏信仰对应的信仰使命。 |
| `growth/` | 等级、装备、属性与经济等成长使命。 |
| `world/` | 地图、裂变、创界山与世界事件使命。 |
| `free/` | 通用自由使命。 |
| `evolution/` | 转职、剧情升级与使命转换映射。 |
| `fallback/` | 各使命类型的通用保底使命。 |
| `conflict_rules/` | 重复条件、互斥标签与组合限制。 |

程序负责：

* 加载使命资源与规则配置。
* 根据角色和世界状态建立合法候选池。
* 按权重抽取五类使命。
* 检查重复、冲突、难度与可完成性。
* 保存使命内容、进度与转换记录。
* 向对应玩家私下发送使命信息。

配置加载时应完成基础校验，包括：

* `missionId` 全局唯一。
* 使命类型、难度与标签属于合法枚举。
* 完成条件与进度口径能够由现有系统判断。
* 基础权重不小于 `0`。
* 每种身份与信仰均拥有足够的合法候选使命。
* 转职映射指向有效的身份使命。
* 自动替换前后的使命类型保持一致。
* 冲突规则不存在自相矛盾或循环依赖。
* 每种受支持的角色配置均能生成完整的五个使命。

新增使命时，只需向对应使命池加入配置，并通过上述校验与组合测试，无需修改使命生成系统的核心流程。

---

## 9. 设计原则总结

使命生成系统应始终遵循以下原则：

* 五类使命结构固定，每类使命承担不同的发展引导职责。
* 随机生成必须建立在角色匹配、世界匹配与可完成性检查之后。
* 玩家拥有多条获胜路线，不被单一身份、区域或玩法完全限制。
* 难度评估围绕“完成任意三个使命”进行，而不是只比较五个使命的总量。
* 转职与世界变化可以调整未完成使命，但不能取消已经完成的记录。
* 所有转换与替换均须保持使命类型、剩余难度与组合合法性。
* 新增使命优先扩充资源配置，不为单项使命增加专属生成逻辑。

通过分类使命池、条件筛选、权重抽取与组合校验，使命生成系统能够在保证公平和可完成性的基础上，为每位玩家提供不同的发展方向，使每一局游戏都拥有新的策略路线与隐藏故事。
