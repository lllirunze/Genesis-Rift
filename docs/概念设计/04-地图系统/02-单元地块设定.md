# 《开天辟地之大地的裂变》单元地块设定

## 1. 文档目的

本文用于定义《开天辟地之大地的裂变》中地图的最小组成单位：单元地块（Hex Tile）。

单元地块只负责描述地图空间与基础环境，不承担角色、事件、任务、战斗等复杂业务逻辑。

所有玩法对象通过地块ID完成定位，而不是直接成为地块内部数据。

---

## 2. 设计原则

### 2.1 最小空间单位

单元地块是世界地图中最小且不可再拆分的空间单位。

玩家移动、距离计算、攻击范围、视野和寻路均以单元地块为基础。

首版地图由第 `0` 环至第 `10` 环的 `331` 个平顶六边形地块组成。

### 2.2 单一职责

单元地块负责：

* 保存稳定ID；
* 描述立方体坐标；
* 提供空间相邻关系；
* 保存基础地形；
* 保存独立地势；
* 保存区域归属；
* 保存基础通行状态。

单元地块不负责：

* 战斗结算；
* 角色成长；
* 技能效果；
* 任务流程；
* 事件执行；
* NPC行为；
* 世界轮次推进。

### 2.3 数据驱动

地块配置保持轻量。

地图中的玩法由外部系统读取地块信息和位置引用后执行，不由地块对象主动处理。

### 2.4 对象与空间分离

所有地图对象共享同一套地块坐标系统，并通过地块ID定位：

```text
玩家：currentTileId
NPC：currentTileId
怪物：currentTileId
事件：targetTileId / areaSelector
任务：targetTileId / targetRegionId
资源点：tileId
特殊地点：occupiedTileIds
```

不应将NPC、事件、怪物和任务对象直接嵌入地块配置。

---

## 3. 地块数据结构

每个地块至少包含以下基础信息：

| 字段 | 说明 |
| --- | --- |
| `tileId` | 地块稳定唯一ID。 |
| `x` | 立方体坐标 `x`。 |
| `y` | 立方体坐标 `y`。 |
| `z` | 立方体坐标 `z`。 |
| `ring` | 根据坐标计算的环数。 |
| `terrainType` | 基础地形类型。 |
| `elevation` | 独立地势值。 |
| `regionId` | 所属区域ID。 |
| `passability` | 基础通行状态。 |

可选的轻量引用包括：

| 字段 | 说明 |
| --- | --- |
| `locationId` | 当前地块关联的特殊地点。 |
| `roadIds` | 与当前地块关联的道路或特殊连接。 |
| `tags` | 用于筛选与配置的标准地块标签。 |

动态占用、事件实例、角色和临时状态应由对应运行时系统维护，不直接写入静态地块配置。

---

## 4. 坐标与环数

每个地块使用立方体坐标：

```text
(x, y, z)
```

并必须满足：

```text
x + y + z = 0
```

地块环数为：

```text
ring = max(|x|, |y|, |z|)
```

基础地图中的地块必须满足：

```text
ring ≤ 10
```

`ring`属于坐标派生数据。即使配置中保存该字段，系统加载时也必须重新计算并校验。

### 4.1 坐标与地势

`x`、`y`、`z`共同表示二维地图位置。

地势使用独立的`elevation`字段，不与任何坐标轴混用。

```text
位置变化：修改 x、y、z，并继续满足坐标约束
地势变化：只修改 elevation，不改变地块位置
```

---

## 5. 地块职责

### 5.1 提供空间位置

所有角色、NPC、怪物、机关和地点都通过地块ID获得空间位置。

地图对象不能使用前端像素坐标作为权威位置。

### 5.2 提供空间相邻关系

每个普通地块最多拥有六个空间相邻地块。

六方向由地图规模与坐标文档统一定义：

```text
NORTH
NORTH_EAST_60
SOUTH_EAST_60
SOUTH
SOUTH_WEST_60
NORTH_WEST_60
```

两个地块的六边形距离为 `1` 时，表示其空间相邻。

空间相邻不等于实际可通行。障碍、道路、区域、状态与角色能力仍可能阻止移动。

### 5.3 提供环向关系

第 `1` 环至第 `10` 环中的每个地块，都拥有两个同环相邻地块。

地图索引应提供：

* 顺时针下一地块；
* 逆时针下一地块；
* 空间相邻的向内地块；
* 空间相邻的向外地块。

这些关系由坐标和环数计算，不应在不同玩法模块中重复维护不一致的连接。

### 5.4 提供基础环境

每个地块拥有一种基础地形，例如：

* 平原；
* 森林；
* 山地；
* 沙漠；
* 湖泊；
* 河流。

基础地形为通行、移动成本、资源、事件和环境条件提供标签，具体规则由《05-基础地形》定义。

### 5.5 提供独立地势

每个地块拥有独立地势值`elevation`，用于描述相对于周边地块的高低差。

地势可以影响：

* 上坡移动成本；
* 悬崖与高度通行限制；
* 视野传播与遮挡；
* 部分战斗范围和地形修正。

修改`elevation`不会改变地块的立方体坐标、环数或几何距离。

### 5.6 提供区域归属

每个普通地块默认属于一个主要区域，只保存对应`regionId`。

区域名称、事件池、环境与势力规则由区域系统维护。

### 5.7 提供基础通行状态

地块拥有基础通行状态，例如：

* 可进入；
* 不可进入；
* 条件进入。

最终通行结果还需结合地块边障碍、道路、动态封锁、占用和角色能力判断。

---

## 6. 地块不负责的内容

### 6.1 玩家与地图单位

地图单位保存自己的`currentTileId`，地块不永久保存单位对象。

空间查询服务可以维护运行时索引，但索引不应成为角色状态的第二份权威来源。

### 6.2 NPC与怪物

NPC与怪物由对应系统管理，只通过位置引用接入地图。

### 6.3 事件与任务

事件和任务可以引用地块、区域或范围选择器，地块本身不执行事件和任务逻辑。

### 6.4 建筑与特殊地点

建筑属于地点系统。单地块地点可以保存`locationId`引用，多地块地点则由地点对象维护完整`occupiedTileIds`。

### 6.5 动态世界状态

天气、裂变、封锁与持续事件由运行时系统维护。地块只提供被修改的空间目标和基础数据。

---

## 7. 地块与其他系统的关系

```text
             角色与地图单位
                    │
                    ▼
事件 / 任务 ─── 六边形地块 ─── 地形 / 地势
                    │
                    ▼
              区域 / 道路
                    │
                    ▼
             战斗 / 视野 / 裂变
```

地块是各系统共享的空间引用，不是所有业务状态的聚合对象。

---

## 8. 数据校验

地图资源加载时，应至少检查：

* `tileId`全局唯一；
* `x`、`y`、`z`均为整数；
* `x + y + z = 0`；
* `ring = max(|x|, |y|, |z|)`；
* `ring`位于`0`至`10`之间；
* 不存在重复坐标；
* `terrainType`与`regionId`引用有效；
* `elevation`符合配置边界；
* 通行状态使用受支持的枚举值。

基础地图还必须验证地块总数为`331`。

---

## 9. 首版约束

`V1`版本中的每个地块：

* 只拥有一种基础地形；
* 默认只属于一个主要区域；
* 使用固定十环立方体坐标；
* 不支持同一坐标的地下、地表和空中多层地块；
* 不直接保存角色、NPC、事件和任务实例；
* 可以通过外部道路和地点系统建立特殊连接。

地下副本、空中区域、异空间和边界秘境优先作为独立场景处理，不在首版基础地图中叠加新的高度坐标。

---

## 10. 设计原则总结

单元地块设计遵循以下原则：

* 六边形最小单位。 地图行为统一以平顶六边形地块为基础。
* 坐标合法。 所有地块满足`x + y + z = 0`。
* 地势独立。 `elevation`不与立方体坐标`z`混用。
* 数据轻量。 地块只保存稳定空间与基础环境信息。
* 对象分离。 玩家、NPC、事件、任务和地点通过ID引用地块。
* 相邻统一。 六方向、环向与距离关系由地图系统统一计算。
* 通行分离。 空间相邻不代表角色必然能够进入。
* 配置可验。 地块数量、坐标、环数与引用在加载阶段完成校验。

通过轻量地块、统一立方体坐标和外部对象引用，地图系统可以在不增加地块自身职责的情况下，持续接入新的区域、事件、战斗与裂变内容。
