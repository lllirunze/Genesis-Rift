# 《开天辟地之大地的裂变》地图规模与坐标

## 1. 文档目的

本文用于规定地图的基础形状、固定规模、六边形方向以及地图单元的坐标表示方式。

地图采用平顶六边形单元格，并使用满足以下条件的三维立方体坐标：

```text
x + y + z = 0
```

该坐标结构统一用于处理：

* 六方向移动；
* 地图环数；
* 两点距离；
* 相邻单元查找；
* 视野范围；
* 路径搜索；
* 地图边界判断。

地图虽然使用三个坐标值表示，但仍然是一张二维地图。三个坐标之间并非相互独立，其中任意两个坐标都能确定第三个坐标。

本章节只定义基础空间规则，不负责地形消耗、障碍、探索、视野传播及具体移动权限。

---

## 2. 地图基础结构

### 2.1 六边形类型

地图采用平顶六边形：

* 上方和下方为平边；
* 左侧和右侧为尖角。

每个普通地图单元最多拥有六个相邻方向：

* 上：正北；
* 右上：北偏东 `60°`；
* 右下：南偏东 `60°`；
* 下：正南；
* 左下：南偏西 `60°`；
* 左上：北偏西 `60°`。

地图中不存在视觉上的正左方与正右方两个直接相邻方向。

角色若要向画面左侧或右侧移动，需要通过左上、右上、左下或右下方向实现。

### 2.2 地图中心

地图中心坐标固定为：

```text
(0, 0, 0)
```

该地图单元属于第 `0` 环，也是创界山核心区域的空间锚点。

地图中的其他单元均以中心位置为基准进行编号、环数和距离计算。

### 2.3 地图环数

地图从中心向外共设置十环：

```text
第 0 环：地图中心
第 1 环：中心周围的 6 个地图单元
第 2 环：包围第 1 环的地图单元
……
第 10 环：地图最外围
```

正常地图坐标必须满足：

```text
max(|x|, |y|, |z|) ≤ 10
```

当结果等于 `10` 时，该单元位于第十环；当结果大于 `10` 时，该位置位于基础地图范围之外。

---

## 3. 地图规模

六边形环形地图中，第 `r` 环的地图单元数量为：

```text
第 r 环单元数量 = 6 × r
```

第 `0` 环单独包含中心单元。

| 环数 | 本环单元数量 |
| --- | ---: |
| 0 | 1 |
| 1 | 6 |
| 2 | 12 |
| 3 | 18 |
| 4 | 24 |
| 5 | 30 |
| 6 | 36 |
| 7 | 42 |
| 8 | 48 |
| 9 | 54 |
| 10 | 60 |

十环地图的单元总数为：

```text
地图总单元数量
= 1 + 6 × (1 + 2 + … + 10)
= 331
```

因此，基础地图共包含：

**`331` 个正常地图单元。**

边界之外的隐藏位置、特殊副本、异空间及独立场景不计入这 `331` 个基础单元。

---

## 4. 立方体坐标

### 4.1 坐标约束

每个地图单元使用三个整数坐标表示：

```text
(x, y, z)
```

三个坐标必须始终满足：

```text
x + y + z = 0
```

例如：

```text
(2, -1, -1)
```

该坐标满足：

```text
2 + (-1) + (-1) = 0
```

因此属于合法坐标。

以下坐标不合法：

```text
(2, 1, 0)
```

因为三个坐标之和不为 `0`。

### 4.2 坐标与地势分离

立方体坐标中的 `z` 是二维六边形位置坐标，不代表地势高度。

地势必须使用独立字段：

```text
elevation
```

因此：

* `x`、`y`、`z` 共同决定地图位置、环数与六边形距离；
* `elevation` 描述地块相对高低，并影响移动、视野和部分战斗规则；
* 修改地势不会改变地图坐标；
* 地图裂变改变 `elevation` 时，不会使地块移动到其他位置。

### 4.3 坐标轴方向

本项目根据地图视觉方向，对三个坐标轴作如下规定。

立方体坐标轴不单独对应屏幕上的水平轴或垂直轴，视觉方向统一由六方向向量决定。

沿上与下方向移动时，`x` 保持不变。

沿右上与左下方向移动时，`y` 保持不变。

沿右下与左上方向移动时，`z` 保持不变。

---

## 5. 六方向坐标变化

从任意地图单元 `(x, y, z)` 向六个方向移动时，坐标变化如下：

| 视觉方向 | 正式方位 | 程序标识 | 方位角 | `x`变化 | `y`变化 | `z`变化 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| 上 | 正北 | `NORTH` | `0°` | 0 | +1 | -1 |
| 右上 | 北偏东 `60°` | `NORTH_EAST_60` | `60°` | +1 | 0 | -1 |
| 右下 | 南偏东 `60°` | `SOUTH_EAST_60` | `120°` | +1 | -1 | 0 |
| 下 | 正南 | `SOUTH` | `180°` | 0 | -1 | +1 |
| 左下 | 南偏西 `60°` | `SOUTH_WEST_60` | `240°` | -1 | 0 | +1 |
| 左上 | 北偏西 `60°` | `NORTH_WEST_60` | `300°` | -1 | +1 | 0 |

对应的六个方向向量为：

```text
NORTH        = ( 0, +1, -1)
NORTH_EAST_60 = (+1,  0, -1)
SOUTH_EAST_60 = (+1, -1,  0)
SOUTH        = ( 0, -1, +1)
SOUTH_WEST_60 = (-1,  0, +1)
NORTH_WEST_60 = (-1, +1,  0)
```

任意一次普通相邻移动只会改变两个坐标：

* 一个坐标增加 `1`；
* 一个坐标减少 `1`；
* 剩余坐标保持不变。

因此，移动后的坐标仍然满足 `x + y + z = 0`。

---

## 6. 相邻方向示例

以地图中心 `(0, 0, 0)` 为例，其六个相邻单元分别为：

```text
上：   ( 0,  1, -1)
右上： ( 1,  0, -1)
右下： ( 1, -1,  0)
下：   ( 0, -1,  1)
左下： (-1,  0,  1)
左上： (-1,  1,  0)
```

完整关系如下：

```text
                    上 (0, 1, -1)

左上 (-1, 1, 0)                      右上 (1, 0, -1)

                    中心 (0, 0, 0)

左下 (-1, 0, 1)                      右下 (1, -1, 0)

                    下 (0, -1, 1)
```

示意图只用于说明视觉方向，程序逻辑必须使用统一方向向量判断相邻关系。

---

## 7. 地图环数计算

任意地图单元所在环数为：

```text
ring = max(|x|, |y|, |z|)
```

例如：

| 坐标 | 环数 |
| --- | ---: |
| `(0, 0, 0)` | 0 |
| `(2, -1, -1)` | 2 |
| `(-4, 1, 3)` | 4 |
| `(10, -6, -4)` | 10 |

这一规则统一用于判断：

* 出生区域；
* 内环与外环；
* 地图边界；
* 边界探索资格；
* 区域危险程度；
* 环向移动关系。

`ring` 可以作为便于查询的派生字段保存，但其值必须由坐标计算并在加载时校验，不能成为独立且可能与坐标冲突的规则来源。

---

## 8. 六边形距离

两个地图单元之间的六边形距离，表示在不存在障碍、地形消耗和额外移动限制时，从一个单元移动至另一个单元至少需要经过多少步。

设两个地图单元分别为：

```text
A(x₁, y₁, z₁)
B(x₂, y₂, z₂)
```

坐标差为：

```text
Δx = x₂ - x₁
Δy = y₂ - y₁
Δz = z₂ - z₁
```

六边形距离为：

```text
Distance = max(|Δx|, |Δy|, |Δz|)
```

也可以表示为：

```text
Distance = (|Δx| + |Δy| + |Δz|) ÷ 2
```

由于坐标始终满足 `Δx + Δy + Δz = 0`，两种计算方式结果相同。项目代码应统一选择一种实现，不在不同模块中重复编写不同公式。

例如，从 `(0, 0, 0)` 到 `(3, -2, -1)`：

```text
Distance = max(3, 2, 1) = 3
```

在不考虑障碍与移动消耗时，至少需要移动 `3` 格。

六边形距离只表示几何距离，不等于实际路径成本。实际寻路仍需考虑地形、地势、障碍、方向限制和动态占用。

---

## 9. 相邻关系

两个地图单元只有在六边形距离为 `1` 时才属于空间相邻：

```text
Distance(A, B) = 1
```

每个普通单元最多拥有六个空间相邻单元。

以下情况可能使空间相邻单元无法通行：

* 目标坐标位于地图范围之外；
* 目标地块属于不可通行地形；
* 两个地块之间存在悬崖、河岸或其他边障碍；
* 道路或区域处于封锁状态；
* 角色不满足特殊通行条件；
* 目标单元受到动态占用限制。

因此，坐标相邻只表示空间关系，不代表角色一定能够进入。通行结果由障碍与移动系统统一判断。

---

## 10. 内环、外环与同环

地图中的“向内”和“向外”不是固定的视觉方向，而是由移动前后环数决定。

| 移动类型 | 判断条件 |
| --- | --- |
| 向内移动 | `目标环数 < 当前环数` |
| 向外移动 | `目标环数 > 当前环数` |
| 同环移动 | `目标环数 = 当前环数` |

因此，同一个地图单元可能拥有若干向内、向外或同环方向，具体数量取决于其在当前环中的位置。

每个非中心环上的地块都有两个同环相邻地块。地图系统应为其建立稳定的顺时针与逆时针环向关系，供默认环形移动规则使用。

顺时针和逆时针是环上地块的有序关系，不等同于某一个固定六方向向量。不同位置的“顺时针下一格”可能对应不同方向向量。

---

## 11. 第十环与地图边界

第十环是基础地图的最外围，共包含 `60` 个地图单元。

当角色所在位置满足：

```text
max(|x|, |y|, |z|) = 10
```

即表示角色位于地图边界。

从第十环继续向外移动时，理论目标坐标会满足：

```text
max(|x|, |y|, |z|) = 11
```

该目标不属于基础地图。普通移动、普通寻路、传送目标筛选和视野传播都不能将其视为正常地块。

只有满足世界边界探索规则时，玩家才能尝试朝对应方向进行边界探索。

---

## 12. 边界外位置

边界外位置不是基础地图的一部分。

在没有玩家执行边界探索前：

* 不生成普通地图单元；
* 不显示地形和地点；
* 不参与普通视野计算；
* 不允许普通寻路进入；
* 不提前公开探索结果。

系统使用第十环起始单元与向外方向共同标识一次边界探索。

例如：

```text
起始单元：(10, -5, -5)
探索方向：NORTH_EAST_60
理论坐标：(11, -5, -6)
```

该位置不作为普通地块保存，而转换为边界探索标识：

```text
edgeSource = (10, -5, -5)
edgeDirection = NORTH_EAST_60
```

这样可以避免将边界事件、秘境或彩蛋错误纳入普通寻路与视野系统。

---

## 13. 坐标与地图显示

立方体坐标用于游戏逻辑，前端需要将其转换为屏幕二维坐标。

平顶六边形显示应满足：

* 上下相邻单元的中心位于同一垂直线；
* 左上和右上单元位于当前单元斜上方；
* 左下和右下单元位于当前单元斜下方；
* 不存在正左方或正右方的直接相邻单元；
* 所有六边形的尺寸、间距和朝向一致。

屏幕像素坐标只负责显示、命中测试和动画。

游戏逻辑不得直接使用像素坐标判断：

* 环数；
* 距离；
* 相邻关系；
* 移动方向；
* 地图边界；
* 攻击和视野范围。

这些规则必须统一通过立方体坐标计算。

---

## 14. 坐标数据结构

每个地图单元至少包含以下空间数据：

| 字段 | 说明 |
| --- | --- |
| `tileId` | 地块稳定ID。 |
| `x` | 立方体坐标 `x`。 |
| `y` | 立方体坐标 `y`。 |
| `z` | 立方体坐标 `z`。 |
| `ring` | 根据立方体坐标计算的环数。 |
| `terrainType` | 基础地形。 |
| `elevation` | 独立地势值。 |
| `regionId` | 所属区域ID。 |
| `passable` | 基础通行状态。 |
| `locationId` | 可选的特殊地点引用。 |

`z` 可以直接保存，也可以通过以下公式动态计算：

```text
z = -x - y
```

为了提高资源可读性与调试效率，地图配置建议同时保存 `x`、`y`、`z`。

加载地图时必须校验：

```text
x + y + z = 0
ring = max(|x|, |y|, |z|)
ring ≤ 10
```

任一条件不满足时，应将该地图资源视为无效配置。

## 15. 方向枚举

代码中统一定义以下六个方向：

```text
NORTH
NORTH_EAST_60
SOUTH_EAST_60
SOUTH
SOUTH_WEST_60
NORTH_WEST_60
```

每个方向绑定固定坐标向量：

```text
NORTH         = ( 0, +1, -1)
NORTH_EAST_60 = (+1,  0, -1)
SOUTH_EAST_60 = (+1, -1,  0)
SOUTH         = ( 0, -1, +1)
SOUTH_WEST_60 = (-1,  0, +1)
NORTH_WEST_60 = (-1, +1,  0)
```

移动、寻路、视野、攻击范围、地图生成和边界探索必须读取同一份方向定义，避免不同系统使用不一致的坐标规则。

## 16. 基础地图生成

十环基础坐标可以按照以下流程生成：

```text
创建中心坐标 (0, 0, 0)
        │
        ▼
遍历 x = -10 至 10
        │
        ▼
遍历 y = -10 至 10
        │
        ▼
计算 z = -x - y
        │
        ▼
判断 max(|x|, |y|, |z|) ≤ 10
        │
   ┌────┴────┐
   │         │
  是         否
   │         │
创建地块    忽略坐标
```

生成完成后必须得到 `331` 个地图单元。

随后再向地块配置中填充：

* 地形；
* 地势；
* 区域；
* 水域；
* 障碍；
* 建筑；
* 特殊地点；
* NPC；
* 出生位置。

基础坐标生成与内容填充应分离，使地图版本可以复用同一套空间结构。

---

## 17. 与其他地图规则的关系

六边形坐标是地图系统的底层空间标准。

| 系统 | 统一规则 |
| --- | --- |
| 移动系统 | 每次普通空间移动只进入六方向之一的相邻地块。 |
| 环形移动 | 根据同环地块的顺时针或逆时针有序连接移动。 |
| 寻路系统 | 以六方向相邻关系建立搜索图，并叠加地形、地势、障碍和权限成本。 |
| 视野系统 | 使用六边形距离筛选范围，并沿六方向传播和处理遮挡。 |
| 区域系统 | 连续区域通过六方向相邻关系判断连通。 |
| 地图边界 | 第十环的 `60` 个地块构成基础地图外围。 |
| 出生系统 | 从环数为 `8` 至 `10` 的合法地块中筛选出生区域。 |
| 战斗系统 | 攻击距离与范围统一使用六边形距离或基于六方向的路径规则。 |

---

## 18. 设计原则

地图规模与坐标系统遵循以下原则：

1. 地图采用平顶六边形单元格。
2. 每个普通单元最多拥有六个相邻方向。
3. 地图允许直接向上与向下移动。
4. 地图不存在正左方与正右方的直接相邻移动。
5. 地图中心固定为 `(0, 0, 0)`。
6. 所有坐标必须满足 `x + y + z = 0`。
7. `z` 是立方体位置坐标，不是地势值。
8. 地势使用独立的 `elevation` 字段。
9. 地图共设置十环，第十环为基础地图边界。
10. 环数使用三个坐标绝对值的最大值计算。
11. 十环地图共包含 `331` 个正常地图单元。
12. 几何距离使用统一六边形距离公式。
13. 游戏逻辑不直接依赖屏幕像素坐标。
14. 所有涉及方向的系统共享同一套六方向向量。
15. 空间相邻与实际可通行是两个不同概念。

通过统一的平顶六边形、立方体坐标与六方向规则，地图系统可以使用同一套基础能力完成移动、距离、环层、视野、寻路与边界判断，并为后续地图内容扩展提供稳定空间基础。
