# 《开天辟地之大地的裂变》地图系统总览

## 1. 文档目的

本文用于定义《开天辟地之大地的裂变》中地图系统的总体定位、基础结构、核心职责以及与其他游戏系统之间的关系。

地图的坐标、地块、区域、地形、障碍、边界、出生、探索、视野与移动规则分别由后续文档详细说明。本章节不重复规定具体地形消耗、事件内容或战斗公式。

---

## 2. 系统定位

地图是游戏世界的空间载体，用于承载玩家移动、区域探索、任务推进、战斗发生、资源获取、特殊地点和世界裂变等玩法。

地图本身不是独立胜负系统，而是连接其他系统的公共基础设施。

玩家通过地图完成以下行为：

1. 在六边形地块之间移动。
2. 进入区域并触发对应内容。
3. 探索城镇、遗迹、副本和特殊地点。
4. 接近、远离或绕行其他地图单位。
5. 根据使命、任务和环境规划路线。
6. 应对地形、地势、障碍、昼夜、气候和裂变。
7. 逐步接近创界山及其他高价值区域。

地图系统的核心作用可以概括为：

**将角色、事件、任务、战斗和世界变化放置在一个统一且可计算的六边形空间中。**

---

## 3. 设计原则

### 3.1 尊重原作核心设定

地图系统保留以下核心内容：

* 创界山位于世界中心并承担重要世界内容；
* 玩家需要通过地图移动和探索推进游戏；
* 地图可以承载迷宫、边界、裂变及特殊区域；
* 上帝或权威系统能够通过公开规则改变部分地图状态；
* 地图同时服务身份、使命、事件、战斗和其他玩法。

补全内容应保持创界大陆的奇幻世界定位，不将现实生活地点作为世界地图主体。

### 3.2 使用平顶六边形地块

完整地图由规则排列的平顶六边形地块组成。

每个普通地块最多拥有六个空间相邻方向：

* 上：正北；
* 右上：北偏东 `60°`；
* 右下：南偏东 `60°`；
* 下：正南；
* 左下：南偏西 `60°`；
* 左上：北偏西 `60°`。

六边形结构能够统一距离、环数、范围、相邻与路径计算，并减少正方形网格中斜向距离和方向选择产生的歧义。

### 3.3 使用统一立方体坐标

每个地块使用 `(x, y, z)` 立方体坐标定位，并满足：

```text
x + y + z = 0
```

三个坐标共同表示二维六边形位置，`z` 不再表示地势。

地势使用独立字段：

```text
elevation
```

地图、移动、战斗、视野、事件和前端显示必须共享同一坐标定义，不得各自建立不同的方向或距离规则。

### 3.4 地图结构与玩法解耦

地块只描述空间和基础环境，不直接绑定所有玩法内容。

一个地块可以由以下层级共同构成：

```text
立方体坐标
+ 环数
+ 基础地形
+ 独立地势
+ 所属区域
+ 通行状态
+ 附属地点引用
+ 动态状态
```

例如，一个地块可以同时属于百妖森林、拥有森林地形、存在古代祭坛，并受到裂变污染。新增任务、事件或资源时，不需要为其创建新的基础地形类型。

### 3.5 保留中心向外扩散的环形结构

地图以中心 `(0, 0, 0)` 为第 `0` 环，向外扩展至第 `10` 环。

任意地块的环数为：

```text
ring = max(|x|, |y|, |z|)
```

第十环构成基础地图边界。每个非中心环上的地块按照稳定顺序形成完整闭环，从而支持顺时针、逆时针、向内和向外等移动概念。

### 3.6 固定基础空间，允许内容变化

首个版本采用固定十环、固定 `331` 格的基础地图。

地图坐标、中心位置和基础边界保持稳定；地形、道路、区域状态、资源、事件、地点与通行关系可以根据地图版本、随机种子和裂变效果发生变化。

普通裂变不直接增加或删除基础地图坐标。副本、秘境与边界外位置通过独立场景或特殊引用接入。

## 4. 地图总体规格

| 项目 | 规格 |
| --- | --- |
| 地图形态 | 平顶六边形环形地图 |
| 基础单位 | 六边形地块 |
| 地图环数 | 第 `0` 环至第 `10` 环 |
| 地块总数 | `331` 格 |
| 坐标体系 | 立方体坐标 `(x, y, z)` |
| 坐标约束 | `x + y + z = 0` |
| 普通相邻方向 | 最多六个 |
| 基础边界 | `max(|x|, |y|, |z|) = 10` |
| 地势字段 | `elevation` |
| 核心区域 | 创界山 |
| 地图扩展方式 | 新增配置、独立场景或新地图版本 |

`331` 格是基础地图的固定空间总量，不代表所有地块都能够被普通移动进入。

地图中可以存在：

* 普通可通行地块；
* 高消耗地块；
* 条件通行地块；
* 完全阻挡地块；
* 文明区域与特殊地点；
* 创界山区域；
* 临时封锁或裂变地块。

单片连续水域原则上不超过 `10` 格。地图可以拥有多片相互分离的水域，因此全图水域总数可以超过 `10` 格。

---

## 5. 地图层级

地图系统采用四级空间结构：

```text
世界地图
└── 区域
    └── 六边形地块
        └── 地块内容
```

### 5.1 世界地图

世界地图是完整对局使用的空间容器，由第 `0` 环至第 `10` 环的 `331` 个六边形地块组成。

世界地图负责维护地图版本、基础坐标集合、区域索引、动态状态以及全局空间查询入口。

### 5.2 区域

区域由若干地块组成，用于表达具有共同名称、文化、环境或规则的地理范围。

区域可以是连续区域，也可以在特殊规则下由多个离散地块组成。连续区域必须按照六方向相邻关系判断连通。

区域主要承载：

* 区域名称与标签；
* 区域事件池；
* 危险程度；
* 势力归属；
* 任务与使命条件；
* 区域级环境效果。

### 5.3 六边形地块

六边形地块是地图系统中最小的空间单位。

玩家移动、攻击距离、视野范围和寻路都以地块为基础。每个地块具有稳定ID、合法立方体坐标、独立地势和区域归属。

### 5.4 地块内容

地块内容是位于地块上的具体玩法对象，包括：

* 城镇与遗迹；
* 资源与宝箱；
* NPC与怪物；
* 玩家角色；
* 任务目标；
* 战斗单位；
* 临时事件；
* 裂变效果。

内容可以变化，但地块自身坐标不会因普通内容变化而改变。

## 6. 地图核心对象

| 对象 | 职责 |
| --- | --- |
| 地块 | 保存空间位置、基础地形、地势、区域与基础通行状态。 |
| 区域 | 组织地块并提供区域级规则和内容池。 |
| 地点 | 提供城镇、遗迹、神殿、副本入口等明确交互。 |
| 障碍 | 修改地块或地块边之间的通行关系。 |
| 道路 | 提供普通、单向、隐藏、传送或跨环连接。 |
| 地图单位 | 表示拥有当前位置的玩家、NPC、怪物与其他实体。 |
| 动态地图状态 | 表示天气、事件、封锁和裂变产生的临时变化。 |

地图对象只维护空间职责，战斗、任务、事件和角色成长仍由对应系统负责。

---

## 7. 环形结构与空间相邻

六方向空间相邻与环形移动权限是两个不同层级。

```text
立方体坐标
    │
    ▼
确定六方向空间相邻
    │
    ▼
计算当前与目标环数
    │
    ▼
识别顺时针、逆时针、向内或向外连接
    │
    ▼
结合角色、区域、道路和状态判断是否可用
```

默认环形移动只开放当前环的顺时针连接，并不意味着其他五个空间相邻方向不存在。

文明区域、道路、事件、技能和特殊效果可以开放逆时针、向内、向外或传送连接。实际移动权限由移动系统统一判断。

---

## 8. 距离与路径

地图几何距离统一使用六边形距离：

```text
Distance = max(|Δx|, |Δy|, |Δz|)
```

该距离用于基础范围、相邻、视野半径和启发式寻路判断。

几何距离不等于实际路径成本。实际路径需要额外考虑：

* 当前允许使用的连接；
* 地形与地势消耗；
* 障碍与道路；
* 区域权限；
* 动态占用；
* 昼夜、天气、状态和裂变。

所有系统必须调用统一坐标和距离能力，不得继续使用平方距离、曼哈顿距离或屏幕像素距离处理游戏规则。

## 9. 与其他系统的关系

| 系统 | 地图提供的能力 |
| --- | --- |
| 回合系统 | 提供移动、探索与空间交互所需的合法目标。 |
| 角色系统 | 提供位置、距离、地形适应和探索条件查询。 |
| 战斗系统 | 提供单位位置、六边形距离、范围、地形与遮挡。 |
| 使命系统 | 判断是否到达指定地块、区域、地形或地点。 |
| 事件系统 | 提供事件触发位置、场景标签和作用范围。 |
| 昼夜与气候 | 应用视野、通行、地块和区域环境变化。 |
| 装备系统 | 为移动、视野、地形适应和特殊交互提供空间条件。 |
| 裂变系统 | 修改地形、地势、道路、地点、区域与动态状态。 |
| 随机系统 | 为地图配置、资源和动态内容提供可复现随机结果。 |

地图系统只提供空间事实和标准操作，不负责定义其他系统的具体业务效果。

---

## 10. 创界山

创界山位于地图中心，是世界结构和高价值内容的核心锚点。

创界山不作为普通地形处理，而应作为独立区域管理。其主要职责包括：

* 为玩家提供长期探索方向；
* 承载世界使命和高难度内容；
* 连接裂变、隐藏副本与重要事件；
* 形成玩家路线的交汇区域；
* 作为创界大陆的叙事中心。

创界山不会在默认模式下绕过“完成任意三个使命”的获胜规则。具体区域、入口与内部规则由后续独立文档定义。

---

## 11. 地图边界

第十环的 `60` 个六边形地块共同构成基础地图边界。

普通移动、寻路、强制位移和传送不能将角色放置到 `ring > 10` 的普通坐标。

边界探索使用“第十环起始地块 + 向外方向”表示，不预先创建第十一环普通地块。该方式既保留世界边缘的探索和彩蛋价值，也避免边界内容进入普通路径与视野计算。

---

## 12. 首版范围

地图系统首版重点完成以下能力：

1. 创建第 `0` 环至第 `10` 环、共 `331` 格的平顶六边形地图。
2. 为每个地块分配合法且唯一的立方体坐标。
3. 提供统一六方向、相邻、环数和距离计算。
4. 支持区域、地形、地势和障碍。
5. 支持环向移动与特殊跨环连接。
6. 支持探索、视野与基础路径计算。
7. 支持特殊地点和创界山区域。
8. 支持地块与道路状态变化。
9. 为边界探索和地图裂变预留标准接口。
10. 支持前端六边形地图的缩放、拖动、选中和路径展示。

以下内容可以放入后续版本：

* 船只、航海和水下区域；
* 多层地下或空中地图；
* 大规模板块移动；
* 玩家建城与领土经营；
* 改变基础环数的特殊地图；
* 完全程序化生成的世界地图。

---

## 13. 设计原则总结

地图系统遵循以下原则：

* 六边形统一。 所有空间规则基于平顶六边形与六方向相邻关系。
* 坐标统一。 逻辑层使用满足 `x + y + z = 0` 的立方体坐标。
* 地势分离。 `elevation` 独立于位置坐标，不再复用 `z`。
* 环层清晰。 环数由坐标计算，第十环构成固定基础边界。
* 权限分离。 空间相邻不等于实际可通行，移动权限由统一系统判断。
* 内容解耦。 地块保持轻量，玩法对象通过位置引用接入地图。
* 动态有界。 世界内容可以变化，基础坐标结构保持稳定。
* 规则复用。 移动、战斗、视野、事件和寻路共享同一套空间能力。

通过十环六边形地图、立方体坐标和独立地势字段，地图系统能够更自然地表达环形探索、六方向移动与范围计算，并为后续内容扩展提供清晰稳定的空间基础。
