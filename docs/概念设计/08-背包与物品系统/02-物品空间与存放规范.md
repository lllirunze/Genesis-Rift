# 《开天辟地之大地的裂变》物品空间与存放规范

## 1. 文档说明

本文档用于统一规范所有可进入背包物品的空间属性、占用方式及存放规则。

所有能够进入玩家背包的物品，都必须遵循本规范，包括但不限于：

* 元宝
* 合成材料
* 消耗品
* 武器
* 护甲
* 鞋子
* 饰品
* 图纸物品
* 特殊道具
* 任务物品

本规范只负责回答以下问题：

* 一件物品占据多少背包格
* 物品能否放入指定位置
* 多个物品能否叠加
* 物品如何移动、拆分与合并
* 装备栏与背包之间如何转移装备

物品的战斗效果、交易价值、使用条件、任务用途及其他业务能力，仍然由对应系统负责。

物品空间规则的核心原则是：

**所有物品必须以完整、连续且不重叠的矩形区域存在于背包中。**

---

## 2. 物品空间属性

每件可放入背包的物品，都需要具备完整的空间属性。

| 属性 | 数据归属 | 说明 |
| --- | --- | --- |
| 宽度（Width） | 物品定义 | 物品横向固定占据的基础格数量。 |
| 高度（Height） | 物品定义 | 物品纵向固定占据的基础格数量。 |
| 最大叠加数量 | 物品定义 | 单个物品堆叠最多能够包含的数量。 |
| 当前叠加数量 | 物品实例 | 当前物品实例或堆叠实际包含的数量。 |
| 背包坐标 | 物品实例 | 物品左上角在背包网格中的位置。 |

其中，物品定义记录不会随游戏过程改变的固定规则；物品实例记录该物品当前的数量与位置。

上述属性只用于描述物品在背包中的空间表现，不直接影响物品本身的战斗、经济、任务或其他游戏效果。

所有宽度、高度、最大叠加数量和当前叠加数量均使用正整数。

物品配置必须满足：

```text
width >= 1
height >= 1
maxStack >= 1
1 <= currentStack <= maxStack
```

不允许创建宽度或高度为 `0`、负数或小数的物品，也不允许存在数量为 `0` 的物品堆叠。某个堆叠数量降低至 `0` 时，该物品实例应被移除并释放占用空间。

---

## 3. 物品尺寸

### 3.1 尺寸定义

物品尺寸统一采用以下形式表示：

```text
宽度 × 高度
```

例如：

```text
1 × 1
2 × 2
3 × 3
4 × 4
```

宽度表示物品横向占据的格数，高度表示物品纵向占据的格数。

例如，一个 `2 × 3` 物品固定占据两列、三行，共六个基础格：

```text
■■
■■
■■
```

物品总占格数量可以表示为：

```text
占格数量 = 宽度 × 高度
```

物品宽度与高度是固定配置，放入背包后不能交换，也不会因整理操作发生变化。

### 3.2 推荐尺寸

为了保持物品空间设计统一，建议优先采用以下尺寸：

| 尺寸 | 推荐物品 |
| ---: | --- |
| `1 × 1` | 元宝、普通材料、小型素材。 |
| `1 × 2` | 药剂、卷轴。 |
| `1 × 3` | 匕首、短工具。 |
| `2 × 2` | 鞋子、小型工具。 |
| `2 × 3` | 小型装备。 |
| `2 × 4` | 长武器。 |
| `3 × 3` | 护甲。 |
| `3 × 4` | 大型护甲。 |
| `4 × 4` | 未穿戴的大型装备。 |

以上内容属于推荐尺寸，不代表同一类别的所有物品都必须使用完全相同的空间配置。

新增物品时，应优先从推荐尺寸中选择。原则上避免设计大量只服务于单件物品的特殊尺寸，以降低玩家整理背包的复杂度，并保持前端表现一致。

物品尺寸不能超过当前规则允许出现的最大背包尺寸。无法放入任何等级背包的物品，不应被设计为普通可拾取物品。

### 3.3 矩形规则

初始版本中，所有物品均采用完整矩形占格。

暂不支持以下形状：

* `L` 形
* `T` 形
* 十字形
* 不规则形状
* 镂空形状
* 多个彼此分离的占用区域

采用统一矩形能够降低规则复杂度，也更便于玩家理解、前端展示、碰撞检测和服务端校验。

如果未来需要增加不规则物品，应作为独立扩展机制设计，不能通过为单件物品增加特殊判断绕过本规范。

### 3.4 初始配置示例

当前代码中提供以下典型物品配置，用于验证不同类别、尺寸与叠加规则：

| 物品 | 类别 | 品质 | 固定尺寸 | 最大叠加数量 | 设计用途 |
| --- | --- | --- | ---: | ---: | --- |
| 元宝 | 货币 | 普通 | `1 × 1` | 5 | 唯一通用货币，空间规则与普通物品一致。 |
| 亚麻布 | 材料 | 普通 | `1 × 1` | 5 | 代表可用于制造的基础材料。 |
| 治疗药水 | 消耗品 | 普通 | `1 × 2` | 3 | 代表能够恢复角色状态的消耗品。 |
| 登山绳 | 特殊道具 | 普通 | `1 × 3` | 1 | 代表在特定地形或场景中使用的工具。 |
| 重型板甲 | 装备 | 稀有 | `3 × 4` | 1 | 代表需要较大连续空间存放的未穿戴装备。 |

上述配置只定义物品进入背包所需的通用属性。治疗数值、场景使用条件、装备效果及制造配方仍由对应业务系统单独配置，不写入背包空间逻辑。

## 4. 物品放置规则

### 4.1 背包坐标

背包采用二维整数坐标。

左上角格子为坐标原点：

```text
(0, 0)
```

坐标方向统一规定为：

```text
X 轴：从左向右递增
Y 轴：从上向下递增
```

背包在代码层级上统一使用宽度为 `6`、高度为 `8` 的固定网格，因此完整坐标范围始终为：

```text
0 <= x < 6
0 <= y < 8
```

背包等级只决定左上角可用区域。对于当前可用宽度为 `W`、可用高度为 `H` 的背包，能够放置物品的基础格坐标范围为：

```text
0 <= x < W
0 <= y < H
```

背包坐标只描述物品在玩家背包界面中的位置，与地图系统的六边形坐标不存在转换关系。

### 4.2 放置方式

玩家放置物品时，只需要指定物品的左上角坐标。

系统以该坐标作为放置起点，根据物品固定宽度与固定高度向右、向下占据连续基础格。

如果一个物品的左上角坐标为 `(x, y)`，固定尺寸为 `w × h`，则其占用范围为：

```text
横向：[x, x + w)
纵向：[y, y + h)
```

也就是说，该物品会占据：

```text
x 到 x + w - 1 的所有列
y 到 y + h - 1 的所有行
```

例如，一个 `2 × 3` 物品以 `(1, 2)` 为左上角时，将占据以下六个坐标：

```text
(1, 2) (2, 2)
(1, 3) (2, 3)
(1, 4) (2, 4)
```

### 4.3 合法放置

物品能够成功放置，需要同时满足以下条件：

* 物品左上角坐标为合法整数坐标
* 放置后的完整占用范围没有超出背包边界
* 占用区域内的全部基础格均为空闲状态
* 占用区域不与其他物品发生重叠
* 当前叠加数量没有超过最大叠加数量
* 物品当前未被其他业务结算锁定

上述条件缺少任意一项，都不能完成放置。

放置操作必须一次性完成。系统不得先占用部分格子，再等待其他条件成立，也不得在放置失败后留下部分占用状态。

### 4.4 边界判断

物品完整位于背包内时，应满足：

```text
x >= 0
y >= 0
x + w <= W
y + h <= H
```

其中，`W` 与 `H` 表示当前等级已经解锁的可用区域，而不是重新创建的网格尺寸：

| 符号 | 含义 |
| --- | --- |
| `x`、`y` | 物品左上角坐标。 |
| `w`、`h` | 物品固定的宽度与高度。 |
| `W`、`H` | 当前背包等级在固定 `6 × 8` 网格中解锁的可用宽度与高度。 |

任何超出当前可用区域的放置都属于非法操作。即使物品仍位于完整 `6 × 8` 网格内，只要占用了当前等级尚未解锁的格子，也不能完成放置。

### 4.5 禁止重叠

任意两个物品不得占据同一个基础格。

若某件物品已经占据对应区域，其他物品不能覆盖其任意一个基础格。物品之间不存在上下层、遮挡或部分重叠关系。

当物品被合法移动、出售、穿戴、使用、丢弃或转移时，其原占用区域才会恢复为空闲状态。

涉及多个步骤的操作必须采用统一提交方式。例如移动物品时，应先确认目标位置合法，再同时释放原位置并占用目标位置；目标位置不合法时，物品继续保留在原位置。

### 4.6 连续空间

背包判断是否能够存放物品时，不仅需要计算剩余空格数量，还需要判断是否存在符合当前尺寸的连续矩形空闲区域。

例如，以下 `4 × 4` 区域中共有八个空闲格，但不存在连续的 `2 × 2` 空闲区域：

```text
图例：■ 已占用　□ 空闲

■□■□
□■□■
■□■□
□■□■
```

因此，即使空闲格总数大于或等于物品占格数量，也不代表物品一定能够放入背包。

对于大型物品，决定能否存放的是符合其当前尺寸的连续矩形空间，而不是空闲格总数本身。

## 5. 物品叠加

### 5.1 最大叠加数量

每件物品定义均具有最大叠加数量（`maxStack`）。

默认值为：

```text
maxStack = 1
```

最大叠加数量为 `1` 表示该物品不能与其他物品合并，必须作为独立物品实例存放。

装备、任务物品和特殊道具通常保持默认值，但具体物品仍以自身配置为准。

最大叠加数量只影响一个物品堆叠能够包含多少数量，不改变该堆叠的宽度、高度和占格数量。

### 5.2 可叠加物品

部分基础资源允许叠加。

示例如下：

| 物品 | 最大叠加数量（示例） |
| --- | ---: |
| 元宝 | `5` |
| 木材 | `5` |
| 铁矿 | `5` |
| 草药 | `10` |
| 魔法粉尘 | `10` |
| 稀有材料 | `3` |

以上数值仅作为规则示例，不代表最终平衡数值。每种物品的最大叠加数量由物品配置统一维护。

### 5.3 元宝规则

元宝属于经济系统定义的唯一通用货币。经济系统负责元宝的产出、消耗、支付、交易与具体配置，背包系统不重复定义这些经济规则。

在空间层面，元宝按照普通可叠加物品处理，不会独立于背包之外存储，也不使用任何专属放置机制。

元宝的示例空间配置如下：

```text
尺寸：1 × 1
最大叠加数量：5
```

当前版本中，元宝正式配置为 `1 × 1`，最大叠加数量为 `5`。该数值由统一物品配置维护，不由背包放置逻辑或经济算法写死。

每个元宝数量单位固定代表 `1` 个元宝。最大叠加数量为 `5` 仅表示同一个 `1 × 1` 堆叠最多容纳 `5` 个元宝，不表示元宝存在面额，也不表示整个堆叠只能作为一个货币单位参与支付。

若玩家拥有 `12` 个元宝，则背包中可以表现为：

```text
5
5
2
```

三个元宝堆叠分别占据一个 `1 × 1` 格，共占据三个基础格。

此时玩家正式背包中的可用元宝数量为：

```text
5 + 5 + 2 = 12
```

若玩家需要支付 `7` 个元宝，则系统按照稳定扣除顺序合计减少 `7` 个元宝数量单位，而不是删除 `7` 个堆叠或将某个堆叠视为单一面额。

经济系统需要查询玩家当前所有合法元宝堆叠的数量总和，不能维护与背包分离的独立元宝余额。元宝的坐标、边界、重叠、叠加、拆分与临时存放规则，均与其他相同尺寸和叠加配置的普通物品一致。

### 5.4 叠加条件

只有同时满足以下条件的物品才能进行叠加：

* 物品定义一致
* 品质一致
* 物品状态一致
* 绑定状态一致
* 其他影响叠加的配置字段一致
* 目标堆叠尚未达到最大叠加数量

“物品定义一致”表示两个物品拥有相同的物品定义标识，而不只是属于相同大类。

例如，木材与铁矿都属于合成材料，但两者不是同一种物品，不能进行叠加。

物品状态包括鉴定状态、耐久状态、有效期及其他会改变物品实际内容的运行时信息。只要任意影响叠加的状态不同，就必须作为独立物品实例存在。

品质与绑定状态只在对应物品实际拥有这些规则时参与比较。没有品质或绑定规则的物品，应使用统一默认状态，不能因字段缺失绕过叠加校验。

### 5.5 合并

合并操作将来源堆叠中的指定数量转移至目标堆叠。

合并后，目标堆叠的当前数量不能超过最大叠加数量。

如果目标堆叠只能容纳部分数量，则最多只能转移其剩余容量允许的数量，未转移部分继续保留在来源堆叠中。

当来源堆叠数量降低至 `0` 时，来源物品实例被移除，其原占用格恢复为空闲状态。

不允许因合并操作产生以下结果：

* 目标堆叠超过最大叠加数量
* 来源堆叠出现负数
* 来源与目标物品不满足叠加条件
* 未转移数量直接消失

### 5.6 拆分

玩家可以主动拆分一组可叠加物品。

例如：

```text
5 个元宝
↓
3 个元宝 + 2 个元宝
```

拆分后的每一组都会成为独立的物品实例，并分别占据自身尺寸对应的背包空间。

拆分数量必须为正整数，并且小于来源堆叠的当前数量。

拆分前必须为新堆叠指定一个合法空闲位置。若背包中不存在符合要求的空间，则拆分操作不能成立，原堆叠保持不变。

合并与拆分都只改变物品实例的数量和占用关系，不改变物品定义。

## 6. 固定尺寸规则

### 6.1 统一固定尺寸

所有物品均使用物品定义中配置的唯一宽度与高度。

物品进入背包后：

* 不能旋转
* 不能交换宽度与高度
* 不能因移动或整理改变尺寸
* 不保存当前朝向
* 不设置“是否可旋转”属性

因此，一件 `1 × 3` 物品始终占据一列、三行，不能在空间不足时改为 `3 × 1` 放置。

### 6.2 空间判断

系统检查物品能否放入背包时，只使用以下数据：

* 物品固定宽度
* 物品固定高度
* 物品左上角坐标
* 背包边界
* 当前格子占用状态

不存在尝试其他朝向或交换尺寸后重新检查的流程。

物品默认形状不适合当前空闲区域时，玩家只能调整其他物品的位置、合并或拆分堆叠、释放空间，不能改变新物品自身的宽度与高度。

### 6.3 配置要求

新增物品时，设计者必须直接确定其唯一尺寸。

物品尺寸应优先使用第 `3.2` 节中的推荐规格，并考虑固定方向对背包整理产生的影响。不能通过在运行时增加例外字段，使某件物品临时交换宽度与高度。

固定尺寸规则适用于元宝、材料、消耗品、装备、图纸、任务物品及其他所有可进入背包的内容。

## 7. 背包整理

初始版本只支持手动整理，不提供自动整理功能。

玩家可以自由进行：

* 移动物品
* 合并物品
* 拆分物品
* 调整排列顺序

玩家可以在任何时候整理自己的背包，不受当前是否为自己回合或角色行动次数影响。

整理背包：

* 不消耗行动次数
* 不消耗移动力
* 不影响回合顺序
* 不属于角色行动
* 不改变游戏结算结果

正在被交易、制造、使用、拾取或其他业务流程锁定的物品不能进行整理。玩家也不能通过整理操作撤销已经提交的物品消耗或转移。

所有整理操作都必须保持背包在操作前后处于合法状态。任何移动、合并或拆分失败时，应完整保留操作前状态。

## 8. 与装备栏的关系

已经穿戴并进入装备栏的装备，不占据背包空间。

背包与装备栏属于两个不同的物品位置。同一件装备实例不能同时存在于背包和装备栏，也不能同时占据多个装备栏。

### 8.1 穿戴装备

从背包穿戴装备时，应按照以下流程处理：

```text
校验装备穿戴条件
↓
校验目标装备栏
↓
锁定背包中的装备实例
↓
从背包移除装备并释放占用区域
↓
将同一装备实例放入装备栏
↓
重新计算装备效果
```

穿戴操作必须完整成功或完整取消。不能出现装备已经离开背包但没有进入装备栏，或同一件装备同时存在于两个位置的情况。

### 8.2 卸下装备

卸下装备时，背包必须存在符合该装备当前存放尺寸的合法连续空间。

卸下流程如下：

```text
选择需要卸下的装备
↓
指定背包目标位置
↓
校验目标区域是否合法
↓
锁定目标区域与装备实例
↓
从装备栏移除装备
↓
将同一装备实例放入背包
↓
重新计算装备效果
```

若背包空间不足或目标位置重叠，则不能完成卸下操作，装备继续保留在原装备栏中并维持原有效果。

玩家可以先整理背包，再按照装备系统规定的装备调整时机进行卸下或替换。

### 8.3 替换装备

替换装备时，被换下的装备需要重新进入背包，因此必须提前为其准备合法存放空间。

背包中即将穿戴的装备原占用区域可以在替换过程中参与空间校验，但整个替换仍必须作为一次不可分割的操作完成。任意一步失败时，原装备栏与背包状态均保持不变。

装备栏负责穿戴条件、栏位数量与装备效果；背包系统负责装备实例的空间、位置和转移合法性。两个系统不能分别创建新的装备实例完成转移。

## 9. 设计原则

物品空间设计遵循以下原则：

1. 所有物品均采用完整矩形占格。
2. 不同物品可以具有不同尺寸。
3. 物品左上角坐标与固定尺寸共同决定完整占用范围。
4. 默认最大叠加数量为 `1`。
5. 元宝与普通材料采用相同的空间存放规则。
6. 只有物品定义及相关状态一致的物品才能叠加。
7. 所有物品均不可旋转，也不设置旋转属性。
8. 物品必须位于背包边界内，并且不得互相重叠。
9. 大型物品必须拥有符合其固定尺寸的连续矩形空间才能存放。
10. 初始版本只支持玩家手动整理。
11. 背包整理不会影响游戏回合或角色行动。
12. 背包与装备栏之间的转移必须完整成功或完整取消。

本规范作为整个游戏物品空间系统的统一标准。后续新增物品均应遵循本文档规定的固定尺寸、空间属性、叠加条件与存放流程，确保所有背包相关玩法保持一致性。
